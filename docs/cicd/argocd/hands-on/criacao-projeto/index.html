Criação do Project no ArgoCD

Objetivo​

Neste etapa, você vai criar um Project no ArgoCD, que é a unidade lógica usada para organizar aplicações, controlar repositórios permitidos e definir namespaces de destino.

O Project funciona como um isolamento lógico, semelhante a um "workspace" dentro do ArgoCD.

Configuração​

1. Criando um Project via ArgoCD UI​

  1. Acesse o painel do ArgoCD -> Settings -> Projects.
  2. Clique em New Project.
  3. Defina os campos principais:
  • Project Name -> Nome do Projeto.
  • Description -> Breve descrição do ambiente.
  • Source Repositories -> Repositórios Git permitidos.
  • Destinations -> Cluster e namespace de destino.
  • Cluster Resource Allow List -> Tipos de recursos permitidos no cluster.
  • Namespace Resource Allow List -> Tipos de recursos permitidos no namespace.
  • Resource Monitoring -> Habilita o monitoramento de recursos.

2. Criando um Project via CLI​

argocd proj create dev \
  --description "Projeto do ambiente de desenvolvimento" \
  --src git@github.com:lotechdevops/infra.git \
  --dest https://kubernetes.default.svc,dev

Como o ArgoCD interpreta o Project​

Depois de criado, o Project gera um recurso Kubernetes do tipo AppProjectdentro do namespace argocd.

Você pode visualizar o YAML com:

kubectl get appproject desenvolvimento -n argocd -o yaml

Exemplo

apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  creationTimestamp: "2025-10-21T21:50:52Z"
  generation: 3
  name: desenvolvimento
  namespace: argocd
  resourceVersion: "3390761"
  uid: 758d6303-e114-43f0-b347-767049f1e7de
spec:
  description: Projeto para o time de desenvolvimento
  destinations:
  - name: in-cluster
    namespace: dev
    server: https://kubernetes.default.svc
  sourceRepos:
  - git@github.com:lotechdevops/infra.git
status: {}

Sobre as listas de recursos (Allow / Deny)​

As listas Allow e Deny controlam o tipo de recurso que pode ser aplicado por Applications associadas a este Project.

  • Cluster Resource Allow List -> Permite recursos de nível cluster (ex: CRDs, ClusterRoles).
  • Namespace Resource Allow List -> Permite recursos dentro do namespace (ex: Deployments, Services).
  • Deny List -> Bloqueia tipos específicos de recursos (ex: NetworkPolicy, ClusterRole).

Se você deixar ambas com *, o Project permitirá todos os recursos.

Criação do Projeto via YAML​

apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: dev
  namespace: argocd
spec:
  description: Projeto do ambiente de desenvolvimento
  sourceRepos:
    - https://github.com/lotechdevops/infra.git
  destinations:
    - namespace: dev
      server: https://kubernetes.default.svc
  clusterResourceWhitelist:
    - group: '*'
      kind: '*'
  namespaceResourceWhitelist:
    - group: '*'
      kind: '*'

Conclusão​

O Project é o primeiro nível de organização e segurança dentro do ArgoCD.

Ele define quem pode usar o quê e onde dentro do cluster.

No próximo passo, criaremos uma Application, que de fato implantará a aplicação do repositório dentro desse Project.
