Configurando o ArgoCD Notifications

Objetivo​

O ArgoCD Notifications é o componente responsável por enviar alertas e notificações automáticas sobre eventos que ocorrem nas Applications do ArgoCD, como sucesso, falha, sincronização, ou degradação.

O ArgoCD pode integrar com as seguintes ferramentas de comunicação:

  • Slack
  • Microsoft Teams
  • E-mail
  • Webhook
  • Opsgenie, PagerDuty, entre outros.

Neste tutorial, vamos configurar notificações para o Slack.

Pré-requisitos

  • ArgoCD instalado e funcionando
  • Application criada (ex: prometheus)
  • Acesso ao Slack com permissões de administrador

Visão Geral do ArgoCD Notifications​

O componente argocd-notifications-controller observa os objetos Application e envia alertas baseados em triggers (gatilhos) e templates (mensagens).

Fluxo simplificado

Application muda status → Trigger detecta → Template formata mensagem → Service envia para Slack

Com isso, o ArgoCD notifica automaticamente eventos como:

  • Sucesso de deploy
  • Falha de sincronização
  • Aplicação degradada
  • Aplicação fora de sync

Estrutura básica​

O Notifications funciona a partir de três blocos principais:

1. Service (Destinatário)

  • Define para onde a notificação vai (ex: Slack, e-mail, webhook)
service.slack: |
  token: $slack-token

2. Template (Conteúdo)

  • Define o conteúdo da mensagem (ex: título, texto, status da aplicação)
template.app-deployed: |
  message: |
    ✅ Application {{.app.metadata.name}} deployed successfully!

3. Trigger (Gatilho)

Define quando a notificação será enviada (ex: ao sincronizar, falhar ou degradar)

trigger.on-deployed: |
  - when: app.status.operationState.phase in ['Succeeded']
    send: [app-deployed]

Exemplo de fluxo completo

Prometheus Application → Status muda para "Succeeded" → 
Trigger "on-deployed" ativa → Template "app-deployed" formata → 
Service "slack" envia para canal do Slack

Passo 1: Criar um App no Slack​

  1. Acesse https://api.slack.com/apps
  2. Clique em Create New App -> From Scratch
  3. Dê um nome (ex: ArgoCD Notifications)
  4. Selecione o Workspace (ex: devopsr66)
  5. Clique em Create App

Passo 2: Configurar OAuth e Permissions​

  1. No menu lateral, vá em OAuth & Permissions
  2. Role até Scopes -> Bot Token Scopes
  3. Clique em Add an OAuth Scope e adicione as permissões necessárias:
  • chat:write -> Permite enviar mensagens nos canais
  • groups:read -> Permite ler informações dos canais privados
  1. Role para o topo da página e clique em Install to Workspace
  2. Na janela que abrir, clique em Allow
  3. Volte para a aba principal e copie o Bot User OAuth Token (ele começa com xoxb-)

Guarde esse token em local seguro! Você precisará dele no próximo passo.

Passo 3: Adicionar o bot ao canal Slack​

Agora você precisa adicionar o bot ao canal onde deseja receber as notificações

Método 1: Via comando no canal

No canal desejado, digite:

/invite @ArgoCD Notifitions

Método 2: Via interface

  1. Abra o canal desejado
  2. Clique no nome do canal no topo
  3. Clique em integrations -> Add apps
  4. Procure por ArgoCD Notifications e adicione

Passo 4: Obter o Channel ID​

Você precisará do ID do canal para configurar as notificações

  1. No Slack, clique no nome do canal
  2. Role até o final da janela de detalhes
  3. Copie o Channel ID (ex: C09N78FRM44)

Esse ID será usado nas annotations das aplicações

Passo 5: Criar a Secret com o Token do Slack​

Agora vamos criar a Secret no Kubernetes com o token do Slack

  1. Transforma o token em base64
echo -n <COLE-O-TOKEN-AQUI> | base64
  1. Crie o arquivo argocd-notifications-secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: argocd-notifications-secret
  namespace: argocd
type: Opaque
data:
  slack-token: <COLE-O-TOKEN-AQUI>

Substitua o valor slack-token pelo seu token em base64

Aplicar no cluster:

kubectl apply -f argocd-notifications-secret.yaml

Passo 6: Criar o ConfigMap com Templates e Triggers​

Agora vamos criar o ConfigMap que define como e quando as notificações serão enviadas

Crie o arquivo argocd-notifications-cm.yaml

apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-notifications-cm
  namespace: argocd
data:
  service.slack: |
    token: $slack-token

  # Template: Deploy bem-sucedido
  template.app-deployed: |
    message: |
      ✅ Application {{.app.metadata.name}} deployed successfully!
    slack:
      attachments: |
        [{
          "color": "#18be52",
          "title": "{{.app.metadata.name}}",
          "title_link": "{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "fields": [
            {
              "title": "Sync Status",
              "value": "{{.app.status.sync.status}}",
              "short": true
            },
            {
              "title": "Health Status",
              "value": "{{.app.status.health.status}}",
              "short": true
            },
            {
              "title": "Project",
              "value": "{{.app.spec.project}}",
              "short": true
            },
            {
              "title": "Namespace",
              "value": "{{.app.spec.destination.namespace}}",
              "short": true
            },
            {{- if .app.spec.sources }}
            {
              "title": "Helm Chart",
              "value": "{{(index .app.spec.sources 0).chart}} v{{(index .app.spec.sources 0).targetRevision}}",
              "short": false
            },
            {
              "title": "Values Repository",
              "value": "{{(index .app.spec.sources 1).repoURL}} ({{(index .app.spec.sources 1).targetRevision}})",
              "short": false
            }
            {{- end }}
          ]
        }]

  # Template: Sync iniciado (melhorado)
  template.app-sync-started: |
    message: |
      🔄 Application {{.app.metadata.name}} sync started...
    slack:
      attachments: |
        [{
          "color": "#0DADEA",
          "title": "{{.app.metadata.name}}",
          "title_link": "{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "fields": [
            {
              "title": "Status",
              "value": "Synchronization in progress",
              "short": true
            },
            {
              "title": "Project",
              "value": "{{.app.spec.project}}",
              "short": true
            },
            {
              "title": "Namespace",
              "value": "{{.app.spec.destination.namespace}}",
              "short": true
            },
            {{- if .app.spec.sources }}
            {
              "title": "Helm Chart",
              "value": "{{(index .app.spec.sources 0).chart}} v{{(index .app.spec.sources 0).targetRevision}}",
              "short": false
            }
            {{- end }}
          ]
        }]

  # Template: Sync falhou
  template.app-sync-failed: |
    message: |
      ❌ Application {{.app.metadata.name}} sync failed!
    slack:
      attachments: |
        [{
          "color": "#E96D76",
          "title": "{{.app.metadata.name}}",
          "title_link": "{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "fields": [
            {
              "title": "Sync Status",
              "value": "{{.app.status.sync.status}}",
              "short": true
            },
            {
              "title": "Operation Phase",
              "value": "{{.app.status.operationState.phase}}",
              "short": true
            },
            {
              "title": "Error Message",
              "value": "{{.app.status.operationState.message}}",
              "short": false
            }
          ]
        }]

  # Template: Health degradado
  template.app-health-degraded: |
    message: |
      ⚠️ Application {{.app.metadata.name}} health is degraded!
    slack:
      attachments: |
        [{
          "color": "#f4c030",
          "title": "{{.app.metadata.name}}",
          "title_link": "{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "fields": [
            {
              "title": "Health Status",
              "value": "{{.app.status.health.status}}",
              "short": true
            },
            {
              "title": "Sync Status",
              "value": "{{.app.status.sync.status}}",
              "short": true
            },
            {
              "title": "Message",
              "value": "{{.app.status.health.message}}",
              "short": false
            }
          ]
        }]

  # Template: Out of Sync
  template.app-out-of-sync: |
    message: |
      ⚠️ Application {{.app.metadata.name}} is out of sync!
    slack:
      attachments: |
        [{
          "color": "#f4c030",
          "title": "{{.app.metadata.name}}",
          "title_link": "{{.context.argocdUrl}}/applications/{{.app.metadata.name}}",
          "fields": [
            {
              "title": "Sync Status",
              "value": "{{.app.status.sync.status}}",
              "short": true
            },
            {
              "title": "Health Status",
              "value": "{{.app.status.health.status}}",
              "short": true
            },
            {
              "title": "Project",
              "value": "{{.app.spec.project}}",
              "short": true
            },
            {
              "title": "Namespace",
              "value": "{{.app.spec.destination.namespace}}",
              "short": true
            }
          ]
        }]

  # Trigger: Deploy bem-sucedido
  trigger.on-deployed: |
    - when: app.status.operationState.phase in ['Succeeded'] and app.status.health.status == 'Healthy'
      send: [app-deployed]

  # Trigger: Sync iniciado (MELHORADO)
  trigger.on-sync-started: |
    - when: app.status.operationState != nil and app.status.operationState.phase in ['Running', 'Progressing']
      send: [app-sync-started]

  # Trigger: Sync falhou
  trigger.on-sync-failed: |
    - when: app.status.operationState.phase in ['Error', 'Failed']
      send: [app-sync-failed]

  # Trigger: Health degradado
  trigger.on-health-degraded: |
    - when: app.status.health.status == 'Degraded'
      send: [app-health-degraded]

  # Trigger: Out of Sync
  trigger.on-out-of-sync: |
    - when: app.status.sync.status == 'OutOfSync'
      send: [app-out-of-sync]

Aplicar no cluster:

kubectl apply -f argocd-notifications-cm.yaml

Passo 7: Adicionar as annotations nas Applications​

Agora você precisa ativar as notificações em cada Application que deseja monitorar

Exemplo: Application do Prometheus

kubectl edit application prometheus -n argocd

Adicione as seguintes annotations:

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: nginx-dev
  namespace: argocd
  annotations:
    notifications.argoproj.io/subscribe.on-sync-succeeded.slack: "C09N78FRM44"
    notifications.argoproj.io/subscribe.on-sync-failed.slack: "C09N78FRM44"
    notifications.argoproj.io/subscribe.on-health-degraded.slack: "C09N78FRM44"
    notifications.argoproj.io/subscribe.on-out-of-sync.slack: "C09N78FRM44"
    notifications.argoproj.io/subscribe.on-deployed.slack: "C09N78FRM44"
spec:
  ...

Explicação das annotations:

  • notifications.argoproj.io/subscribe.<TRIGGER>.<SERVICE>: "<CHANNEL_ID>"
  • TRIGGER: Nome do trigger definido no ConfigMap
  • SERVICE: slack, e-mail, webhook, etc
  • CHANNEL_ID: ID do canal do Slack

Substitua C09N78FRM44 pelo seu Channel ID obtido no Passo 4!

Passo 8: Reiniciar o controller​

Para que as mudanças tenham efeito imediato, reinicie o notifications controller:

kubectl rollout restart deployment argocd-notifications-controller -n argocd

Ou delete o pod para forçar recriação:

kubectl delete pod -n argocd -l app.kubernetes.io/name=argocd-notifications-controller

Passo 9: Testar as notificações​

Agora vamos testar se as notificações estão funcionando!

Teste 1: Forçar sincronização

argocd app sync prometheus
  1. Sync Running -> Quando a sincronização iniciar
  2. Deployed -> Quando concluir com sucesso

Teste 2: Simular falha

Edite o values.yaml do Prometheus com uma configuração inválida e faça push. Você deve receber:

  1. Sync Failed -> Quando a sincronização falhar

Exemplo de mensagens no Slack​

Deploy bem-sucedido

Falha de sincronização

Comandos úteis​

  • Ver todas as notificações configuradas
kubectl get applications -n argocd -o json | \
  jq '.items[] | select(.metadata.annotations | 
  has("notifications.argoproj.io/subscribe.on-deployed.slack")) | 
  .metadata.name'
  • Listar todos os templates disponíveis
kubectl get configmap argocd-notifications-cm -n argocd -o yaml | \
  grep "template\." | cut -d: -f1 | sed 's/ //g'
