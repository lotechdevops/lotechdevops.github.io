Instalação do Argo CD

Fundamentos​

Como instalar o Argo CD​

MétodoComoQuando usar
Manifesto oficialkubectl apply -f install.yamlTestes rápidos
Helm chart (argo/argo-cd)helm install com values.yamlRecomendado: configuração versionada e upgrades controlados
OperatorArgo CD OperatorCenários específicos

Neste lab usamos o Helm, porque o values.yaml pode ser guardado no Git e as versões ficam sob controle.

Por que fixar a versão​

Instalar "a última" muda o resultado de um dia para o outro. Em produção, a versão do chart é fixada (--version), e o upgrade é uma decisão deliberada.

Quem acessa o quê (por enquanto)​

Neste lab o acesso é por port-forward, sem expor nada. A exposição com Traefik, TLS e Cloudflare Access fica no Lab 2.

Pré-requisitos
  • Cluster Kubernetes funcionando (kubectl get nodes com todos os nós Ready).
  • helm instalado na máquina de onde você administra o cluster.
  • StorageClass padrão não é necessária: o Argo CD não usa volumes persistentes (o Redis é só cache).

Prática​

1. Adicionar o repositório do chart​

helm repo add argo https://argoproj.github.io/argo-helm
helm repo update
"argo" has been added to your repositories
Hang tight while we grab the latest from your chart repositories...
...Successfully got an update from the "argo" chart repository
Update Complete. ⎈Happy Helming!⎈

2. Escolher e anotar a versão​

helm search repo argo/argo-cd
NAME        	CHART VERSION	APP VERSION	DESCRIPTION                                       
argo/argo-cd	10.11.6      	v3.5.6     	A Helm chart for Argo CD, a declarative, GitOps...
Use a versão que aparecer para você

Os números acima são de exemplo (versão vista no repositório do chart no momento da escrita). Use a que o seu helm search mostrar e anote a CHART VERSION: ela será reutilizada em upgrades.

Antes de instalar, leia as notas de versão do chart para ver se há mudanças que quebrem a configuração: https://github.com/argoproj/argo-helm/releases.

3. Criar o values.yaml​

mkdir -p ~/gitops/argocd && cd ~/gitops/argocd
# values.yaml
global:
  domain: argocd.devopsr66.com   # usado no Lab 2 (exposição) e no SSO

configs:
  params:
    # O TLS será terminado no Traefik, então o argocd-server fala HTTP por dentro
    server.insecure: true
Por que server.insecure: true?

O argocd-server serve HTTPS por padrão. Atrás de um Ingress que já termina o TLS (Lab 2), isso causa redirecionamentos em loop. Com insecure, o servidor fala HTTP dentro do cluster e o TLS fica no Traefik.

Esse arquivo vai para o Git depois (repositório de infraestrutura). Nenhum segredo entra nele.

4. Instalar​

helm install argocd argo/argo-cd \
  --namespace argocd --create-namespace \
  --version 10.11.6 \
  -f values.yaml
NAME: argocd
LAST DEPLOYED: Sun Nov  1 10:25:14 2026
NAMESPACE: argocd
STATUS: deployed
REVISION: 1

6. Acessar a interface (port-forward)​

kubectl port-forward svc/argocd-server -n argocd 8080:80
Forwarding from 127.0.0.1:8080 -> 8080
Forwarding from [::1]:8080 -> 8080

Abra http://localhost:8080 no navegador (mantenha o terminal aberto).

7. Obter a senha inicial do admin​

Em outro terminal:

kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d; echo
Xk3p9QzL7mR2vT8w

Usuário: admin. Senha: a saída acima (a sua será diferente).

8. Instalar a CLI argocd​

Use uma CLI da mesma versão do servidor (ver APP VERSION do passo 2):

VERSION=v3.4.5   # ajuste para o APP VERSION do seu chart
curl -sSL -o argocd \
  https://github.com/argoproj/argo-cd/releases/download/${VERSION}/argocd-linux-amd64
sudo install -m 555 argocd /usr/local/bin/argocd && rm argocd
argocd version --client

9. Login pela CLI​

A CLI fala gRPC, e o kubectl port-forward manual costuma resetar a conexão nesse caso (connection reset by peer / lost connection to pod). Por isso, deixe a própria CLI abrir o port-forward. Feche o kubectl port-forward do passo 6 antes, para não conflitar:

argocd login --port-forward --port-forward-namespace argocd \
  --username admin --plaintext
Password:
'admin:login' logged in successfully
Context 'port-forward' updated

--plaintext é necessário porque ativamos server.insecure. O contexto salvo se chama port-forward.

O contexto salvo guarda o servidor como o texto port-forward, então cada comando seguinte também precisa das flags. Para não repeti-las, defina a variável ARGOCD_OPTS, que a CLI lê automaticamente (vale para o terminal atual; coloque no ~/.bashrc se quiser permanente):

export ARGOCD_OPTS="--port-forward --port-forward-namespace argocd --plaintext"
argocd app list
NAME  CLUSTER  NAMESPACE  PROJECT  STATUS  HEALTH  SYNCPOLICY  CONDITIONS  REPO  PATH  TARGET

Lista vazia é o esperado: ainda não há Applications.

Erro lookup port-forward ... server misbehaving

Significa que a CLI está tratando port-forward como nome de servidor: falta o ARGOCD_OPTS (ou as flags) no terminal em que você rodou o comando.

10. Trocar a senha do admin e apagar a senha inicial​

argocd account update-password
*** Enter password of currently logged in user (admin):
*** Enter new password for user admin:
*** Confirm new password for user admin:
Password updated
Context 'localhost:8080' updated

Depois de trocar, o Secret com a senha inicial não serve mais para nada e deve ser apagado:

kubectl -n argocd delete secret argocd-initial-admin-secret
secret "argocd-initial-admin-secret" deleted
Guarde a nova senha

Salve a senha em um gerenciador de senhas. Se for perdida, é preciso redefinir o hash no argocd-secret. Em produção, o admin é desativado depois que o SSO estiver funcionando (veja a página de RBAC e Segurança); neste Hands-on ele continua ativo.

Resumo​

  • Instalação recomendada: Helm, com --version fixa e values.yaml versionado.
  • server.insecure: true quando o TLS é terminado no Ingress.
  • Acesso inicial por port-forward (svc/argocd-server, porta 80).
  • Senha inicial: Secret argocd-initial-admin-secret. Troque a senha e apague o Secret.
  • A CLI deve ter a mesma versão do servidor.
  • Em produção, o admin só é desativado depois que o SSO funcionar (página de RBAC e Segurança).
  • O Argo CD guarda o estado em recursos do Kubernetes, sem volume persistente.
