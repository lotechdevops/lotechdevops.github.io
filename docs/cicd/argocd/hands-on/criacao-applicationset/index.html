Criação da ApplicationSet

Objetivo​

Neste tutorial, vamos criar uma ApplicationSet no ArgoCD para automatizar o deploy de uma stack de observabilidade completa, gerenciando múltiplas aplicações relacionadas (Prometheus, Grafana, Alertmanager) de forma centralizada.

Com ApplicationSet, ao invés de criar e manter manualmente várias Applications, criamos um único manifesto que gera automaticamente todas as Applications necessárias.

Pré-requisitos

  • ArgoCD instalado e funcionando
  • Projects prometheus e grafana criados
  • Repositório Git com a estrutura configurada
  • ArgoCD notifications configurado

Revisão rápida​

Antes do ApplicationSet

Cada Application precisava ser criada manualmente:

# prometheus-application.yaml (60+ linhas)
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: prometheus
spec:
  project: prometheus
  sources:
    - repoURL: https://prometheus-community.github.io/helm-charts
      chart: kube-prometheus-stack
      # ... resto da configuração

---
# grafana-application.yaml (60+ linhas)
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: grafana
spec:
  project: grafana
  sources:
    - repoURL: https://grafana.github.io/helm-charts
      chart: grafana
      # ... resto da configuração

---
# alertmanager-application.yaml (60+ linhas)
# ... e assim por diante

Resultado: 3 arquivos, ~180 linhas, manutenção trabalhosa!

Com ApplicationSet

# applicationset-observabilidade.yaml (50 linhas)
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: observability-stack
spec:
  generators:
  - list:
      elements:
      - app: prometheus
        project: prometheus
      - app: grafana
        project: grafana
  template:
    # Template único que gera todas as Applications

Resultado: 1 arquivo, ~50 linhas, 2+ Applications geradas automaticamente!

Entendendo Generators​

O Generator define de onde vem a lista de aplicações a serem criadas.

Tipos principais de Generators

| Generator    | Quando usar                     | Exemplo de uso             |
|--------------|---------------------------------|----------------------------|
| List         | Lista estática de aplicações    | Stack de apps relacionados |
| Git          | Baseado em diretórios/arquivos  | Ambientes (dev/stage/prod) |
| Cluster      | Baseado em clusters registrados | Multi-cluster deployments  |
| Matrix       | Combinação de generators        | Ambientes × Clusters       |
| Pull Request | Apps temporárias por PR         | Preview environments       |

Neste tutorial usaremos o List Generator porque:

  • Mais simples e explícito
  • Ideal para stack de apps relacionados
  • Fácil adicionar/remover aplicações
  • Configuração específica por aplicação

Configuração​

Passo 1: Criar os Projects​

Certifique-se de que os Projects existem:

kubectl get appproject -n argocd | grep -E "prometheus|grafana"

Se não existirem, aplique os Projects que você já criou anteriormente.

Passo 2: Criar o ApplicationSet​

Crie o arquivo applicationset-observabilidade.yaml

apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: observabilidade-stack
  namespace: argocd
spec:
  # Estratégia de sincronização global
  goTemplate: true
  goTemplateOptions: ["missingkey=error"]
  
  generators:
  - list:
      elements:
      # Prometheus
      - app: prometheus
        project: prometheus
        chart: kube-prometheus-stack
        chartVersion: 79.5.0
        helmRepo: https://prometheus-community.github.io/helm-charts
        valuesPath: apps/values/prometheus/values.yaml
        namespace: observabilidade
      
      # Grafana
      - app: grafana
        project: grafana
        chart: grafana
        chartVersion: 10.1.4
        helmRepo: https://grafana.github.io/helm-charts
        valuesPath: apps/values/grafana/values.yaml
        namespace: observabilidade
  
  template:
    metadata:
      name: '{{.app}}'
      labels:
        app: '{{.app}}'
        stack: observabilidade
      annotations:
        # Notificações no Slack
        notifications.argoproj.io/subscribe.on-sync-succeeded.slack: "C0A138KGJBF"
        notifications.argoproj.io/subscribe.on-sync-failed.slack: "C0A138KGJBF"
        notifications.argoproj.io/subscribe.on-health-degraded.slack: "C0A138KGJBF"
        notifications.argoproj.io/subscribe.on-out-of-sync.slack: "C0A138KGJBF"
        notifications.argoproj.io/subscribe.on-deployed.slack: "C0A138KGJBF"
    
    spec:
      # Project específico de cada app
      project: '{{.project}}'
      
      # Múltiplos sources: Helm Chart + Values do Git
      sources:
        # Source 1: Helm Chart oficial
        - repoURL: '{{.helmRepo}}'
          chart: '{{.chart}}'
          targetRevision: '{{.chartVersion}}'
          helm:
            releaseName: '{{.app}}'
            valueFiles:
              - $values/{{.valuesPath}}
            skipCrds: false
        
        # Source 2: Values customizados no Git
        - repoURL: git@github.com:lotechdevops/apps-argocd.git
          targetRevision: main
          ref: values
      
      # Destino no cluster
      destination:
        server: https://kubernetes.default.svc
        namespace: '{{.namespace}}'
      
      # Política de sincronização
      syncPolicy:
        automated:
          enabled: true
          prune: true
          selfHeal: true
        retry:
          limit: 5
          backoff:
            duration: "5s"
            factor: 2
            maxDuration: "3m"
        syncOptions:
          - CreateNamespace=true
          - PruneLast=true
          - ServerSideApply=true

Explicação dos campos principais

Metadata do ApplicationSet

metadata:
  name: observabilidade-stack # Nome do ApplicationSet
  namespace: argocd

GoTemplate

goTemplate: true
goTemplateOptions: ["missingkey=error"]
  • Use sintaxe Go Template (mais poderosa)
  • missingkey=error: Falha se variável não existir (evita erros silenciosos)

List Generator

generators:
- list:
    elements:
    - app: prometheus          # Nome da aplicação
      project: prometheus      # Project do ArgoCD
      chart: kube-prometheus-stack  # Nome do Helm Chart
      chartVersion: 79.5.0     # Versão específica
      helmRepo: https://...    # Repositório Helm
      valuesPath: apps/values/prometheus/values.yaml
      namespace: observabilidade

Cada elemento na lista gera uma Application com essas variáveis

Template

O template define como cada Application será criada usando as variáveis do generator:

template:
  metadata:
    name: '{{.app}}'  # prometheus, grafana, etc
  spec:
    project: '{{.project}}'
    sources:
      - chart: '{{.chart}}'
        targetRevision: '{{.chartVersion}}'

Passo 4: Aplicar o ApplicationSet​

kubectl apply -f applicationset-observabilidade.yaml

Passo 5: Verificar as Applications geradas'​

Via kubectl

kubectl get applications -n argocd -l stack=observabilidade

Saída esperada:

NAME         SYNC STATUS   HEALTH STATUS
prometheus   Synced        Healthy       
grafana      Synced        Healthy

Via ArgoCD CLI

argocd app list -l stack=observabilidade

Saída esperada:

NAME               CLUSTER                         NAMESPACE        PROJECT     STATUS  HEALTH   SYNCPOLICY  CONDITIONS               REPO                                                PATH  TARGET
argocd/grafana     https://kubernetes.default.svc  observabilidade  grafana     Synced  Healthy  Auto-Prune  OrphanedResourceWarning  https://grafana.github.io/helm-charts                     10.1.4
argocd/prometheus  https://kubernetes.default.svc  observabilidade  prometheus  Synced  Healthy  Auto-Prune  OrphanedResourceWarning  https://prometheus-community.github.io/helm-charts        79.5.0

Passo 6: Ver detalhes do ApplicationSet​

# Ver o ApplicationSet
kubectl get applicationset observabilidade-stack -n argocd

# Ver detalhes
kubectl describe applicationset observabilidade-stack -n argocd

# Via CLI
argocd appset get observabilidade-stack

Generators avançados​

Git Generator (para ambientes)

Se você quiser criar o mesmo stack com múltiplos ambientes:

generators:
- matrix:
    generators:
    # Lista de aplicações
    - list:
        elements:
        - app: prometheus
          chart: kube-prometheus-stack
        - app: grafana
          chart: grafana
    
    # Lista de ambientes
    - list:
        elements:
        - env: dev
        - env: prod

template:
  metadata:
    name: '{{.app}}-{{.env}}'
  spec:
    destination:
      namespace: 'observabilidade-{{.env}}'

Resultado: Gera 4 Applications:

  • prometheus-dev
  • prometheus-prod
  • grafana-dev
  • grafana-prod

Git Directory Generator

Para estrutura baseada em diretórios:

generators:
- git:
    repoURL: git@github.com:lotechdevops/apps-argocd.git
    revision: main
    directories:
    - path: apps/applications/*

Cada diretório gera automaticamente uma Application

Comandos úteis​

Ver ApplicationSet

kubectl get applicationset -n argocd

Ver Applications geradas por label

kubectl get applications -n argocd -l stack=observabilidade

Ver detalhes do ApplicationSet

kubectl get applicationset observabilidade-stack -n argocd -o yaml

Ver status das Applications

argocd app list -l stack=observabilidade

Forçar refresh do ApplicationSet

# Método 1: Via annotation
kubectl annotate applicationset observability-stack -n argocd \
  argocd.argoproj.io/refresh=normal

# Método 2: Deletar e recriar (força re-scan completo)
kubectl delete applicationset observability-stack -n argocd
kubectl apply -f observability-stack-applicationset.yaml
