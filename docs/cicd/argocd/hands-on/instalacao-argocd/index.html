Instalação do ArgoCD

Este laboratório mostra como instalar o ArgoCD em um cluster Kubernetes.

Pré-requisitos​

Antes de começar, certifique-se de ter:

  • Cluster Kubernetes funcional
    • Minikube, Kind, K3s, EKS, GKE, AKS, etc.
  • kubectl configurado e com acesso ao cluster
  • Ao menos 2 CPU e 4GB RAM disponíveis no cluster

Validar acesso ao cluster:

kubectl cluster-info
kubectl get nodes

Tipos de Instalação​

O ArgoCD oferece dois tipos de instalação:

TipoArquivoUso
Non-HAinstall.yamlDesenvolvimento, teste, laboratório
HA (High Availability)ha/install.yamlProdução, múltiplas réplicas

Neste guia, usaremos a instalação Non-HA para laboratório. Para produção, veja a seção de HA no final.

1. Criar namespace do ArgoCD​

O ArgoCD deve rodar em seu próprio namespace:

kubectl create ns argocd

Validar:

kubectl get ns argocd

2. Instalar o ArgoCD​

Aplicar os manifestos de instalação:

kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

O que foi instalado:

Esta instalação inclui todos os componentes principais:

  • argocd-server → API e interface web
  • argocd-repo-server → Clona e interpreta manifests do Git
  • argocd-application-controller → Aplica e reconcilia estados
  • argocd-applicationset-controller → Gerencia ApplicationSets
  • argocd-dex-server → Autenticação (SSO)
  • argocd-notifications-controller → Notificações e alertas
  • argocd-redis → Cache de estado

3. Verificar se os pods foram criados​

Aguarde todos os pods ficarem no estado Running:

kubectl get pods -n argocd

Você deve ver algo como:

Se algum pod não subir:

# Ver detalhes do pod problemático
kubectl describe pod <nome-do-pod> -n argocd

# Ver logs
kubectl logs <nome-do-pod> -n argocd

4. Verificar os Services criados​

kubectl get svc -n argocd

Você deve ver algo como:

O argocd-server é o que usaremos para acessar a UI.

5. Acessar a interface web​

Por padrão, o ArgoCD expõe o argocd-server como um Service do tipo ClusterIP (não acessível externamente).

Opção 1: Port-forwarding​

Para acessar localmente, faça um port-forwarding:

kubectl port-forward svc/argocd-server -n argocd 8080:443

Agora a UI estará acessível em:

http://localhost:8080

6. Obter a senha inicial​

O usuário padrão do ArgoCD é admin.

A senha inicial é armazenada em um Secret Kubernetes criado durante a instalação.

Para exibir a senha:

kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d && echo

7. Instalar a CLI do ArgoCD​

A CLI facilita o gerenciamento via terminal.

Linux​

# Baixar a versão estável
curl -sSL -o argocd https://github.com/argoproj/argo-cd/releases/latest/download/argocd-linux-amd64

# Dar permissão de execução
chmod +x argocd

# Mover para o PATH
sudo mv argocd /usr/local/bin/

Validar a instalação:

argocd version

8. Fazer login via CLI​

argocd login localhost:8080 --username admin --password <SENHA_INICIAL> --insecure

Use --insecure se estiver usando HTTPS sem certificado válido (ambiente local).

Saída esperada:

9. Verificar a comunicação via CLI​

argocd app list

Mesmo sem Applications criadas, o comando deve funcionar:

Isso confirma que a CLI está conectada ao servidor.

10. Expor ArgoCD externamente (Opcional)​

Opção 2: LoadBalancer (Cloud)​

kubectl patch svc argocd-server -n argocd -p '{"spec": {"type": "LoadBalancer"}}'

Obtenha o IP externo:

kubectl get svc argocd-server -n argocd

Opção 3: Ingress​

Pré-requisitos: Ingress Controller instalado (nginx, traefik, etc)

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: argocd-server-ingress
  namespace: argocd
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/backend-protocol: "HTTPS"
spec:
  ingressClassName: nginx
  rules:
  - host: argocd.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: argocd-server
            port:
              number: 443
  tls:
  - hosts:
    - argocd.example.com
    secretName: argocd-server-tls  # Criar com cert-manager

Aplicar:

kubectl apply -f argocd-ingress.yaml

11. Instalação em HA (High Availability)​

Para ambientes de produção, use a instalação HA:

kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/ha/install.yaml

Diferenças da instalação HA:

  • ✅ argocd-server: 3+ réplicas
  • ✅ argocd-repo-server: 2+ réplicas
  • ✅ argocd-applicationset-controller: 2+ réplicas
  • ✅ argocd-dex-server: 3+ réplicas
  • ✅ redis-ha: Redis em modo HA com Sentinel (3+ réplicas)

Recursos mínimos recomendados para HA:

# argocd-server
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi

# argocd-repo-server
resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    cpu: 1000m
    memory: 1Gi

# argocd-application-controller
resources:
  requests:
    cpu: 250m
    memory: 1Gi
  limits:
    cpu: 2000m
    memory: 4Gi

Troubleshooting Comum​

Pods não sobem (Peding)​

Problema: Falta de recurso no cluster

Solução:

kubectl describe pod <pod-name> -n argocd
# Procure por "Insufficient cpu" ou "Insufficient memory"

# Verificar recursos disponíveis
kubectl top nodes

Erro "CrashLoopBackOff"​

Problema: Pod reiniciando contantemente

Solução:

# Ver logs do pod
kubectl logs <pod-name> -n argocd --previous

# Ver eventos
kubectl get events -n argocd --sort-by='.lastTimestamp'

Não consigo acessar a UI​

Problema: Port-forward ou Ingress não funcionando

Solução:

# Verificar se o service está rodando
kubectl get svc argocd-server -n argocd

# Testar conexão dentro do cluster
kubectl run -it --rm debug --image=nicolaka/netshoot --restart=Never -- curl -k https://argocd-server.argocd.svc.cluster.local

Secret password inicial não existe​

Problema: Secret foi deletado ou não foi criado

Solução:

Resetar senha do admin

kubectl -n argocd create secret argocd-secret -p '{"stringData": {"admin.password": "'$(htpasswd -nbBC 10 "" YOUR_NEW_PASSWORD | tr -d ':\n' | sed 's/$2y/$2a/')'"}}'

Validação Final​

Checklist de validação:

# Todos os pods Running
kubectl get pods -n argocd

# Todos os services criados
kubectl get svc -n argocd

# UI acessível
# Abra https://localhost:8080

# CLI funcionando
argocd version
argocd app list

# Login funciona
# User: admin, Password: <senha-obtida>
