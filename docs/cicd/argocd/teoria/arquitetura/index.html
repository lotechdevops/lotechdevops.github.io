Arquitetura do ArgoCD

Visão Geral​

O ArgoCD é composto por uma arquitetura modular, onde cada componente executa uma função específica.
Todos os componentes rodam como pods dentro do Kubernetes, garantindo escalabilidade, observabilidade e fácil atualização.

O objetivo dessa arquitetura é manter o estado do cluster sincronizado com o estado desejado armazenado no Git, de forma contínua, segura e auditável.

Componentes Principais​

ArgoCD API Server​

  • É o cérebro central do ArgoCD.
  • Exponibiliza uma API REST, a interface web (UI) e o acesso da CLI (argocd).
  • Cuida da autenticação, autorização e do gerenciamento das Applications.
  • Todos os comandos executados pelo usuário passam pelo API Server.

Ele é o ponto de entrada para o ArgoCD, conectando usuários, automações e a UI.

Application Controller​

  • É o motor de reconciliação do ArgoCD.
  • Monitora o estado declarado no Git e o compara com o estado real do cluster Kubernetes.
  • Quando identifica diferenças (drift), o controlador executa a sincronização (Sync).
  • Aplica políticas de auto-sync, self-heal e rollback automático.

É o componente que efetivamente faz o GitOps acontecer.

ArgoCD ApplicationSet Controller​

  • É o componente responsável pelo recurso ApplicationSet, que permite gerar Applications dinamicamente com base em templates e fontes de dados.
  • Ideal para ambientes multi-cluster, multi-ambiente ou com muitos microserviços.
  • Suporta diferentes "geradores" (generators), como:
    • List Generator (lista estática de parâmetros).
    • Cluster Generator (gera apps para cada cluster registrado).
    • Git Generator (lê pastas ou arquivos no repositório).
    • Matrix/Combination Generator (combina múltiplas fontes).

O ApplicationSet Controller traz automação e escalabilidade, eliminando a necesidade de criar centenas de Applications manualmente.

ArgoCD Notifications Controller​

  • É o subsistema de alertas e notificações do ArgoCD
  • Envia mensagens automáticas quando ocorrem eventos como:
    • Sincronizações bem-sucedidas ou com falha.
    • Mudanças no status da aplicação (ex: degradada, saudável, fora de sync).
    • Ações manuais executadas por usuários.
  • Suporta integração com diversos canais:
    • Slack
    • Microsoft Teams
    • Email
    • Webhook genérico
    • Opsgenie, PagerDuty, Grafana OnCall, entre outros.

Esse componente é essencial em ambientes corporativos e SRE, onde o time precisa ser notificado imediatamente sobre qualquer problema de sincronização.

Dex (ou outro provedor de autenticação)​

  • Cuida da autenticação (login) no ArgoCD.
  • Suporta SSO (Single Sign-On) e integração com:
    • LDAP / Active Directory
    • OAuth2 / OIDC
    • SAML
  • Facilita o uso de credenciais corporativas sem precisar criar usuários locais.

Redis​

  • Atua como cache em memória para o ArgoCD.
  • Armazena dados temporários para melhorar o desempenho nas consultas e sincronização.
  • Não guarda dados permanentes (tudo é reconstruído em caso de reinício).

CLI (argocd)​

  • Ferramenta de linha de comando para interagir com o ArgoCD via API Server.
  • Permite criar, listar e sincronizar Applications diretamente do terminal.
  • Útil em pipelines CI/CD, scripts de automação e tarefas administrativas.

Fluxo de Funcionamento​

  1. O usuário (via UI ou CLI) cria uma Application apontando para um repósitorio Git.
  2. 0 Repository Server clona o repositório e interpreta os manifests.
  3. O Application Controller compara o estado do Git com o cluster e aplica o que for necessário.
  4. O API Server expõe o status via UI/CLI/API.
  5. O Notifications Controller envia alertas se ocorrer algum evento (ex: falha de sincronização).
  6. O ApplicationSet Controller cria ou atualiza Applications automaticamente, conforme as regras definidas.
  7. O Dex gerencia quem pode acessar a UI e a API, de acordo com as políticas de autenticação corporativas.

Resiliência e Escalabilidade​

  • O ArgoCD pode rodar em modo HA (High Availability).
  • Os componentes principais (API Server, Application Controller e Repo Server) podem ter réplicas para suportar alta demanda.
  • O ApplicationSet Controller e o Notifications Contoller também podem ser escalados separadamente.
  • É comum integrar o ArgoCD como:
    • Vault / SOPS para gerenciamento de segredos.
    • Prometheus e Alertmanager para monitoramente.
    • Grafana para dashboards de saúde e status das aplicações.

Conclusão​

A arquitetura do ArgoCD é formada por componentes independentes, mas altamente integrados:

  • O API Server centraliza o acesso.
  • O Application Controller garante a reconciliação.
  • O Repository Server interpreta os manifests.
  • O ApplicationSet Controller automatiza a criação de Applications.
  • O Notifications Controller alerta sobre eventos importantes.
  • O Dex autentica os usuários.
  • O Redis acelera as operações.

Essa modularidade permite que o ArgoCD seja usado desde ambientes pequenos on-premises até plataformas corporativas complexas com múltiplos clusters e centenas de aplicações.
