Controle de Recursos no Kubernetes com ResourceQuota

Obejtivo​

Neste laboratório, você vai aprender a utilizar o objeto ResourceQuota no Kubernetes para limitar o consumo de recursos dentro de um namespace. Você irá:

  • Criar um namespace isolado.
  • Aplicar uma ResourceQuota que limita o número de pods, CPU, memória e armazenamento.
  • Testar na prática como o Kubernetes impede a criação de workloads que excedem os limites definidos.
  • Compreender como as cotas interagem com requests, limits e PersistentVolumeClaims.

Etapas de Configurações - Exemplo com CPU e Memória​

Etapa 1 - Criar um namespace​

  • Crie um namespace específico onde será aplicada a ResourceQuota, conforme o comando abaixo
kubectl create namespace lab-resource-quota

Etapa 2 - Criar um ResourceQuota​

  • Crie um objeto ResourceQuota com requests e limits, conforme exemplo abaixo:
apiVersion: v1
kind: ResourceQuota
metadata:
  name: lab-resource-quota
  namespace: lab-resource-quota
spec:
  hard:
    pods: "6"
    requests.cpu: "1"
    requests.memory: "512Mi"
    limits.cpu: "2"
    limits.memory: "2Gi"

Entendendo o ResourceQuota criado

  • pods: "6" -> Permite no máximo 6 pods dentro do namespace.

  • requests.cpu: "1" -> Limita o uso total de CPU para o namespace.

  • requests.memory: "512Mi" -> Limita o uso total de memória para o namespace.

  • limits.cpu: "2" -> Limita o uso máximo de CPU dentro do namespace.

  • limits.memory: "2Gi" -> Limita o uso máximo de memória dentro do namespace.

  • Aplique o arquivo do ResourceQuota conforme o comando abaixo:

kubectl apply -f resourcequota.yaml
  • Verifique os detalhes do ResourceQuota conforme o comando abaixo:
kubectl describe resourcequota lab-resource-quota -n lab-resource-quota

Retorno esperado:

Name:            lab-resource-quota
Namespace:       lab-resource-quota
Resource         Used  Hard
--------         ----  ----
limits.cpu       0     2
limits.memory    0     2Gi
pods             0     6
requests.cpu     0     1
requests.memory  0     512Mi

Como pode ser visto acima, ainda não estamos utilizando nenhum recurso no namespace.

Etapa 3 - Criar um Deployment no namespace​

  • Agora vamos criar um Deployment com 6 réplicas, onde cada pod solicita recursos computacionais que, no total, irão ultrapassar os limites definidos no ResourceQuota.
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
      app: myapp
  name: myapp
  namespace: lab-resource-quota
spec:
  replicas: 6
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - image: nginx
        name: nginx
        resources:
          limits:
            cpu: "0.5"
            memory: "512Mi"
          requests:
            cpu: "0.2"
            memory: "64Mi"

Valores declarados no manifesto:

  • limits.cpu: "0.5" (500m) por pod.
  • limits.memory: "512Mi" (512Mi) por pod.
  • requests.cpu: "0.2" (200m) por pod.
  • requests.memory: "64Mi" (64Mi) por pod.

Entendendo os limits e requests após subir a aplicação:

Name:            lab-resource-quota
Namespace:       lab-resource-quota
Resource         Used   Hard
--------         ----   ----
limits.cpu       2      2
limits.memory    2Gi    2Gi
pods             4      6
requests.cpu     800m   1
requests.memory  256Mi  512Mi

Ao verificar os pods em execução foi notado que subiu apenas 4 réplicas. Vamos entender o que aconteceu:

Cálculo total dos recursos:

  • requests.cpu total: 6 x 0.2 (200) = 1200m (1,2 cores)
  • requests.memory total: 6 x 64Mi (64Mi) = 384Mi
  • limits.cpu total: 6 x 0.5 (500) = 3000m (3 cores)
  • limits.memory total: 6 x 512Mi (512Mi) = 3072Mi (3GB)

Comparação com o ResourceQuota:

  • requests.cpu: (1.2 cores) -> Excede o limite definido de 1 core.
  • requests.memory total: (384Mi) -> Está dentro do limite definido de 512Mi.
  • limits.cpu total: (3 cores) -> Excede o limite definido de 2 cores.
  • limits.memory total: (3072Mi) -> Excede o limite definido de 2GB.

O Kubernetes impede que novos pods assim que qualquer umas das restrições do ResourceQuota é violado. No nosso caso, a violação de requests.cpu, limits.cpu e limits.memory impediu que os 6 Pods fossem criados, limitando o número de réplicas a 4.

kubectl get pods -n lab-resource-quota
NAME                     READY   STATUS    RESTARTS   AGE
myapp-65d9cb665b-4dpgg   1/1     Running   0          6m29s
myapp-65d9cb665b-fzcn9   1/1     Running   0          6m29s
myapp-65d9cb665b-r5fx4   1/1     Running   0          6m30s
myapp-65d9cb665b-z884l   1/1     Running   0          6m29s

Etapas de Configurações - Exemplo com Storage​

Etapa 1 - Criar um ResourceQuota​

Nesta etapa, vamos criar uma nova ResourceQuota que define limites para:

  • Armazenamento total solicitado requests.storage.
  • Quantidade de PVCs permitidos persistentVolumeClaims.

Manifesto do ResourceQuota para volumes:

apiVersion: v1
kind: ResourceQuota
metadata:
  name: storage-quota
  namespace: lab-resource-quota
spec:
  hard:
    requests.storage: "10Gi"
    persistentvolumeclaims: "1"

Valores declarados no manifesto:

  • requests.storage: "10Gi" -> Limita a soma de armazenamento a 10 GB

  • persistentvolumeclaims: "1" -> Limita no máximo 3 PVC no namespace.

  • Aplique no cluster:

kubectl apply -f resourcequota-storage.yaml

Etapa 2 - Criar um PVC​

  • Vamos criar um PVC que solicita 10 GB de armazenamento.

  • Crie o arquivo pvc-quota.yaml

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-quota
  namespace: lab-resource-quota
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: "10Gi"
  storageClassName: nfs-storage
  • Aplique com:
kubectl apply -f pvc-quota.yaml

Verifique o consumo de recursos:

kubectl describe resourcequota storage-quota -n lab-resource-quota

Saída esperada:

Name:                   storage-quota
Namespace:              lab-resource-quota
Resource                Used  Hard
--------                ----  ----
persistentvolumeclaims  1     1
requests.storage        10Gi  10Gi

Etapa 3 - Criar outro PVC para violar a ResourceQuota​

  • Crie um segundo PVC com 2 GB, apenas para testar a violação da cota.

  • Crie o arquivo pvc-quota-2.yaml

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-quota-2
  namespace: lab-resource-quota
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: "2Gi"
  storageClassName: nfs-storage
  • Aplique com:
kubectl apply -f pvc-quota-2.yaml

Resultado esperado:

Error from server (Forbidden): error when creating "pvc-2.yaml": persistentvolumeclaims "pvc-quota-2" is forbidden: exceeded quota: storage-quota, requested: persistentvolumeclaims=1,requests.storage=2Gi, used: persistentvolumeclaims=1,requests.storage=10Gi, limited: persistentvolumeclaims=1,requests.storage=10Gi

Explicação:

  • O primeiro PVC já consumiu todo o limite de 10GB permitido.
  • Ao tentar criar outro, o Kubernetes bloqueia a operação, mantendo os recursos dentro da cota definida.
