Controle de Recursos no Kubernetes com LimitRange

Objetivo​

Demonstrar, na prática, como usar o recurso LimitRange para definir restrições de CPU e memória dentro de um namespace, assegurando que todos os Pods sigam limites controlados mesmo quando não especificados.

Pré-requisitos​

  1. Um cluster Kubernetes funcional.
  2. kubectl configurado.
  3. Conhecimento básico sobre Pods e recursos de CPU/Memória.

Etapas de Configurações​

Etapa 1 - Criar o namespace para o Lab​

  • Crie um namespace específico onde será aplicada a LimitRange, conforme o comando abaixo
kubectl create namespace lab-limitrange

Etapa 2 - Criar o LimitRange​

  • Crie um arquivo chamado limitrange.yaml com o conteúdo abaixo:
apiVersion: v1
kind: LimitRange
metadata:
  name: default-cpu-mem-limit
  namespace: lab-limitrange
spec:
  limits:
  - default:
      cpu: 500m
      memory: 256Mi
    defaultRequest:
      cpu: 250m
      memory: 128Mi
    min:
      cpu: 100m
      memory: 64Mi
    max:
      cpu: 1
      memory: 512Mi
    type: Container

O que esse manifesto faz:

  • Aplica limites mínimos e máximos para containers.

  • Define valores padrões (default) e defaultRequest para casos em que o usuário não definir os recursos explicitamente.

  • Aplique o recurso:

kubectl apply -f limitrange.yaml
  • Verifique se foi criado:
kubectl get limitrange -n lab-limitrange

Etapa 3 - Criar um Pod sem resquests/limits definidos​

  • Crie um pod de teste chamado `pod-sem-limites.yaml:
apiVersion: v1
kind: Pod
metadata:
  name: test-lr-pod
  namespace: lab-limitrange
spec:
  containers:
  - name: test
    image: busybox
    command: ["sh", "-c", "sleep 3600"]
  • Aplique com:
kubectl apply -f pod-sem-limites.yaml
  • Agora, veja quais recursos foram aplicados automaticamente:
kubectl get pod test-lr-pod -n lab-limitrange -o jsonpath="{.spec.containers[*].resources}"

Resultado esperado:

{"limits":{"cpu":"500m","memory":"256Mi"},"requests":{"cpu":"250m","memory":"128Mi"}}

Isso demonstra que o limitrange aplicou os valores padrão mesmo que o manifesto não tenho especificado nada.

Etapa 4 - Testar limites mínimos e máximos​

  • Crie um pod que tente violar os limites:

1. Abaixo do mínimo:

apiVersion: v1
kind: Pod
metadata:
  name: pod-abaixo-min
  namespace: lab-limitrange
spec:
  containers:
  - name: test
    image: busybox
    command: ["sh", "-c", "sleep 3600"]
    resources:
      requests:
        cpu: 50m
        memory: 32Mi
  • Aplique com:
kubectl apply -f pod-abaixo-min.yaml

Resultado:

Error from server (Forbidden): error when creating "pod-abaixo-min.yaml": pods "pod-abaixo-min" is forbidden: [minimum cpu usage per Container is 100m, but request is 50m, minimum memory usage per Container is 64Mi, but request is 32Mi]

2. Acima do máximo:

apiVersion: v1
kind: Pod
metadata:
  name: pod-acima-max
  namespace: lab-limitrange
spec:
  containers:
  - name: test
    image: busybox
    command: ["sh", "-c", "sleep 3600"]
    resources:
      limits:
        cpu: "2"
        memory: "1Gi"
  • Aplique com:
kubectl apply -f pod-acima-max.yaml

Resultado:

Error from server (Forbidden): error when creating "pod-acima-max.yaml": pods "pod-acima-max" is forbidden: [maximum cpu usage per Container is 1, but limit is 2, maximum memory usage per Container is 512Mi, but limit is 1Gi]

Conclusão​

Com o recurso LimitRange aplicado:

  • Todos os Pods recebem valores padrão de CPU e memória, mesmo que não seja especificados.
  • Pods com valores fora do intervalo (mínimo e máximo) são rejeitados.
  • O LimitRange ajuda a manter a previsibilidade e o controle do uso de recursos dentro do namespace.
