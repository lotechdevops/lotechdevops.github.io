HPA na Prática: Implementação com Nginx

Pré-requisitos​

  • Cluster Kubernetes rodando
  • kubectl configurado
  • Metrics Server instalado

1. Instalar Metrics Server​

O Metrics Server é essencial para o HPA funcionar, pois fornece as métricas de CPU e memória dos pods.

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

Verificar instalação​

Verificar se o Metrics Server está rodando

kubectl get deployment metrics-server -n kube-system

**Aguardar 1-2 minutos e testar

kubectl top nodes
kubectl top pods -A

Configuração para ambientes de desenvolvimento​

Se estiver usando um cluster local (minikube, kind, k3s), pode ser necessário adicionar a flag --kubelet-insecure-tls

kubectl edit deployment metrics-server -n kube-system

Adicionar aos args container: - --kubelet-insecure-tls

2. Criar o Deployment​

Vamos usar uma imagem nginx simples com recursos definidos

deployment.yaml:

apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: nginx-hpa
  name: nginx-hpa
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx-hpa
  template:
    metadata:
      labels:
        app: nginx-hpa
    spec:
      containers:
      - image: nginx
        name: nginx-hpa
        resources:
          limits:
            cpu: "500m"          # 500 millicores
            memory: 500Mi
          requests:
            cpu: "200m"          # 200 millicores (base para cálculo do HPA)
            memory: 250Mi

Campos importantes

CPU:

  • requests.cpu: "500m" - Base para o cálculo de utilização do HPA (500m = 50% de 1 CPU)
  • limits.cpu: "200m" - Limite máximo que o container pode usar Memória:
  • requests.memory: 500Mi - Quantidade mínima de memória garantida. Base para o cálculo de utilização do HPA
  • limits.memory: 250Mi - Limite máximo de memória. Se ultrapssar, o pod será terminado (OOMKilled)

Réplicas:

  • replicas: 1 - Valor inicial (O HPA vai ajustar automaticamente para minReplicas ou mais)

O HPA calcula a utilização como porcentagem do request

  • CPU a 50m = 50% de utilização (50m / 100m request)
  • Memória a 8Mi = 50% de utilização (8Mi / 16Mi request)

Aplique o deployment no cluster:

kubectl apply -f deployment.yaml
kubectl get pods -l app=nginx-hpa

3. Criar o Service​

service.yaml:

apiVersion: v1
kind: Service
metadata:
  name: nginx
spec:
  selector:
    app: nginx-hpa
  ports:
  - port: 80
    targetPort: 80

Aplique o service no cluster:

kubectl apply -f service.yaml
kubectl get svc nginx

4. Configurar o HPA​

hpa.yaml:

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: nginx-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx-hpa
  minReplicas: 3              # Mínimo de 3 pods sempre
  maxReplicas: 5              # Máximo de 5 pods
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 50    # Escala quando CPU média > 50%
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 50    # Escala quando memória média > 50%
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60    # Aguarda 60s antes de confirmar
      policies:
      - type: Percent
        value: 100                      # Dobra o número de pods
        periodSeconds: 10               # A cada 10 segundos
    scaleDown:
      stabilizationWindowSeconds: 60    # Aguarda 60s antes de remover
      policies:
      - type: Percent
        value: 100                      # Remove até 100% dos pods
        periodSeconds: 10               # A cada 10 segundos

Explicação das Métricas​

type: Resource

  • Métricas de CPU/memória do pod inteiro
  • averageUtilization: 50= quando a média dos pods atingir 50% do request

Explicação do Behavior​

scaleUp:

  • stabilizationWindowSeconds: 60 = Aguarda 1 minuto confirmando que realmente precisa escalar
  • value: 100 com type: Percent = Pode dobrar o número de pods (aumentar 100%)

scaleDown:

  • stabilizationWindowSeconds: 60 = Aguarda 1 minuto antes de remover pods
  • Evita flapping (oscilação constante)

Aplique o hpa no cluster:

kubectl apply -f hpa.yaml

5. Verificar o HPA​

Ver status do HPA

kubectl get hpa

Saída esperada:

# NAME        REFERENCE              TARGETS                      MINPODS   MAXPODS   REPLICAS
# nginx-hpa   Deployment/nginx-hpa   <unknown>/50%, <unknown>/50%   3         5         1

Aguarde alguns segundos para as métricas aparecerem:

# NAME        REFERENCE              TARGETS         MINPODS   MAXPODS   REPLICAS
# nginx-hpa   Deployment/nginx-hpa   0%/50%, 0%/50%  3         5         3

Ver detalhes

kubectl describe hpa nginx-hpa

6. Testar o HPA​

Observar o escalonamento inicial​

Como configuramos minReplicas: 3 , o HPA vai automaticamente criar 3 pods:

watch -n 2 'kubectl get hpa && echo "" && kubectl get pods -l app=nginx-hpa'

Gerar carga para testar scale up​

Com request.cpu: 200m e target de 50%, o HPA vai escalar quando a média de CPU passar de 100m (50% de 200m).

Método 1: Carga leve (testar escalonamento gradual)

Criar 3 pods gerando carga moderado

for i in {1..3}; do
  kubectl run load-test-$i --image=busybox --restart=Never -- /bin/sh -c "while true; do wget -q -O- http://nginx > /dev/null; sleep 0.05; done" &
done

Observe o comportamento:

Em outro terminal:

watch -n 2 'kubectl get hpa && echo "" && kubectl get pods -l app=nginx-hpa'

watch -n 2 'kubectl top pods -l app=nginx-hpa'

Você verá:

  • CPU dos pods começa a subir: ~6m -> ~15m -> ~20m

Método 2: Carga Pesada (forçar scale up rápido)

Criar 10 pods gerando carga agressiva

for i in {1..10}; do
  kubectl run heavy-load-$i --image=busybox --restart=Never -- /bin/sh -c "while true; do wget -q -O- http://nginx > /dev/null; done" &
done

Observe o comportamento:

Em outro terminal:

Você verá:

  • CPU dos pod sobe rapidamente: ~30m -> ~50m -> ~70m -> ~100m
  • Média ultrapassa 100m rapidamente
  • Após 60s, HPA escala de 3 -> 4

Parar o teste de carga​

Deletar todos os pods de teste

kubectl delete pod -l run --force --grace-period=0

Observe o comportamento:

  • CPU dos pods cai
  • HPA aguarda 60s
  • Após confirmar que a carga está baixa, começa a remover pods
  • Processo pode levar ~1 minutos devido ao stabilizationWindow

Troubleshooting​

CPU não sobe mesmo com carga​

Verificar se os pods estão recebendo requisições

kubectl logs -l app=nginx-hpa --tail=20

HPA não escala mesmo com CPU alta​

Verificar se passou do threshold

kubectl top pods -l app=ngix-hpa

Verificar eventos do HPA

kubectl describe hpa nginx-hpa

Sucesso! Seu HPA está configurado e testado!
