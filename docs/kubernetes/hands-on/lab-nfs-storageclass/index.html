NFS + StorageClass no Kubernetes

Objetivo​

Neste laboratório prático, vamos criar um servidor NFS em uma VM e configurá-lo como um backend de armazenamento para o Kubernetes. Usaremos o NFS para provisionar volumes persistentes via StorageClass, testando com PersistentVolumes (PV), PersistentVolumeClaims (PVC) e um Pod que monta o volume.

Pré-requisitos​

  1. Ambiente com VMs Linux (ex: VirtualBox)
  2. Uma VM Linux (ex: Ubuntu Server) para o Servidor NFS
  3. Cluster Kubernetes funcional (kubeadm ou minikube com 1 master + 1 ou mais workers)
  4. Conectividade entre as VMs (rede NAT ou bridge)
  5. kubectl configurado e com acesso ao cluster
  6. Plugin CSI do NFS (nfs-subdir-external-provisioner)

Etapa 1 - Criar o servidor NFS​

Na sua VM NFS (ex: nfs-server), execute os comandos:

sudo apt update
sudo apt install -y nfs-kernel-server
sudo mkdir -p /mnt/nfs/data
sudo chown nobody:nogroup /mnt/nfs/data

Exportar o diretório:

echo "/mnt/nfs/data *(rw,sync,no_subtree_check,no_root_squash)" | sudo tee -a /etc/exports
sudo exportfs -rav
sudo systemctl restart nfs-kernel-server

Verificar se está funcionando:

sudo exportsfs -v

Você deve ver algo como:

/mnt/nfs/data   <world>(rw,sync,wdelay,no_root_squash,no_subtree_check)

Teste o acesso pela VM worker (ou master):

sudo apt install -y nfs-common
showmount -e <IP_DO_SERVIDOR_NFS>

Etapa 2 - Instalar o Provisionador NFS no Cluster​

No seu cluster Kubernetes:

Adicionar o Helm repo:

helm repo add nfs-subdir-external-provisioner https://kubernetes-sigs.github.io/nfs-subdir-external-provisioner/
helm repo update

Criar um namespace dedicado:

kubectl create ns storage-nfs

**Instalar o provisionador (exemplo no namespace: storage-nfs)

helm install provisioner-nfs nfs-subdir-external-provisioner/nfs-subdir-external-provisioner \
  --namespace storage-nfs \
  --set nfs.server=192.168.123.27 \
  --set nfs.path=/mnt/nfs/data \
  --set storageClass.name=storage-nfs \
  --set storageClass.defaultClass=true

Explicação dos parâmetros:

nfs.server: IP do seu servidor NFS (no meu caso: 192.168.123.27)

nfs.path: Caminho exportado pelo NFS (no meu caso: /mnt/nfs/data)

storageClass.name: Nome da StorageClass que será criado (no meu caso: storage-nfs)

storageClass.defaultClass: Define este StorageClass como padrão (no meu caso: true)

Confirmar que o StorageClass foi criado:

kubectl get storageClass -n storage-nfs

Etapa 3 - Criar o PVC com o StorageClass NFS​

Crie o PVC com o StorageClass NFS como o exemplo abaixo:

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: meu-pvc
  namespace: storage-nfs
spec:
  accessModes:
    - ReadWriteMany
  storageClassName: storage-nfs
  resources:
    requests:
      storage: 1Gi

Aplique no cluster Kubernetes, com o comando:

kubectl apply -f pvc.yaml
kubectl get pvc -n storage-nfs

Etapa 4 - Criar um Pod que usa o PVC​

Crie um Pod como o exemplo abaixo:

apiVersion: v1
kind: Pod
metadata:
  name: pod-com-nfs
  namespace: storage-nfs
spec:
  containers:
  - name: app
    image: busybox
    command: [ "sleep", "3600" ]
    volumeMounts:
    - name: volume-nfs
      mountPath: /mnt/nfs
  volumes:
  - name: volume-nfs
    persistentVolumeClaim:
      claimName: meu-pvc

Aplique no cluster Kubernetes, com o comando:

kubectl apply -f pod.yaml
kubectl get pods -n storage-nfs

Etapa 5 - Teste​

  • Após aplicar o manifesto do Pod que consome o PVC provisionado via NFS, acesse o container e valida se o volume está sendo montado corretamente.

Comando utilizado:

kubectl exec -it pod-com-nfs -n storage-nfs -- sh

Esse comando abre um terminal interativo (sh) dentro do container em execução. É útil para validar o funcionamento da aplicação ou, neste caso, o volume montado.

  • Acesse o diretório do volume NFS montado:
cd /mnt/nfs

Este é o caminho onde o volume NFS foi montado, conforme configurado no campo volumeMounts do Pod.

  • Crie um arquivo de teste:
echo "Testando volume NFS" > teste.txt

Esse comando cria um arquivo chamado teste.txt com o conteúdo "Testando volume NFS" dentro do volume compartilhado. Como o volume está sendo via NFS, ele será persistido no servidor NFS e poderá ser acessado por outros Pods.

  • Verifique se o arquivo foi criado
ls /mnt/nfs/teste.txt

  • Verifique se o arquivo foi criado no servidor NFS
