Instalação e Configuração do Traefik como Ingress Controller no Kubernetes

Objetivo desta seção​

Nesta etapa, você vai entender o que é um Ingress Controller, por que escolhemos o Traefik e instalá-lo com Helm, exposto por um IP do MetalLB.

O que é um Ingress Controller​

O recurso Ingress é apenas uma declaração de regras de roteamento (host, path, Service de destino). Quem de fato recebe o tráfego e aplica essas regras é o Ingress Controller, que roda como Pod no cluster e atua como proxy reverso.

Neste laboratório, o fluxo é:

  1. O Traefik roda no cluster e é exposto por um Service LoadBalancer (IP fornecido pelo MetalLB).
  2. Você cria objetos Ingress com ingressClassName: traefik.
  3. O Traefik observa esses objetos e roteia as requisições para os Services corretos.

Por que Traefik e não Ingress-NGINX? O Ingress-NGINX foi aposentado em março de 2026 e não recebe mais correções de segurança. O Traefik é mantido ativamente, é um Ingress Controller de uso geral e funciona com o mesmo recurso Ingress do Kubernetes. Existem outras alternativas na lista de controllers da documentação do Kubernetes.

Instalação do Traefik​

1. Adicionar o repositório do Helm​

helm repo add traefik https://traefik.github.io/charts
helm repo update

2. Instalar o Traefik​

helm install traefik traefik/traefik \
  --namespace traefik \
  --create-namespace \
  --set service.type=LoadBalancer

Explicações

  • --create-namespace -> cria o namespace traefik.
  • service.type=LoadBalancer -> faz o Service do Traefik pedir um IP externo, que o MetalLB atribui. (Esse já é o padrão do chart; deixamos explícito para ficar claro o papel do MetalLB.)
  • O chart cria automaticamente os entrypoints web (porta 80) e websecure (porta 443) e o IngressClass chamado traefik.

Para ver todas as opções de configuração do chart: helm show values traefik/traefik.

3. Verificar a instalação​

kubectl get pods -n traefik
kubectl get ingressclass

O Pod do Traefik deve estar Running e deve existir um IngressClass chamado traefik.

4. Verificar o IP atribuído​

kubectl get svc -n traefik

Você verá algo como:

NAME      TYPE           CLUSTER-IP       EXTERNAL-IP    PORT(S)                      AGE
traefik   LoadBalancer   10.108.214.119   10.10.20.200   80:32505/TCP,443:31540/TCP   102s

O EXTERNAL-IP é o primeiro IP livre do pool do MetalLB (10.10.20.200-10.10.20.220, criado na etapa anterior). Se o seu pool for outro, você verá um IP da sua faixa.

Importante: o IP 10.10.20.200 é o ponto de entrada de todas as aplicações na rede do laboratório (10.10.20.0/24). Ele será usado nos testes locais e, depois, pelo Cloudflare Tunnel.

5. Testar a conectividade​

Ainda não existe nenhum Ingress, então o Traefik não conhece nenhuma rota. Mesmo assim, ele deve responder à requisição com um 404, e isso já prova que o caminho de rede está funcionando (anúncio do MetalLB, rede e Traefik):

curl -i http://10.10.20.200

Saída esperada (trecho):

HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Sat, 31 Oct 2026 19:02:05 GMT
Content-Length: 19

404 page not found

Um 404 aqui é sucesso: quem respondeu foi o Traefik, dizendo que não há rota para aquele host. Se o comando ficar sem resposta ou der No route to host, o problema está na rede ou no MetalLB, não no Traefik (veja os problemas comuns abaixo).

Acessando de outra máquina

O IP 10.10.20.200 está na rede roteada do laboratório. Outras máquinas da sua rede local só o alcançam se tiverem rota para a 10.10.20.0/24 passando pelo host que hospeda as VMs.

Acessando o dashboard (opcional)​

O Traefik tem um dashboard útil para depurar rotas. Por padrão ele não é exposto externamente; use port-forward:

1. Habilitar a rota do dashboard​

helm upgrade traefik traefik/traefik \
  --namespace traefik \
  --reuse-values \
  --set ingressRoute.dashboard.enabled=true
  • --reuse-values -> mantém as configurações da instalação (como service.type=LoadBalancer). Sem ele, o upgrade volta aos valores padrão do chart.

2. Acessar com port-forward​

kubectl -n traefik port-forward deploy/traefik 8080:8080

Acesse http://localhost:8080/dashboard/ (a barra final é obrigatória). Quando você criar Ingresses na próxima etapa, eles aparecerão em HTTP → Routers.

Problemas comuns​

SintomaCausa provável
EXTERNAL-IP em <pending>O MetalLB não está configurado ou o pool acabou (volte à etapa 3).
EXTERNAL-IP atribuído, mas o curl não respondeO IP do pool está em uma rede que a sua máquina não alcança, ou o L2Advertisement anuncia pela interface errada (confira o campo interfaces na etapa 3).
Dashboard em localhost:8080/dashboard/ retorna 404A rota do dashboard não está habilitada. Rode o helm upgrade com ingressRoute.dashboard.enabled=true e confira com kubectl get ingressroute -n traefik.
Pod do Traefik em CrashLoopBackOffVeja kubectl logs -n traefik deploy/traefik.
Ingress criado, mas resposta 404 page not foundO Ingress não tem ingressClassName: traefik, ou o host/path não bate com a requisição.
