Protegendo Aplicações com Cloudflare Access (Zero Trust)

Visão Geral​

Agora que sua aplicação já está exposta através do Cloudflare Tunnel, vamos adicionar uma camada essencial de segurança: o Cloudflare Access.

O Access permite que você controle quem pode acessar sua aplicação, usando autenticação por e-mail, PIN, Google Workspace, GitHub e muito outros modos, seguindo o modelo de Zero Trust.

O que é o Cloudflare Access​

O Cloudflare Access é uma solução de segurança baseada em identidade que permite controlar o acesso a aplicações privadas ou públicas sem depender de VPNs ou redes corporativas.

Com ele, é possível:

  • Exigir login com e-mail.
  • Solicitar código PIN temporário por e-mail.
  • Integrar com Google, GitHub, Okta, Azure AD, etc.
  • Aplicar MFA (Autenticação Multifator).
  • Auditar e registrar acessos de usuários.

O que será feito​

  1. Criar um Application no Cloudflare Zero Trust
  2. Configurar a URL protegida (por exemplo: https://prometheus.devopsr66.com)
  3. Criar uma Politica de acesso baseada em e-mail + PIN
  4. Testar o acesso seguro à aplicação.

Configuração do Cloudflare Access​

1. Criar uma Application​

  1. Acesse o painel Cloudflare Zero Trust
  2. No men lateral, vá em Access -> Applications
  3. Clique em Add an application e selecione Self-hosted
  4. Preencha os seguintes campos:
    • Application Name -> Nome descritivo da aplicação (ex: prometheus)
    • Session Duration -> Tempo que o usuário permanecerá autenticado (ex: 24h)
  5. Em seguinda, clique em Add public hostname e configure:
    • Input Method -> Matenha a opção padrão.
    • Subdomain -> O subdomínio para acesso (ex: prometheus)
    • Domain -> Seu domínio principal (ex: devopsr66)
  6. Clique em Next para prosseguir com a criação da aplicação.

2. Criar uma Access Policy (Política de Acesso)​

  1. Ainda no menu *Access, vá para Policies
  2. Clique em Add a policy
  3. Preencha os campos:
    • Policy Name -> Nome descritivo (ex: E-mail com PIN)
    • Action:
      • Allow -> Para permitir o acesso.
      • Deny -> Para bloquear o acesso.
      • Bypass -> Para ignorar a autenticação (ex: IP local)
  4. Session Duration -> Tempo que o usuário permanecerá autenticado.
  5. Rules -> Adicione os métodos de autenticação desejados. Por exemplo:
    • Emails -> user@example.com
    • One-Time PIN
  6. Clique em Save para salvar a política.
  7. Volte em Application, clique na aba Policies e associe a Política criada.

3. Testar o Acesso​

  1. Acesse a URL da aplicação (ex: https://prometheus.devopsr66.com)
  2. Você verá a tela de autenticação da Cloudflare Access.
  3. Digite o e-mail autorizado
  4. Insira o código PIN enviado para o e-mail
  5. A aplicação será carregada de forma segura.

Neste tutorial, mostramos o básico para proteger uma aplicação com autenticação por e-mail e PIN, mas o Cloudflare Access oferece uma ampla gama de recursos avançados que você pode explorar:

  • Integração com provedores de identidade como:
    • Google Workspace
    • GitHub
    • Okta
    • Azure AD
  • Autenticação com múltiplos fatores (MFA)
  • Controle por localização (geolocalização de IP)
  • Permissão baseada em grupo de usuários
  • Bypass por IP local ou rede privada
  • Tempo de expiração personalizado para sessão e políticas
  • Políticas condicionais com lógica avançada (AND, OR, NOT)

Esses recursos tornam o Cloudflare Access uma solução robusta de Zero Trust Access
