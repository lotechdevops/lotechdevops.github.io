Ingress com TLS para Aplicações no Kubernetes

Objetivo​

Nesta seção, você vai expor uma aplicação do cluster por meio de um Ingress com TLS, usando um domínio real e um certificado do Let's Encrypt emitido pelo cert-manager.

Para mais detalhes sobre o Let's Encrypt e o cert-manager, veja Let's Encrypt e Cert-manager.

Importante: o acesso será feito diretamente pelo IP do MetalLB, sem o Cloudflare Tunnel ainda. Assim você valida o Ingress e o TLS antes de colocar a camada de proteção extra (próximas etapas).

Pré-requisitos​

  • MetalLB e Traefik instalados (etapas 3 e 4), com o Traefik com EXTERNAL-IP.
  • cert-manager funcionando, com um ClusterIssuer pronto (kubectl get clusterissuer).

1. Criar uma aplicação de exemplo​

Usaremos o whoami, uma aplicação leve que devolve informações da requisição (útil para ver headers). Crie o namespace, o Deployment e o Service:

app-whoami.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: whoami
  namespace: demo
spec:
  replicas: 2
  selector:
    matchLabels:
      app: whoami
  template:
    metadata:
      labels:
        app: whoami
    spec:
      containers:
      - name: whoami
        image: traefik/whoami:v1.10.2
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: whoami
  namespace: demo
spec:
  selector:
    app: whoami
  ports:
  - port: 80
    targetPort: 80
kubectl apply -f app-whoami.yaml
kubectl get pods,svc -n demo

Saída esperada:

NAME                          READY   STATUS    RESTARTS   AGE
pod/whoami-55454855c8-45m4j   1/1     Running   0          7s
pod/whoami-55454855c8-shwjp   1/1     Running   0          7s

NAME             TYPE        CLUSTER-IP     EXTERNAL-IP   PORT(S)   AGE
service/whoami   ClusterIP   10.111.119.4   <none>        80/TCP    7s
  • Os 2 Pods Running correspondem às 2 réplicas do Deployment.
  • O Service é ClusterIP: só é acessível dentro do cluster. Quem vai expô-lo para fora é o Ingress.

2. Emitir o certificado TLS​

Em vez de copiar Secrets entre namespaces, peça ao cert-manager que emita o certificado diretamente no namespace da aplicação. A Secret TLS precisa estar no mesmo namespace do Ingress.

certificado.yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: whoami-cert
  namespace: demo
spec:
  secretName: whoami-tls
  issuerRef:
    name: letsencrypt-prod           # ajuste para o nome do seu ClusterIssuer
    kind: ClusterIssuer
  dnsNames:
    - whoami.devopsr66.com           # ajuste para o seu domínio
Confira o nome do ClusterIssuer

Use kubectl get clusterissuer e copie o nome exato na coluna NAME. Para este teste, use o de produção: com o letsencrypt-staging, o curl do passo 4 reclamaria do certificado, pois a CA de staging não é confiável.

kubectl apply -f certificado.yaml
kubectl get certificate -n demo -w

O -w (watch) mantém o comando rodando; encerre com Ctrl+C quando ver READY igual a True.

Saída esperada:

NAME          READY   SECRET       AGE
whoami-cert   False   whoami-tls   81s
whoami-cert   True    whoami-tls   81s
  • READY False no início é normal: o cert-manager está criando o registro TXT no Cloudflare e aguardando a propagação do desafio DNS-01.
  • Neste laboratório, a emissão levou cerca de 3 minutos. Pode variar.

Ao final, a Secret whoami-tls existirá no namespace demo:

kubectl get secret whoami-tls -n demo

Saída esperada:

NAME         TYPE                DATA   AGE
whoami-tls   kubernetes.io/tls   2      39s

Os 2 itens de DATA são a chave privada (tls.key) e o certificado (tls.crt).

3. Criar o Ingress com TLS​

ingress-whoami.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: whoami
  namespace: demo
  annotations:
    traefik.ingress.kubernetes.io/router.entrypoints: websecure
spec:
  ingressClassName: traefik
  tls:
    - hosts:
        - whoami.devopsr66.com
      secretName: whoami-tls
  rules:
    - host: whoami.devopsr66.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: whoami
                port:
                  number: 80

Explicação dos campos

  • metadata.namespace -> o Ingress, o Service e a Secret TLS devem estar no mesmo namespace.
  • annotations -> router.entrypoints: websecure faz o Traefik atender esta rota somente em HTTPS (porta 443). Annotations com prefixo traefik.ingress.kubernetes.io/ são específicas do Traefik.
  • ingressClassName: traefik -> define qual controller gerencia este Ingress.
  • tls -> ativa HTTPS para os hosts listados, usando o certificado da Secret whoami-tls.
  • rules.host -> domínio que roteia para a aplicação.
  • paths.pathType: Prefix -> / e qualquer subcaminho (/api, /health...) vão para o Service.
  • backend.service -> nome e porta do Service (não do Pod).
kubectl apply -f ingress-whoami.yaml
kubectl get ingress -n demo

Saída esperada:

NAME     CLASS     HOSTS                  ADDRESS        PORTS     AGE
whoami   traefik   whoami.devopsr66.com   10.10.20.200   80, 443   19s
  • CLASS traefik confirma que o Ingress foi entregue ao Traefik.
  • PORTS 80, 443 aparece porque há uma seção tls. A rota em si responde só em HTTPS, por causa da annotation websecure.
  • A coluna ADDRESS pode ficar vazia com o chart do Traefik. Isso não é erro: o IP de entrada é o EXTERNAL-IP do Service (kubectl get svc -n traefik).

4. Testar a aplicação​

Como o DNS público ainda não aponta para o cluster, use o /etc/hosts da sua máquina para resolver o domínio para o IP do MetalLB:

echo "10.10.20.200 whoami.devopsr66.com" | sudo tee -a /etc/hosts
Rota para a rede do laboratório

O IP 10.10.20.200 está na rede 10.10.20.0/24. A máquina que executa o curl precisa ter rota para essa rede passando pelo host das VMs.

Teste pela linha de comando:

curl -v https://whoami.devopsr66.com

Saída esperada (trechos):

* subjectAltName: host "whoami.devopsr66.com" matched cert's "whoami.devopsr66.com"
* SSL certificate verify ok.
...
< HTTP/2 200
...
Hostname: whoami-7d9c5b8f4c-4xk2p
  • SSL certificate verify ok prova que o certificado do Let's Encrypt é válido, sem precisar de -k.
  • Hostname é o nome do Pod que respondeu. Repita o curl algumas vezes e o nome alterna entre os 2 Pods.

Também pode abrir https://whoami.devopsr66.com no navegador e conferir o cadeado.

Remova a linha do /etc/hosts depois dos testes, para não conflitar com o DNS real quando o tunnel estiver configurado.

Redirecionamento de HTTP para HTTPS (opcional)​

Com a annotation router.entrypoints: websecure, requisições HTTP (porta 80) para este host retornam 404. Para redirecionar automaticamente de HTTP para HTTPS, configure o redirecionamento no entrypoint web do Traefik. A sintaxe depende da versão do chart/Traefik; consulte a documentação de entrypoints do Traefik para a versão instalada.

Problemas comuns​

SintomaCausa provável
Certificate não fica READYVeja kubectl describe certificate,certificaterequest,order,challenge -n demo. Geralmente é problema no solver DNS-01 ou no ClusterIssuer.
404 page not foundingressClassName incorreto, host diferente do usado na requisição, ou acesso por HTTP com a rota restrita a websecure.
Navegador mostra certificado "TRAEFIK DEFAULT CERT"A Secret TLS não existe no namespace do Ingress ou o nome em secretName está errado.
502 Bad GatewayO Service não tem endpoints (labels do selector não batem) ou a porta está errada. Veja kubectl get endpoints whoami -n demo.
