Ingresses com TLS para as Aplicações

Objetivo​

Neste seção, você vai aprender a expor aplicações que estão rodando dentro do seu cluster Kubernetes por meio de um recurso chamado Ingress.

O foco aqui será a criação de um Ingress com suporte a TLS, utilizando um domínio real e um certificado gerado pelo Let's Encrypt com auxílio do Cert-manager.

Para mais detalhes sobre o Let's Encrypt e Cert-manager confira o artigo Let's Encrypt e Cert-manager

Importante: O acesso será feito diretamente pelo IP do cluster via MetalLB, sem ainda utilizar o Cloudflare Tunnel. O objetivo é mostrar o caminho tradicional de exposição com TLS antes de avançar para soluções com camada de proteção extra (que serão tratadas nos próximos passos).

Pré-Requisitos​

Antes de prosseguir, certifique-se de que os seguintes requisitos estão atendidos:

  • O Ingress Controller (como o NGINX) já está instalado e operando no cluster.
  • O cert-manager está configurado e funcionando corretamente.
  • Um certificado válido foi gerado e está disponível via uma Secret TLS no mesmo namespace da aplicação.

Criando um ingress​

Vamos agora demonstrar como criar um Ingress para a nossa aplicação Prometheus com TLS habilitado.

No nosso exemplo iremos usar um certificado TLS criado anteriormente no cluster. Como secrets são recursos "namespaced", precisamos copiá-la para o namespace onde estará rodando nossa aplicação, no nosso caso iremos rodar a aplicação no namespace Observabilidade

1. Copiar o certificado TLS do namespace default para o namespace observabilidade

kubectl get secret devopsr66-tls -n default -o yaml \
  | sed 's/namespace: default/namespace: observabilidade/' \
  | kubectl apply -f -

Agora a secret TLS estará disponível no mesmo namespace da aplicação.

2. Criação do Ingress com TLS

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: prometheus-ingress
  namespace: observabilidade
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/backend-protocol: "HTTP"
    nginx.ingress.kubernetes.io/proxy-body-size: "50m"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - prometheus.devopsr66.com
      secretName: devopsr66-tls
  rules:
    - host: prometheus.devopsr66.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: prometheus-operated
                port:
                  number: 9090

Explicação dos campos

  • metadata.name -> Nome do recurso Ingress.
  • namespace -> Mesmo namespace da aplicação (Ex: Observabilidade).
  • annotations -> Ativa o redirecionamento HTTPS e configura o comportamento do proxy.
  • ingressClassName: nginx -> Garante que o NGINX Ingress Controller será utilizado.
  • tls -> Define o domínio e o nome da Secret TLS usada para criptografia.
  • rules -> Define a rota HTTP (host e path) e o serviço de destino (nome e porta)

3. Aplica o Ingress

kubectl apply -f ingress-prometheus.yaml

4. Validar Ingress criado

kubectl get ingress -n observabilidade

5. Testando a aplicação

Caso ainda não esteja usando um DNS resolvido externamente, poderá configurar a aplicação no arquivo /etc/hosts para realizar os testes, rode o comando abaixo para configurar.

echo "192.168.123.233 prometheus.devopsr66.com" | sudo tee -a /etc/hosts

Acesse o endereço prometheus.devopsr66.com no navegador e verifica o certificado.

Até aqui configuramos a forma tradicional de expor serviços com TLS. No próximo passo, vamos evoluir a configuração adicionando o Cloudflare Tunnel e o Cloudflare Access, trazendo autenticação, proteção extra e acesso global.
