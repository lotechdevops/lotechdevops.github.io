Instalação e Configuração do MetalLB no Kubernetes

Objetivo desta seção​

Nesta etapa, vamos entender o papel do MetalLB no ambiente Kubernetes e realizar sua instalação.

Diferente de cluster hospedados em nuvens públicas (como EKS, GKE ou AKS), ambientes on-premises não possuem balanceadores de carga nativo.

MetalLB supre essa necessidade, fornecendo um mecanismo para expor serviços do tipo LoadBalancer de forma funcional em redes locais.

O que é o MetalLB?​

O MetalLB é um Load Balancer de rede para cluster Kubernetes que estão rodando fora da nuvem, como em ambientes bare-metal, datacenters próprios ou laboratórios locais.

Enquanto provedores como AWS, GCP e Azure oferecem serviços de LoadBalancer automaticamente (através de serviços como ELB, NLB, etc), o Kubernetes em ambientes on-premises não possui essa funcionalidade por padrão. O MetalLB preenche essa lacuna ao implementar o tipo LoadBalancerde forma nativa.

Como o MetalLB funciona?​

O MetalLB pode operar em dois modos principais:

  • Layer 2: responde diretamente a requisições ARP na rede local, fazendo o tráfego fluir diretamente para o pod correto.
  • BGP (Border Gateway Protocol): integra com roteadores externos para anunciar os IPs públicos disponíveis.

Neste tutorial, usaremos o modo Layer 2.

Instalação e Configuração do MetalLB​

1. Criação do Namespace para o MetalLB​

kubectl create namespace metallb-system

2. Instalação do MetalLB via manifesto​

kubectl apply -f https://raw.githubusercontent.com/metallb/metallb/v0.13.10/config/manifests/metallb-native.yaml

Verificar se o MetalLB foi instalado corretamente

kubectl get pods -n metallb-system

Você deverá ver os pods controller e speaker rodando

3. Configuração do Pool de IPs​

Agora precisamos definir a faixa de IPs que o MetalLB poderá distribuir aos serviços do tipo LoadBalancer.

3.1 - Criar o recurso IPAddressPool

apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: metallb-pool
  namespace: metallb-system
spec:
  addresses:
    - 192.168.123.233-192.168.123.240

Essa faixa deve estar dentro da rede do seu cluster, mas fora do intervalo de IPs usados pelos nós do cluster.

3.2 - Criar o recurso L2Advertisement

apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: metallb-l2
  namespace: metallb-system
spec:
  ipAddressPools:
    - metallb-pool

3.3 - Salve os dois arquivos YAML e aplique com:

kubectl apply -f metallb-pool.yaml
kubectl apply -f metallb-l2.yaml

3.4 - Verifique se os recuros foram criados corretamente:

kubectl get ipaddresspools -n metallb-system
kubectl get l2advertisements -n metallb-system

Com o MetalLB instalado e configurado, agora é possível expor serviços no seu cluster local utilizando o tipo LoadBalancer. Essa será a base para integrar o Ingress-NGINX, que também será exposto através de um IP definido pelo MetalLB.
