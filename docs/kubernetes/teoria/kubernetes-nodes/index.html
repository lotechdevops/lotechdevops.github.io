Kubernetes Workers: componentes e papel dos nós de trabalho

No Kubernetes, a execução da carga de trabalho acontece nos Workers (ou Nós).

Cada nó pode ser uma máquina virtual ou uma máquina física, dependendo de como o cluster foi configurado.

Um nó é responsável por hospedar os Pods, que são a menor unidade de execução no Kubernetes. Para isso, cada nó conta com alguns componentes essenciais que permitem rodar e gerenciar os contêineres:

  • Kubelet
  • Kube-proxy
  • Container Runtime (ex: containerd, CRI-O, Docker)

Esses serviços são gerenciados pela camada de controle (Control Plane), garantindo que o estado desejado do cluster seja respeitado.

Kubelet​

O Kubelet é o agente principal que roda em cada nó do Kubernetes. Ele atua como uma ponte entre o Control Plane e o worker, garantindo que os Pods estejam em execução conforme definido nas especificações.

As principais responsabilidades do Kubelet incluem:

1. Gerenciamento de Pods

  • Garante que os contêineres descritos nos manifestos estejam em execução e íntegros.
  • Se um contêiner falhar, o Kubelet toma as ações necessárias (reiniciar, remover ou reportar falha).

2. Gerenciamento de Recursos:

  • Monitora e impõe limites de CPU, memória e outros recursos.
  • Eele decide quais Pods podem rodar dentro do nó de acordo com as solicitações (requests) e limites (limits).

3. Monitoramento de Integridade:

  • Reporta constantemente o status dos contêineres para o Control Plane.
  • Usa probes (readiness/liveness) para verificar se os Pods estão saudáveis.

4. Gerenciamento de Volumes:

  • Monta volumes nos contêineres conforme especificado no manifesto. Isso garante acesso a armazenamento persistente ou temporário.

5. Configuração de Rede:

  • Trabalha junto ao runtime e aos plugins de rede (CNI) para configurar IPs, namespaces e mapeamento de portas.

6. Gerenciamento de Imagens:

  • Faz o download de imagens de registros de contêiner e garante que a versão correta esteja rodando.

Em resumo, o Kubelet é o executor do estado desejado: ele recebe instruções do Control Plane e traduz em ações reais no nó.

Kube-Proxy​

O Kube-Proxy é o componente responsável pela rede dentro do cluster. Ele roda em cada worker e garante que o tráfego seja roteado corretamente para os Pods e Services.

Suas principais funções:

  • Roteamento de tráfego:

    • Mantém regras de rede para encaminhar solicitações para os Pods corretos.

  • Modos de operação:

    • IPTables mode: utiliza regras de iptables para rotear tráfego. Funciona bem, mas pode ter limitações em clusters grandes.
    • IPVS mode: usa o módulo IPVS do kernel Linux, oferecendo maior desempenho e escalabilidade.

  • Monitoramento constante:

    • O kube-proxy se comunica com a API do Kubernetes para detectar novos Pods, Services e Endpoints, atualizando regras de rede automaticamente.

Além disso, o kube-proxy é peça-chave para a exploração de serviços para fora do cluster, seja via NodePort, LoadBalancer ou Ingress Controller.

Condições do Nó​

Além dos componentes internos, o Kubernetes também monitora o estado de cada nó através de condições.
Essas condições indicam se o nó está íntegro e se pode receber novas cargas de trabalho.

Condição do NóDescrição
Ready (Pronto)True se o nó estiver íntegro e pronto para aceitar Pods. False se não estiver aceitando Pods e Unknown se o controlador do nó não tiver recebido atualizações dentro do node-monitor-grace-period (padrão: 40s).
OutOfDisk (Sem espaço)Indica se o nó está sem espaço livre suficiente em disco. Se True, pode não ser possível agendar novos Pods. (Observação: condição descontinuada em versões recentes do Kubernetes, substituída por métricas mais específicas).
DiskPressure (Disco)Indica se o nó está sob pressão de disco, como pouco espaço disponível ou problemas de E/S.
MemoryPressure (Memória)True quando o nó está com pouca memória disponível, o que pode afetar a execução dos Pods.
PIDPressure (Processos)True se houver muitos processos em execução no nó (pressão de PIDs).
NetworkUnavailable (Rede)Indica se o nó não está conectado à rede ou enfrenta problemas de conectividade, impedindo a comunicação com o cluster.
