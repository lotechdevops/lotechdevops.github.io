ConfigMaps no Kubernetes: gerenciamento de configurações

O que são ConfigMaps?​

No Kubernetes, os ConfigMaps são objetos utilizados para armazenar dados de configuração não sensíveis em pares chave-valor, permitindo que os aplicativos usem essas informações sem a necessidade de alterar o código ou reconstruir a imagem.

O uso de ConfigMaps promove o desacoplamento entre a configuração e a aplicação, facilitando ajustes de comportamente em tempo de execução. São ideais para armazenar configurações como:

  • Strings de conexão com banco de dados.
  • Parâmetros de inicialização.
  • Arquivos .properties, .env ou .conf.

Como os ConfigMaps funcionam?​

Um ConfigMap pode ser:

  • Criado a partir de pares chave=valor.
  • Criado a partir de arquivos de configuração.
  • Injetado como variáveis de ambiente, arquivos em volume ou utilizado diretamente via API.

Quando um Pod usa ConfigMap, ele pode referenciar valores específicos ou montar todo o conteúdo do ConfigMap como arquivos.

Como usar um ConfigMap em um Pod​

Você pode utilizar um ConfigMap de quatro formas principais:

  1. Dentro de comandos command ou args do contêiner.
  2. Como variáveis de ambiente individuais.
  3. Como volume montado contendo arquivos de configuração.
  4. Via API do Kubernetes (em controladores personalizados ou operators).

Exemplo de um manifesto de um ConfigMap​

apiVersion: v1
kind: ConfigMap
metadata:
  name: my-configmap
data:
  key1: value1
  key2: value2

Configurando um ConfigMap em Pod​

Como variável de ambiente​

apiVersion: v1
kind: Pod
metadata:
  name: cm-pod-env
spec:
  containers:
    - name: cm-container
      image: busybox
      command: [ "/bin/sh", "-c", "env" ]
      env:
        - name: DB_ENV
          valueFrom:
            configMapKeyRef:
              name: cm-env-file
              key: conf.database

Como múltiplas variáveis de ambiente​

apiVersion: v1
kind: Pod
metadata:
  name: cm-pod-env
spec:
  containers:
    - name: cm-container
      image: busybox
      command: [ "/bin/sh", "-c", "env" ]
      env:
        - name: DB_ENV
          valueFrom:
            configMapKeyRef:
              name: cm-env-file
              key: conf.database
        - name: DB_IP
          valueFrom:
            configMapKeyRef:
              name: cm-env-file
              key: conf.database.ip

Como um volume montado​

apiVersion: v1
kind: Pod
metadata:
  name: cm-pod-volume
spec:
  containers:
    - name: cm-container
      image: busybox
      command: [ "/bin/sh", "-c", "env" ]
      volumeMounts:
        - name: config-volume
          mountPath: /config
  volumes:
    - name: config-volume
      configMap:
        name: cm-env-file
