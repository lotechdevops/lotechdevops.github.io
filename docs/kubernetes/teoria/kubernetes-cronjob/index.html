CronJob no Kubernetes: agendamento de tarefas

O que é um CronJob?​

Um CronJob no Kubernetes é um recurso que permite agendar a execução de tarefas recorrentes, similar ao comando cron em sistemas Unix/Linux. É comumente utilizado para automações como:

  • Backups periódicos
  • Geração de relatórios
  • Execução de scripts de manutenção
  • Envio de notificações
  • Limpeza de arquivos ou registros antigos

Cada execução programada do CronJob cria um Job, que por sua vez cria um ou mais Pods para realizar a tarefa.

Como funciona um CronJob?​

O funcionamento de uma CronJob no Kubernetes segue um fluxo bem definido baseado em **agendamento, execução e histórico:

1. Agendamento pela Control Plane

  • O agendador (kube-controller-manager) monitora continuamente os CronJob e verifica se há alguma tarefa agendada para ser executada, com base no campo schedule.

2. Criação de Job

  • Quando chega a hora definida pelo schedule, o Kubernetes cria um objeto do tipo Job, que é o responsável direto por executar o Pod com a tarefa desejada.

3. Execução do Pod

  • O Job criado gera um ou mais Pods para rodar a tarefa. Após a conclusão (com sucesso ou falha), o Job atualiza seu status.

4. Histórico de Execuções

  • O CronJob mantém um histórico de execuções por meio dos campos successfulJobsHistoryLimit e failedJobsHistoryLimit. Isso ajuda a controlar a quantidade de Jobs antigos armazenados no cluster.

5. Política de Concorrência

  • Antes de agendar uma nova execução, o CronJob avalia se há execuções anteriores ainda em andamento e aplica a política definida em concurrencyPolicy.

6. Falhas de Agendamento

  • Se o Kubernetes estiver indisponível ou atrasar a execução de um Job agendado (por exemplo, por congestionamento no cluster), ele pode ainda executar o Job se estiver dentro do tempo permitido por startingDeadlineSeconds.

Componentes Principais​

  • Job Template (jobTemplate)

    • Específica o conteúdo do Job que será executado. Inclui definições como imagem do container, comandos, variáveis de ambiente, etc.

  • Schedule (schedule)

    • Define o cronograma com sintaxe cron padrão (* * * * *), indicando a frequência de execução.

  • Concurrency Policy (concurrencyPolicy)

    • Controla como lidar com múltiplas execuções concorrentes:
      • Allow (padrão): permite múltiplas execuções em paralelo.
      • Forbid: impede novas execuções se uma anterior ainda estiver rodando.
      • Replace: encerra a execução anterior para iniciar a nova.

Exemplo de um manifesto de um CronJob​

apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-database
  labels:
    app: backup
spec:
  schedule: "0 2 * * *"                 # Executa todos os dias às 2h da manhã
  concurrencyPolicy: Forbid             # Não permite múltiplas execuções simultâneas
  startingDeadlineSeconds: 100          # Tempo limite para iniciar após o horário agendado
  successfulJobsHistoryLimit: 3         # Mantém 3 execuções bem-sucedidas no histórico
  failedJobsHistoryLimit: 1             # Mantém 1 execução com falha no histórico
  suspend: false                        # Se true, o cronjob será pausado
  jobTemplate:
    spec:
      template:
        metadata:
          labels:
            app: backup
        spec:
          restartPolicy: OnFailure
          containers:
          - name: db-backup
            image: alpine:3.18
            command:
              - /bin/sh
              - -c
              - "echo 'Executando backup...' && sleep 20 && echo 'Backup finalizado!'"

Explicando o manifesto de um CronJob

schedule:
  • Define a frequência de execução no formato cron (0 2 * * *) = 2h da manhã.
concurrencyPolicy:
  • Controla concorrência: Allow, Forbid ou Replace.
startingDeadlineSeconds:
  • Tempo máximo para iniciar uma execução atrasada.
successfulJobsHistoryLimit:
  • Limita a quantidade de Jobs bem-sucedidos mantidos.
failedJobsHistoryLimit:
  • Limita a quantidade de Jobs com falha mantidos.
suspend:
  • Se true, pausa novas execuções do CronJob.
restartPolicy:
  • OnFailure garante reinício do Pod em caso de falha.
command:
  • Comando que será executado dentro do contêiner.
