LimitRange no Kubernetes: limites de CPU e memória

O que é LimitRange?​

O recurso LimitRange é utilizado para definir restrições e padrões de uso de recursos (como CPU, memória e armazenamento) dentro de um namespace no Kubernetes.

Ele serve para evitar o consumo excessivo ou mal configurado por parte dos pods, promovendo uma alocação mais eficiente e previsível dos recursos disponíveis no cluster.

Funcionalidades do LimitRange​

1. Definir padrões (default): Aplica automaticamente valores padrão de requests e limits para contêineres que não os especificam.

2. Impor limites máximos e mínimos: Restringe o intervalo de valores aceitáveis que podem ser configurados nos contêineres.

3. Melhorar a qualidade de serviço (QoS): Garante que os pods sejam classificados corretamente em QoS (Guaranteed, Burstable, BestEffort), com base nos recursos declarados.

Estrutura básica do LimitRange​

apiVersion: v1
kind: LimitRange
metadata:
  name: example-limit-range
  namespace: meu-namespace
spec:
  limits:
  - type: Container
    max:
      cpu: "1"
      memory: "1Gi"
    min:
      cpu: "100m"
      memory: "128Mi"
    default:
      cpu: "500m"
      memory: "512Mi"
    defaultRequest:
      cpu: "200m"
      memory: "256Mi"

Explicação dos campos:

  • max: -> Valor máximo que um contêiner pode solicitar para CPU e memória.
  • min: -> Valor mínimo permitido para o recursos solicitados.
  • default: -> Valor que será aplicado como limit padrão, se o contêiner não definir um.
  • defaultRequest: Valor que será aplicado como request padrão, se o contêiner não definir um.
  • type: Define o escopo das regras, que pode ser Container ou Pod. O mais comum é Container.

Benefícios do uso de LimitRange​

  • Evita sobrecarga acidental: Protege o cluster de contêineres mal configurados que poderiam consumir recursos exageradamente.
  • Aplica boas práticas automaticamente: Garante que nenhum contêiner fique sem request ou limit.
  • Padroniza consumo de recursos: Ajuda a manter consistência no uso de CPU e memória entre aplicações.
  • Estabiliza o cluster: Reduz o risco de instabilidade por consumo descontrolado de recursos.
