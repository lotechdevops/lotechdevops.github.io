Ingress no Kubernetes: roteamento e exposição de aplicações

O que é um Ingress?​

O Ingress é um recurso do Kubernetes que gerencia o acesso externo aos serviços internos do cluster.

Ele atua como uma camada de roteamento HTTP/HTTPS, permitindo direcionar requisições externas para diferentes serviços com base em critérios como o nome do host, o caminho da URL ou até mesmo o método HTTP utilizado.

Essa funcionalidade é especialmente útil quando queremos expor diversas aplicações rodando no cluster por meio de um único ponto de entrada. Em vez de criar vários serviços do tipo LoadBalancer, o que pode gerar custos e complicações, é possível configurar um único Ingress para rotear o tráfego de forma inteligente.

Como o Ingress funciona​

O Ingress por si só é apenas uma declaração de regras de roteamento, mas não faz nada até que um Ingress Controller esteja instalado no cluster. O Ingress Controller é quem escuta os objetos Ingress e aplica as configurações reais de roteamento, atuando como um proxy reverso entre o mundo externo e os serviços internos.

Entre os Ingress Controllers mais utilizados estão o Nginx, HAProxy, Traefik e o Istio (para casos mais avançados com malha de serviço).

Quando um cliente externo faz uma requisição HTTP ou HTTPS ao cluster, o Ingress Controller intercepta a requisição e, com base nas regras definidas no objeto Ingress, direcina o tráfego para o serviço correspondente, que, por sua vez, encaminha para o Pod correto.

Exemplo prático do funcionamento de um Ingress no Kubernetes utilizando o controlador NGINX. O tráfego externo chega pelo Load Balancer, passa pelo Ingress Controller e é roteado para os serviços internos com base nas regras definidas no Ingress.

Principais funcionalidades do Ingress​

Um Ingress bem configurador pode fornecer diversas capacidades avançadas:

  • Roteamento por host: permite que diferentes domínios (como api.meusite.com e admin.meusite.com) apontem para serviços distintos dentro do cluster.
  • Roteamento por caminho: permite que diferentes rotas (como /api, /admin, /app) sejam redirecionadas para diferentes serviços.
  • Balanceamento de carga: distribui automaticamente o tráfego entre os Pods de um mesmo serviço.
  • Terminação SSL/TLS: o Ingress pode ser configurado para aceitar conexões HTTPS e lidar com certificados, fornecendo comunicação segura aos usuários.
  • Reescrita de URL e redirecionamento: com uso de anotações, é possível modificar o caminho da requisição ou redirecionar para outra rota.
  • Fallback com backend padrão: caso nenhuma regra de roteamento seja atendida, o Ingress pode encaminhar o tráfego para um serviço padrão.

Por que utilizar o Ingress ?​

Além de simplificar a exposição de serviços, o Ingress traz uma camada de controle centralizada para o tráfego de entrada do cluster. Ele abstrai a complexidade de lidar com múltiplos LoadBalancers, portas abertas e configurações de rede, facilitando o gerenciamento e reforçando a segurança.

Ingress também é altamente integrável com provedores de nuvem. Na AWS, GCP ou Azure, por exemplo, é comum utilizar um serviço LoadBalancer externo que ponta para o Ingress Controller, unindo o melhor dos dois mundos: o provisionamento automático de IP público e a flexibilidade de roteamento do Ingress.

Exemplo de Uso

Imagine que você tenha dois serviços rodando no cluster: um frontend e uma API. Com um Ingress, é possível configurar regras para:

  • Redirecionar https://meusite.com para o frontend
  • Redirecionar https://meusite.com/api para o backend

Essa separação é feita dentro de um único objeto Ingress, com regras simples e organizadas.

Exemplo de um manifesto de um Ingress​

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: meu-ingress
  namespace: default
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - meusite.com
      secretName: meusite-tls
  rules:
    - host: meusite.com
      http:
        paths:
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: meu-servico-api
                port:
                  number: 8080
          - path: /
            pathType: Prefix
            backend:
              service:
                name: meu-servico-frontend
                port:
                  number: 80

Explicação dos principais campos

ingressClassName: nginx
  • Indica que o controlador de Ingress responsável por processar esse objeto será o do NGINX.
annotations:
  • Adiciona comportamentos extras ao Ingress, como reescrita de rota (rewrite-target) e redirecionamento automático para HTTPS (ssl-redirect).
tls:
  • Configura HTTPS para o domínio meusite.com, utilizando o Secret com o certificado chamado meusite-tls.
rules:
  • Quando o caminho for /api, o tráfego será enviado para o serviço meu-servico-api na porta 8080.
  • Quando o caminho for /, será enviado para meu-servico-frontend na porta 80.
