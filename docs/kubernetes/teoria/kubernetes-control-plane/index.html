Control Plane do Kubernetes: componentes e funções

O que é o Control Plane?​

O Control Plane é o cérebro do Kubernetes.

Ele é responsável por tomar decisões globais sobre o cluster (como agendamento de pods), além de monitorar e reagir a eventos (como criar um novo pod quando uma réplica falha).

Embora, em teoria, os componentes do Control Plane possam ser executados em qualquer nó dos cluster, normalmente eles são concentrados em nós dedicados chamados de master nodes. Em ambientes de produção, recomenda-se executar múltiplas instâncias para garantir alta disponibilidade.

Componentes do Control Plane​

1. kube-apiserver​

O kube-apiserver é a porta de entrada do cluster Kubernetes. Ele expõe a API RESTFul, permitindo que usuários, ferramentas (como o kubectl) e outros componentes se comuniquem com o cluster.

Principais responsabilidades:

  • Endpoint da API: Oferece um endpoint seguro (HTTP/HTTPS) para acesso ao cluster.
  • Autenticação e Autorização: Garante que apenas usuários e serviços autorizados executem ações.
  • Validação de Objetos: Valida manifestos e solicitações de acordo com esquemas predefinidos.
  • Gerenciamento de Recursos: Manipula recursos do Kubernetes (Pods, Services, Deployments, etc).
  • Controle de Admissão: Permite aplicar políticas e restrições personalizadas antes de persistir no etcd.
  • Escalabilidade: Pode ser executado em múltiplas instâncias atrás de um balanceador de carga.

2. kube-scheduler​

O kube-scheduler é responsável por decidir em qual nó cada pod deve ser executado.

Quando um pod é criado, ele inicialmente não tem um nó associado. O scheduler avalia recursos disponíveis e aplica regras para selecionar o nó ideal.

Critérios de decisão incluem:

  • Recursos disponíveis: CPU, memória e capacidade do nó.
  • Afinidade e antiafinidade: Regras que influenciam onde os pods podem ou não ser alocados.
  • Prioridade de Pod: Pods críticos podem ter prioridade maior no agendamento.
  • Condições do Nó: Evita agendar pods em nós com problemas de saúde.
  • Relação entre Pods: Define se determinados pods devem estar juntos ou separados.

3. kube-controller-manager​

O kube-controller-manager executa diversos controladores que garantem que o estado real do cluster acompanhe o estado desejado.

Ele funciona como um conjunto de loops de controle, cada um responsável por um aspecto do cluster.

Principais controladores:

  • Node Controller: Monitora a saúde dos nós e reage a falhas.
  • Replication Controller: Garante que o número desejado de réplicas esteja sempre em execução.
  • Endpoints Controller: Atualiza os objetos Endpoints com base nos Services.
  • Namespace Controller: Gerencia criação e exclusão de namespaces.
  • Service Account Controller: Cria e gerencia contas de serviço.

Em ambientes de produção, várias instâncias do kube-controller-manager podem ser executadas para aumentar a disponibilidade.

4. etcd​

O etcd é um banco de dado distribuído chave-valor que armazena todo o estado do cluster kubernetes.

Ele é fundamental para a consistência do sistema.

Funções principais:

  • Coordenação do Cluster: Mantém informações de nós, Pods, Services e configurações.
  • Armazenamento de Configuração: Guarda todos os dados do cluster de forma consistente.
  • Alta Disponibilidade: É comum rodar múltiplas instâncias de etcd em cluster, usando o algoritmo Raft para eleição de líder.
  • Descoberta de Serviço: Permite que os componentes consultem dados atualizados do cluster.
  • Consistência Forte: Garante que todos os nós enxerguem o mesmo estado.

5. cloud-controller-manager​

O cloud-controller-manager permite a integração do Kubernetes com provedores de nuvem (AWS, GCP, Azure, etc).

Ele executa apenas controladores que dependem de APIs de nuvem, separando essa lógica dos demais componentes.

Principais controladores relacionados à nuvem:

  • Node Controller: Detecta se um nó foi removido da nuvem.
  • Route Controller: Configura rotas na infraestrutura da nuvem.
  • Service Controller: Cria e gerencia balanceadores de carga extremos.

Esse componente só existe quando o cluster está rodando em nuvem pública ou privada que possui suporte. Em ambientes locais (on-premises), ele não é necessário.

Resumo​

O Control Plane é composto por:

  • kube-apiserver: Porta de entrada e API central.
  • kube-scheduler: Decide onde cada pod vai rodar.
  • kube-controller-manager: Conjunto de controladores que mantém o estado desejado.
  • etcd: Banco de dados chave-valor distribuído.
  • cloud-controller-manager: Integração com provedores de nuvem.
