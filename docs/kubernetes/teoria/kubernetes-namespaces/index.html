Namespaces no Kubernetes: organização e isolamento

O que são Namespaces?​

No Kubernetes, os Namespaces são uma forma de organizar e isolar recursos dentro de um cluster. Eles funcionam como ambientes virtuais separados, permitindo que você divida logicamente os recursos, mesmo que eles estejam rodando no mesmo cluster físico.

Eles são especialmente úteis em cenários onde múltiplas equipes, ambientes (como dev, homolog e prod) ou projetos copartilham o mesmo cluster. Cada Namespace atua como um "mini cluster" dentro do cluster principal, com seus próprios Pods, Services, ConfigMaps, Secrets e outros objetos.

Por que usar Namespaces?​

Alguns dos principais motivos para utilizar Namespaces são:

  • Separação lógica de ambientes (dev, stating, prod, etc).
  • Delegação de acesso: você pode aplicar políticas de RBAC específicas por Namespace.
  • Gerenciamento de recursos: com objetos como ResourceQuota e LimitRange, é possível controlar o uso de CPU, memória e número de objetos por Namespace.
  • Organização de grandes clusters: em clusters com muitos times ou projetos, Namespaces ajudam a manter tudo organizado e controlado.

Como os Namespaces funcionam​

Por padrão, o Kubernetes já vem com alguns Namespaces criados:

  • default -> Usado quando nenhum namespace é especificado.
  • kube-system -> Componentes internos do Kubernetes (como kube-dns, kube-proxy, etc).
  • kube-public -> Acesso público, geralmente para informações como a configuração do cluster.

Você pode criar quantos Namespaces quiser, conforme a necessidade da sua organização.

Exemplo de manifesto de um Namespace​

apiVersion: v1
kind: Namespace
metadata:
  name: ambiente-dev

Esse manifesto cria um Namespace chamado ambiente-dev.

Boas práticas​

  • Use um Namespace por ambiente
  • Utilize Namespaces para segmentar times e aplicações em cluster multi-tenant.
  • Aplique ResourceQuota para limitar o uso de CPU/memória por Namespace.
  • Use o RBAC para restringir permissões de usuários por Namespace.
