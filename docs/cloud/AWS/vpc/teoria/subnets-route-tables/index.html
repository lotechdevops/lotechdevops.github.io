Sub-redes e Route Tables

Sub-redes (subnets)​

Uma sub-rede é uma faixa de IPs dentro do CIDR da VPC, criada em uma única zona de disponibilidade (AZ). As instâncias EC2 e outros recursos são lançados dentro de sub-redes.

Regras importantes:

  • Uma sub-rede fica em uma só AZ e não pode se estender por várias.
  • O CIDR da sub-rede tem de /16 a /28 e precisa estar dentro do CIDR da VPC.
  • Sub-redes da mesma VPC não podem ter CIDRs sobrepostos.
  • O CIDR IPv4 de uma sub-rede não pode ser alterado depois de criada.
  • 5 IPs de cada sub-rede são reservados pela AWS (veja o artigo anterior).
observação

Para alta disponibilidade, crie sub-redes em pelo menos duas AZs e distribua os recursos entre elas.

Sub-rede pública x privada​

O que torna uma sub-rede pública ou privada não é o nome, e sim a route table associada a ela.

TipoRota para a internetUso típico
PúblicaTem rota 0.0.0.0/0 para um Internet GatewayLoad Balancers, servidores web, bastion hosts
PrivadaNão tem rota para um Internet GatewayAplicações, bancos de dados

Para um recurso em sub-rede pública ser acessível pela internet, ele ainda precisa de um IP público (ou Elastic IP) e de regras de Security Group e NACL que permitam o tráfego.

Na sub-rede você também define se as instâncias recebem IP público automaticamente ao serem lançadas (opção Auto-assign public IPv4 address).

observação

Recursos em sub-redes privadas que precisam sair para a internet (atualizações, APIs) usam um NAT Gateway, visto no próximo artigo.

Route tables (tabelas de rotas)​

Uma route table é um conjunto de regras (rotas) que decide para onde o tráfego de uma sub-rede é enviado. Cada rota tem:

  • Destino: um bloco CIDR (por exemplo 0.0.0.0/0)
  • Alvo (target): para onde enviar (Internet Gateway, NAT Gateway, peering, etc.)

A rota local​

Toda route table tem, por padrão, uma rota local para o CIDR da VPC. É ela que permite que todas as sub-redes da mesma VPC conversem entre si, sem internet e sem configuração. Ela não pode ser removida.

Route table principal x customizada​

TipoComo funciona
Principal (main)Criada junto com a VPC. Toda sub-rede sem associação explícita usa a principal.
CustomizadaCriada por você e associada a sub-redes específicas.
  • Uma sub-rede está associada a uma route table por vez.
  • Uma route table pode ser usada por várias sub-redes.
aviso

Boa prática: não adicione rota para a internet na route table principal. Como ela vale para qualquer sub-rede nova sem associação, uma sub-rede criada sem querer já nasceria pública. Deixe a principal só com a rota local e use route tables customizadas.

Alvos mais comuns​

AlvoUso
localTráfego dentro da VPC
igw-...Internet Gateway
nat-...NAT Gateway
eigw-...Egress-only Internet Gateway (IPv6)
pcx-...VPC Peering
tgw-...Transit Gateway
vgw-...Virtual Private Gateway (VPN)
vpce-...VPC Endpoint (Gateway)

Exemplos de route tables​

Sub-rede pública (rota para o Internet Gateway):

DestinoAlvo
10.0.0.0/16local
0.0.0.0/0igw-xxxxxxxx

Sub-rede privada (saída pelo NAT Gateway):

DestinoAlvo
10.0.0.0/16local
0.0.0.0/0nat-xxxxxxxx

Sub-rede privada sem saída para a internet (somente rede interna):

DestinoAlvo
10.0.0.0/16local

Qual rota vale: a mais específica​

Quando mais de uma rota combina com o destino, a AWS usa a mais específica, ou seja, a de maior prefixo (longest prefix match).

Exemplo com esta route table:

DestinoAlvo
10.0.0.0/16local
172.31.0.0/16pcx-xxxxxxxx
0.0.0.0/0igw-xxxxxxxx
  • Tráfego para 10.0.5.20 → local (combina com 10.0.0.0/16).
  • Tráfego para 172.31.4.9 → pcx-xxxxxxxx (peering).
  • Tráfego para 8.8.8.8 → igw-xxxxxxxx (só 0.0.0.0/0 combina).

Exemplo de planejamento: 2 AZs, 2 camadas​

VPC 10.0.0.0/16, com sub-redes públicas e privadas em duas AZs:

Sub-redeAZCIDRTipoRoute table
public-aa10.0.0.0/24Públicart-publica (IGW)
public-bb10.0.1.0/24Públicart-publica (IGW)
private-aa10.0.10.0/24Privadart-privada-a (NAT da AZ a)
private-bb10.0.11.0/24Privadart-privada-b (NAT da AZ b)

Deixe faixas livres para crescer (por exemplo, para uma camada de banco de dados em 10.0.20.0/24).

Dica de diagnóstico​

Quando algo não conecta, verifique nesta ordem:

  1. Route table da sub-rede (existe a rota? a associação está certa?)
  2. Network ACL da sub-rede
  3. Security Group do recurso

Uma rota ausente ou a sub-rede associada à route table errada é uma das causas mais comuns de "não consigo acessar".

Limites padrão​

RecursoLimite padrão
Sub-redes por VPC200
Route tables por VPC200

Resumo rápido​

  • Sub-rede = uma AZ; pública ou privada depende da route table.
  • Rota local liga todas as sub-redes da VPC e não se remove.
  • Sub-rede sem associação usa a route table principal.
  • Vence a rota mais específica (maior prefixo).
  • Sub-rede pública: rota 0.0.0.0/0 para o IGW; privada: sem essa rota (saída via NAT).
