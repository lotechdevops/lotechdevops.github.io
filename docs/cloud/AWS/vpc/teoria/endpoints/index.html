VPC Endpoints

O problema​

Uma instância em sub-rede privada precisa acessar o S3, o SQS ou o Secrets Manager. Esses serviços têm endpoints públicos. Sem outra opção, o tráfego sai pelo NAT Gateway, passa pela internet pública e você paga pelo processamento de cada GB.

O VPC Endpoint resolve isso: cria um caminho privado entre a VPC e o serviço, dentro da rede da AWS, sem Internet Gateway, sem NAT e sem IP público.

Os dois tipos principais​

Gateway EndpointInterface Endpoint (PrivateLink)
Como funcionaUma rota na route tableUma ENI com IP privado na sua sub-rede
ServiçosSomente S3 e DynamoDBA maioria dos serviços da AWS e serviços de terceiros
CustoGratuitoPor hora (por AZ) + por GB processado
Usa PrivateLinkNãoSim
Alcançável de fora da VPCNão (local à VPC)Sim, via VPN, Direct Connect ou peering
SegurançaPolicy do endpointPolicy do endpoint + Security Group

Gateway Endpoint​

Funciona por rota. Ao criar o endpoint e escolher as route tables, a AWS adiciona uma entrada assim:

DestinoAlvo
pl-xxxxxxxx (prefix list do S3)vpce-xxxxxxxx (o endpoint)
  • A prefix list é uma lista de faixas de IP do serviço, mantida pela AWS. Você não precisa atualizar nada.
  • A rota do endpoint é mais específica que 0.0.0.0/0, então o tráfego para o S3 usa o endpoint automaticamente. Seu código não muda.
  • Só vale para as route tables associadas. Sub-redes em outras route tables continuam usando o endpoint público.
  • Não há cobrança pelo endpoint nem pelos dados que passam por ele. Você paga apenas pelo uso normal do S3 ou DynamoDB.

Dica de custo​

Se suas instâncias privadas trafegam muitos dados com o S3 pelo NAT Gateway, criar um Gateway Endpoint elimina essa parte da cobrança do NAT. É uma das otimizações mais simples e mais comuns.

Interface Endpoint (AWS PrivateLink)​

Cria uma ENI com IP privado na(s) sub-rede(s) que você escolher. O serviço passa a ser acessado por esse IP.

Pontos importantes​

  • Crie o endpoint em uma sub-rede por AZ para alta disponibilidade.
  • Controle o acesso com um Security Group anexado ao endpoint (por exemplo, liberar HTTPS 443 só para o Security Group da aplicação).
  • Com o Private DNS ligado, o nome público do serviço (como sqs.us-east-1.amazonaws.com) passa a resolver para o IP privado do endpoint. O código continua igual.
  • Para o Private DNS funcionar, a VPC precisa ter enableDnsSupport e enableDnsHostnames ativados (veja o artigo de DNS na VPC).
  • Tem custo por hora e por GB. Para poucos serviços e pouco tráfego, o custo é baixo; com muitos endpoints em várias AZs, soma.

Exemplos de uso​

  • Acessar SQS, SNS, Secrets Manager, SSM ou ECR de sub-redes privadas sem NAT.
  • Acessar o S3 a partir da rede on-premises (pela VPN ou Direct Connect), onde o Gateway Endpoint não alcança.
  • Consumir um serviço de terceiros (SaaS) de forma privada, ou expor o seu próprio serviço a outras VPCs ou contas.

Policy do endpoint​

Todo endpoint aceita uma policy (JSON, igual à do IAM) que limita o que pode ser feito por ele.

Exemplo de uso: permitir que o endpoint do S3 acesse apenas o bucket da sua empresa. Isso ajuda a evitar que dados sejam enviados para buckets de outras contas.

A policy do endpoint não substitui as permissões do IAM. As duas precisam permitir.

Qual escolher?​

SituaçãoEscolha
Acessar S3 ou DynamoDB de dentro da VPCGateway Endpoint (grátis)
Acessar S3 de on-premises pela VPN ou Direct ConnectInterface Endpoint
Acessar SQS, SNS, Secrets Manager, SSM, ECR etc. de sub-rede privadaInterface Endpoint
Consumir ou publicar um serviço via PrivateLinkInterface Endpoint

Resumo rápido​

  • VPC Endpoint = acesso privado a serviços da AWS, sem internet e sem NAT.
  • Gateway Endpoint: rota com prefix list, só S3 e DynamoDB, gratuito, só dentro da VPC.
  • Interface Endpoint: ENI com IP privado, quase todos os serviços, cobrado por hora e por GB, protegido por Security Group.
  • Use o Gateway Endpoint do S3 para reduzir a conta do NAT Gateway.
  • Policies de endpoint limitam o que pode ser acessado e somam com o IAM.
