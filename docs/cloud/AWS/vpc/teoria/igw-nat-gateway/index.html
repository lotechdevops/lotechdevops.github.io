Internet Gateway e NAT Gateway

Como a VPC acessa a internet​

Uma VPC nova não tem acesso à internet. Dois componentes resolvem isso, cada um para um caso:

ComponenteDireçãoUso
Internet Gateway (IGW)Entrada e saídaRecursos em sub-redes públicas
NAT GatewaySomente saídaRecursos em sub-redes privadas

Internet Gateway (IGW)​

O Internet Gateway é o componente que liga a VPC à internet. A AWS o descreve como um componente escalável horizontalmente, redundante e altamente disponível, que suporta tráfego IPv4 e IPv6. Você não precisa se preocupar com banda nem com disponibilidade dele.

Ele faz duas coisas:

  • Serve de alvo nas route tables para o tráfego destinado à internet.
  • Faz a tradução de endereço (NAT 1:1) entre o IP privado da instância e o IP público (ou Elastic IP) dela.

O que torna uma instância acessível pela internet​

Os quatro itens são necessários, ao mesmo tempo:

  1. Um Internet Gateway anexado à VPC
  2. Uma rota 0.0.0.0/0 para o IGW na route table da sub-rede
  3. A instância com IP público ou Elastic IP
  4. Security Group e NACL liberando o tráfego

Se qualquer um faltar, a instância não é acessível. Esse é o roteiro de diagnóstico mais usado.

Características​

  • Um IGW por VPC (e uma VPC por IGW).
  • A VPC padrão já vem com IGW; em uma VPC customizada você cria e anexa o seu.
  • O IGW em si não tem custo, mas há cobrança pela transferência de dados de saída e pelo IPv4 público dos recursos.

Egress-only Internet Gateway (IPv6)​

Endereços IPv6 são públicos por padrão. Para permitir que instâncias saiam para a internet por IPv6, mas impedir que a internet inicie conexões com elas, use o Egress-only Internet Gateway.

  • Funciona somente para IPv6 (para IPv4 use NAT Gateway).
  • Escalável, redundante e altamente disponível, e sem custo.
  • Rota na sub-rede privada: ::/0 → eigw-xxxxxxxx.

NAT Gateway​

O NAT Gateway permite que recursos de sub-redes privadas acessem a internet (para baixar atualizações, chamar APIs, etc.), sem que a internet consiga iniciar conexões com eles. O tráfego sai com o IP do NAT Gateway.

Instância privada (10.0.10.5)
      │  rota 0.0.0.0/0 → nat-xxxx
      ▼
NAT Gateway (sub-rede pública, com Elastic IP)
      │  rota 0.0.0.0/0 → igw-xxxx
      ▼
Internet Gateway → Internet

Tipos de conectividade​

TipoO que faz
PúblicoAcesso à internet. Fica em uma sub-rede pública e usa um Elastic IP
PrivadoComunicação com outras VPCs ou com a rede da empresa, sem acesso à internet

Como configurar (NAT Gateway zonal, o clássico)​

  1. Crie o NAT Gateway em uma sub-rede pública e associe um Elastic IP.
  2. Na route table da sub-rede privada, adicione 0.0.0.0/0 → nat-xxxxxxxx.
  3. A sub-rede pública do NAT precisa ter rota para o IGW.

Alta disponibilidade​

O NAT Gateway zonal funciona dentro de uma AZ. Para não depender de uma única zona, crie um NAT Gateway por AZ e aponte a route table de cada sub-rede privada para o NAT da mesma AZ.

Regional NAT Gateway (novidade)​

Em novembro de 2025, a AWS lançou o modo regional do NAT Gateway. Em vez de criar um NAT por AZ, você cria um só para a VPC e ele se expande e se contrai automaticamente pelas AZs onde há carga de trabalho.

CaracterísticaZonalRegional
EscopoUma AZA VPC inteira, em várias AZs
Sub-rede pública para hospedarPrecisaNão precisa
Route tablesUma rota por AZUma única rota para o ID do NAT
Elastic IPs por AZAté 8Até 32
Conectividade privadaSuportaNão suporta
  • A expansão para uma nova AZ pode levar até 60 minutos. Nesse intervalo, o tráfego dessa AZ passa por outra AZ.
  • Há dois modos: automático (a AWS gerencia IPs e AZs, recomendado) e manual.
observação

O modo zonal continua existindo e é o mais encontrado em ambientes atuais e em provas. Conheça os dois.

Custos do NAT Gateway​

O NAT Gateway é um dos itens que mais surpreendem na fatura. Cobra-se por:

  • Hora em que o gateway existe
  • Gigabyte de dados processados
  • IPv4 público (o Elastic IP do NAT)
  • Transferência entre AZs, quando a instância e o NAT estão em AZs diferentes

Como referência, em us-east-1 o NAT Gateway custa cerca de US$ 0,045 por hora mais US$ 0,045 por GB processado (confira a página de preços da sua Região).

aviso

Em laboratórios, apague o NAT Gateway ao terminar e libere o Elastic IP dele. Ele cobra por hora mesmo sem tráfego.

Como reduzir o custo​

  • Use VPC Endpoints do tipo Gateway para S3 e DynamoDB. Eles não têm cobrança por hora nem por GB e tiram esse tráfego do NAT.
  • Mantenha instâncias e NAT na mesma AZ.
  • Para ambientes de estudo, avalie se a sub-rede realmente precisa de saída para a internet.

NAT Gateway x NAT Instance​

NAT GatewayNAT Instance
GerenciamentoAWS (totalmente gerenciado)Você (uma EC2 configurada como NAT)
DisponibilidadeAlta, dentro da AZVocê precisa montar
EscalaAutomáticaLimitada ao tamanho da instância
Uso hojeRecomendadoLegado; só em casos específicos de custo

IGW x NAT Gateway​

Internet GatewayNAT Gateway
Sub-rede dos recursosPúblicaPrivada
Internet inicia conexão para dentroSim (se SG/NACL permitirem)Não
Recurso precisa de IP públicoSimNão
CustoSem custo próprioPor hora + por GB
Rota0.0.0.0/0 → igw0.0.0.0/0 → nat

Resumo rápido​

  • IGW: entrada e saída para sub-redes públicas; HA e sem custo próprio; um por VPC.
  • Egress-only IGW: só saída por IPv6.
  • NAT Gateway: só saída para sub-redes privadas; fica em sub-rede pública com Elastic IP; um por AZ (zonal) ou um regional para a VPC.
  • NAT Gateway cobra por hora e por GB: apague nos laboratórios e use Gateway Endpoints para S3 e DynamoDB.
