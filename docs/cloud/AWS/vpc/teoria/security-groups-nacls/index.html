Security Groups e Network ACLs

Duas camadas de firewall​

A VPC tem dois firewalls que trabalham juntos, em camadas:

Security Group (SG)Network ACL (NACL)
NívelInstância (interface de rede, ENI)Sub-rede
EstadoStatefulStateless
Tipos de regraSomente permitirPermitir e negar
AvaliaçãoTodas as regras são avaliadasRegras em ordem numérica; a primeira que combina vale
Tráfego de respostaLiberado automaticamentePrecisa de regra explícita
PadrãoNega entrada, permite saídaNACL padrão libera tudo
AssociaçãoVárias por recursoUma por sub-rede

Security Groups​

O Security Group é um firewall virtual que controla o tráfego de entrada (inbound) e de saída (outbound) de um recurso, no nível da interface de rede (ENI).

Como funciona​

  • Só tem regras de permissão. Não existe regra de bloqueio explícito.
  • O que não é permitido é negado.
  • É stateful: se uma conexão de entrada é permitida, a resposta sai automaticamente, sem precisar de regra de saída (e vice-versa).
  • As alterações valem imediatamente, sem reiniciar a instância.

Regras​

Cada regra tem protocolo, porta (ou faixa) e origem/destino. A origem pode ser:

  • Um IP ou faixa CIDR (203.0.113.10/32, 10.0.0.0/16)
  • Outro Security Group (muito usado, veja abaixo)
  • Uma prefix list

Comportamento padrão​

SituaçãoEntradaSaída
Security Group novoTudo negadoTudo permitido
Security Group padrão da VPCPermite tráfego vindo do próprio grupoTudo permitido

O Security Group padrão da VPC não pode ser excluído.

Referenciar outro Security Group​

Em vez de liberar um IP, você pode liberar "quem faz parte do Security Group X". É a forma mais limpa de montar arquiteturas em camadas:

Security GroupEntrada permitida
sg-albHTTPS 443 de 0.0.0.0/0
sg-appHTTP 8080 de sg-alb
sg-dbMySQL 3306 de sg-app

Assim, só o balanceador fala com a aplicação, e só a aplicação fala com o banco, mesmo que os IPs mudem.

Limites padrão​

ItemLimite
Regras por Security Group60 de entrada e 60 de saída
Security Groups por interface de rede5
Security Groups por Região2.500

As regras de todos os Security Groups associados a uma interface são somadas.

Boas práticas​

  • Aplique o menor privilégio: abra só as portas necessárias.
  • Não use 0.0.0.0/0 para SSH, RDP ou banco de dados. Use o seu IP, uma VPN ou o Session Manager.
  • Dê nomes e descrições claros aos grupos.
  • Use referência entre Security Groups em vez de IPs fixos.

Network ACLs (NACLs)​

A Network ACL é um firewall no nível da sub-rede: filtra o tráfego que entra e sai da sub-rede, para todos os recursos dentro dela.

Como funciona​

  • É stateless: não guarda estado. Entrada e saída são avaliadas separadamente, então a resposta também precisa de regra.
  • As regras têm número e são avaliadas do menor para o maior. Quando uma regra combina, ela é aplicada e as demais são ignoradas.
  • Tem regras de permitir e de negar.
  • Ao final há uma regra * que nega o que não combinou com nenhuma regra.
  • Cada sub-rede tem uma NACL; uma NACL pode ser usada por várias sub-redes.

NACL padrão x customizada​

TipoComportamento
NACL padrãoJá existe na VPC e permite todo o tráfego de entrada e de saída (regra 100)
NACL customizadaNasce negando tudo, até você adicionar regras de permissão

Portas efêmeras​

Como a NACL é stateless, a resposta de uma conexão volta por uma porta efêmera (faixa 1024-65535) do cliente. Você precisa liberar essa faixa para o tráfego de retorno.

Exemplo de NACL para uma sub-rede pública de servidor web:

Entrada (inbound)

RegraTipoPortaOrigemAção
100HTTP800.0.0.0/0Permitir
110HTTPS4430.0.0.0/0Permitir
120SSH22203.0.113.10/32Permitir
130TCP personalizado1024-655350.0.0.0/0Permitir
*Todo o tráfegoTodas0.0.0.0/0Negar

Saída (outbound)

RegraTipoPortaDestinoAção
100HTTP800.0.0.0/0Permitir
110HTTPS4430.0.0.0/0Permitir
120TCP personalizado1024-655350.0.0.0/0Permitir
*Todo o tráfegoTodas0.0.0.0/0Negar
observação

Numere as regras de 10 em 10 ou de 100 em 100. Assim você consegue inserir novas regras entre as existentes sem renumerar tudo.

Quando usar NACL​

Como o Security Group não tem regra de negação, a NACL é o lugar para bloquear um IP ou uma faixa específica (por exemplo, um atacante conhecido). Fora isso, os Security Groups costumam resolver, e a NACL fica como camada extra de proteção da sub-rede.

Limite padrão​

ItemLimite
Regras por NACL20 de entrada e 20 de saída (ajustável)

Como os dois trabalham juntos​

Para um pacote entrar em uma instância, ele passa pelas duas camadas:

Internet → Route table → NACL da sub-rede (entrada) → Security Group da instância → Instância

Na saída, o caminho é o inverso: Security Group, depois NACL da sub-rede. Os dois precisam permitir o tráfego.

Diagnóstico: "não consigo conectar"​

Siga a ordem:

  1. Route table da sub-rede: existe a rota correta?
  2. NACL da sub-rede: há regra permitindo entrada e a saída das portas efêmeras? Há algum Negar antes?
  3. Security Group da instância: a porta e a origem estão liberadas?
  4. Dentro da instância: o serviço está rodando e escutando na porta? O firewall do sistema operacional está liberando?

Resumo rápido​

  • Security Group: nível da ENI, stateful, só permite, todas as regras avaliadas, resposta liberada automaticamente.
  • NACL: nível da sub-rede, stateless, permite e nega, regras em ordem numérica, resposta precisa de regra (portas efêmeras 1024-65535).
  • NACL padrão libera tudo; NACL customizada nega tudo até você criar regras.
  • Para bloquear um IP, use a NACL.
  • SG: 60 regras por sentido e 5 SGs por interface (padrão).
