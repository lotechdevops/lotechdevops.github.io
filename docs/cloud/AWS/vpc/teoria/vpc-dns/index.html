DNS na VPC

Como a VPC resolve nomes​

Toda VPC tem um servidor DNS embutido, o Route 53 Resolver (também chamado de Amazon DNS server ou AmazonProvidedDNS). Ele responde às consultas das instâncias sem custo adicional e sem você configurar nada.

Endereços do Resolver​

EndereçoObservação
169.254.169.253Endereço fixo (IPv4), sempre o mesmo em qualquer VPC
Base da VPC + 2Por exemplo, 10.0.0.2 em uma VPC 10.0.0.0/16
fd00:ec2::253Endereço IPv6

Todos apontam para o mesmo serviço.

Limite: cada interface de rede pode enviar até 1024 pacotes por segundo ao Resolver, e esse limite não pode ser aumentado. Aplicações que fazem muitas consultas DNS sem cache podem sofrer throttling.

Os dois atributos da VPC​

AtributoO que faz
enableDnsSupportLiga a resolução DNS pelo servidor da Amazon. Desligado, as consultas ao Resolver falham
enableDnsHostnamesFaz as instâncias com IP público receberem um nome DNS público (como ec2-52-1-2-3.compute-1.amazonaws.com)

Valores padrão​

VPCenableDnsSupportenableDnsHostnames
VPC padrãoLigadoLigado
VPC criada por vocêLigadoDesligado (no console, você escolhe ao criar)

Quando os dois precisam estar ligados​

  • Zonas hospedadas privadas do Route 53 (domínios internos, como app.interno).
  • Private DNS de Interface Endpoints (veja o artigo de VPC Endpoints).

Esquecer o enableDnsHostnames é uma causa comum de "o endpoint não resolve para o IP privado".

Nomes DNS das instâncias​

Ao lançar uma instância na VPC, ela recebe:

  • Um hostname privado (por exemplo, ip-10-0-1-25.ec2.internal), que resolve para o IP privado.
  • Um hostname público, se tiver IP público e o enableDnsHostnames estiver ligado. Dentro da VPC, esse nome resolve para o IP privado; fora da VPC, para o IP público.

DHCP Option Sets​

O DHCP option set define as configurações de rede entregues às instâncias na inicialização, como:

  • Servidores DNS (padrão: AmazonProvidedDNS).
  • Nome de domínio (domain name).
  • Servidores NTP.

Você pode criar um option set próprio para usar servidores DNS da empresa (por exemplo, um Active Directory). Cada VPC usa um option set por vez, e a troca vale para novas concessões de DHCP.

Se trocar o DNS por um servidor próprio, ele precisa saber resolver os nomes que você precisa, inclusive os da AWS. Por isso, em muitos casos é melhor manter o AmazonProvidedDNS e usar o Resolver para encaminhar o que for da empresa.

Zonas hospedadas privadas​

Uma private hosted zone do Route 53 cria nomes visíveis só dentro das VPCs associadas:

  • db.interno → 10.0.2.15
  • api.interno → 10.0.1.30

Você pode associar a mesma zona a várias VPCs, inclusive de contas diferentes. Os detalhes de registros e políticas ficam na seção do Route 53.

DNS híbrido: Resolver Endpoints​

O Resolver da VPC não é acessível pela rede da empresa, e as instâncias não enxergam o DNS da empresa por padrão. Para resolver nomes nos dois sentidos, existem os Resolver Endpoints:

EndpointDireçãoUso
InboundOn-premises → AWSServidores da empresa consultam nomes da AWS (como zonas privadas)
OutboundAWS → On-premisesInstâncias consultam nomes da empresa, por regras de encaminhamento

Detalhes:

  • Os endpoints são ENIs nas sub-redes da VPC, com Security Group.
  • Funcionam sobre VPN ou Direct Connect.
  • No outbound, você cria regras (por exemplo, corp.empresa.com → servidor DNS 192.168.0.10).
  • Têm custo por hora de cada interface.

Diagnóstico: "o nome não resolve"​

  1. Os atributos enableDnsSupport e enableDnsHostnames estão ligados?
  2. A instância usa o DNS correto? (AmazonProvidedDNS no DHCP option set?)
  3. A zona privada está associada à VPC que consulta?
  4. É DNS híbrido? Existe Resolver Endpoint e a regra correta?
  5. O Security Group do endpoint permite DNS (porta 53, UDP e TCP)?

Resumo rápido​

  • O Route 53 Resolver responde às consultas da VPC em 169.254.169.253 e na base da VPC + 2.
  • enableDnsSupport liga a resolução. enableDnsHostnames dá nomes DNS públicos às instâncias.
  • Zonas privadas e Private DNS de Interface Endpoints exigem os dois atributos ligados.
  • DHCP option set define quais servidores DNS as instâncias usam.
  • Para DNS híbrido, use Resolver Endpoints: inbound (empresa → AWS) e outbound (AWS → empresa).
