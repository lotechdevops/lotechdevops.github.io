VPC Flow Logs e Reachability Analyzer

Duas ferramentas, duas perguntas​

FerramentaPergunta que responde
VPC Flow LogsO que aconteceu? Quais conexões foram aceitas ou rejeitadas
Reachability AnalyzerIsso deveria funcionar? Onde, na configuração, o caminho é bloqueado

VPC Flow Logs​

Registram metadados do tráfego IP que passa pelas interfaces de rede (ENIs) da VPC. Não capturam o conteúdo dos pacotes, apenas quem falou com quem.

Onde habilitar​

Em três níveis:

  • VPC: todas as interfaces da VPC.
  • Sub-rede: todas as interfaces da sub-rede.
  • ENI: uma interface específica.

Qual tráfego registrar​

FiltroRegistra
ACCEPTSó o tráfego permitido
REJECTSó o tráfego bloqueado (por Security Group ou NACL)
ALLOs dois

Destinos​

DestinoQuando usar
CloudWatch LogsConsultar com Logs Insights, criar métricas e alarmes
Amazon S3Guardar por muito tempo e analisar (por exemplo, com Athena)
Amazon Data FirehoseEnviar para ferramentas externas (SIEM)

Como é um registro​

Cada linha traz campos separados por espaço, como:

CampoSignificado
srcaddr / dstaddrIP de origem e de destino
srcport / dstportPortas de origem e destino
protocolNúmero do protocolo (6 = TCP, 17 = UDP, 1 = ICMP)
packets / bytesVolume do fluxo
actionACCEPT ou REJECT
log-statusOK, NODATA ou SKIPDATA

Você pode usar o formato padrão ou um formato personalizado, escolhendo os campos.

Os registros são agregados em um intervalo (1 ou 10 minutos) e levam um tempo adicional até aparecer no destino. Não são tempo real.

O que não é registrado​

  • Tráfego para o DNS da Amazon (Route 53 Resolver).
  • Acesso ao serviço de metadados (169.254.169.254).
  • Amazon Time Sync (169.254.169.123).
  • Tráfego DHCP.
  • Tráfego entre a ENI do endpoint e a interface do Network Load Balancer, entre outros.

Como usar para diagnosticar​

  • Muitos REJECT na porta 22 vindos de IPs desconhecidos: tentativas de acesso SSH.
  • ACCEPT na entrada, mas sem resposta: verifique a saída e a NACL (stateless).
  • Dica: filtre por REJECT para reduzir ruído e custo.

Custos​

Flow Logs não têm taxa própria de ativação, mas você paga pela ingestão e armazenamento no destino. Em VPCs com muito tráfego, o volume cresce rápido.

Reachability Analyzer​

Uma ferramenta de análise estática da configuração. Você informa origem, destino, protocolo e porta, e ela diz se existe um caminho.

Como funciona​

  • Não envia pacotes reais. Ela analisa a configuração (route tables, Security Groups, NACLs, gateways, peerings, Transit Gateway, endpoints).
  • Se o destino é alcançável, mostra o caminho salto a salto.
  • Se não é, aponta qual componente bloqueia (por exemplo, "falta rota" ou "NACL nega a porta 443").

Como usar​

  1. No console, VPC → Reachability Analyzer → Create and analyze path.
  2. Escolha origem, destino, protocolo e porta.
  3. Execute a análise e leia o resultado.

O path pode ser salvo e reexecutado depois de cada mudança.

Custo​

É cobrado por análise executada. Criar o path em si é gratuito.

Limitação​

Como é análise de configuração, não vê problemas dentro da instância (serviço parado, firewall do sistema operacional). Isso continua sendo verificado na máquina.

Quando usar cada um​

SituaçãoFerramenta
"Minha instância não alcança o banco. Onde está o bloqueio?"Reachability Analyzer
"Quem está tentando acessar meu servidor?"Flow Logs
Auditoria e conformidade (histórico de conexões)Flow Logs
Validar a rede depois de uma mudançaReachability Analyzer

Muitas vezes se usam juntos: o Analyzer indica o componente, e os Flow Logs confirmam o que realmente acontece.

Resumo rápido​

  • Flow Logs: registram metadados (não o conteúdo) do tráfego, em nível de VPC, sub-rede ou ENI.
  • Destinos: CloudWatch Logs, S3, Firehose. Filtro: ACCEPT, REJECT, ALL.
  • Não registram DNS da Amazon, metadados (169.254.169.254), DHCP e Time Sync.
  • Reachability Analyzer: análise estática, sem enviar tráfego, mostra o caminho ou o bloqueio.
  • Cobrado por análise. Não enxerga problemas dentro do sistema operacional.
