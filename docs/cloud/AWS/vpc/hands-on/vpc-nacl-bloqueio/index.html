NACL bloqueando um IP

Objetivo​

Usar uma Network ACL (NACL) para bloquear um IP específico na porta 80, o que o Security Group não consegue fazer, pois ele só tem regras de permissão. O teste usa o seu próprio IP.

Veja a teoria em Security Groups e NACLs.

aviso

Você vai bloquear só a porta 80 do seu IP. Não bloqueie o SSH (porta 22) do seu IP, senão perde o acesso à instância. Se acontecer, associe a sub-rede de volta à NACL padrão pelo console.

Pré-requisitos​

  • Instância ec2-publica em execução na sub-publica-1a
  • O seu IP público (descubra no seu computador com curl https://checkip.amazonaws.com)

Etapas​

1. Liberar a porta 80 no Security Group​

  1. Abra o lab-publica-sg → Editar regras de entrada → Adicionar regra.
  2. Tipo HTTP, origem Meu IP.
  3. Salve.

2. Subir o servidor de teste​

Conecte na ec2-publica e rode:

cd /tmp
sudo python3 -m http.server 80

No seu computador, acesse o servidor:

curl -m 5 http://IP_PUBLICO

Retorna a listagem de arquivos. Deixe o servidor rodando em outro terminal.

3. Criar a NACL personalizada​

  1. No console da VPC, clique em ACLs de rede → Criar ACL de rede.
  2. Nome: nacl-lab-bloqueio. VPC: lab-vpc.
  3. Clique em Criar ACL de rede.
observação

Uma NACL personalizada nasce negando todo o tráfego, de entrada e de saída. Por isso precisamos criar também as regras que liberam o que queremos.

4. Criar as regras de entrada​

  1. Selecione nacl-lab-bloqueio → aba Regras de entrada → Editar regras de entrada.
  2. Adicionar nova regra:
    • Número da regra: 100
    • Tipo: HTTP (80)
    • Origem: SEU_IP/32
    • Permitir/Negar: Negar
  3. Adicionar nova regra:
    • Número da regra: 200
    • Tipo: Todo o tráfego
    • Origem: 0.0.0.0/0
    • Permitir/Negar: Permitir
  4. Salve as alterações.

5. Criar a regra de saída​

  1. Aba Regras de saída → Editar regras de saída → Adicionar nova regra.
  2. Número da regra: 100. Tipo: Todo o tráfego. Destino: 0.0.0.0/0. Permitir/Negar: Permitir.
  3. Salve.

6. Associar a NACL à sub-rede​

  1. Aba Associações de sub-redes → Editar associações de sub-redes.
  2. Marque sub-publica-1a e salve.

7. Testar o bloqueio​

No seu computador:

curl -m 5 http://IP_PUBLICO

A conexão falha por tempo esgotado: a NACL negou a porta 80 do seu IP. Teste também o SSH:

ssh ec2-user@IP_PUBLICO

O SSH continua funcionando, pois só a porta 80 foi bloqueada, e a regra 200 libera o restante.

8. Provar que a ordem das regras importa​

  1. Edite as regras de entrada e troque os números: a regra de Permitir tudo passa a 50, e a de Negar HTTP continua em 100.
  2. Salve e repita o curl: agora a conexão funciona, porque a NACL avalia as regras em ordem numérica e a regra 50 (permitir tudo) combina primeiro.
  3. Volte os números ao original (Negar em 100, Permitir tudo em 200).

O que observar​

  • A NACL avalia as regras em ordem numérica, e a primeira que combina vale. Por isso o bloqueio fica antes da liberação geral.
  • NACLs são stateless: a resposta também precisa ser permitida. Aqui liberamos toda a saída com a regra de saída 100.
  • A NACL age na sub-rede inteira, e afeta todas as instâncias dela. Para bloquear só uma instância, use o Security Group.
  • É o único jeito de negar um IP específico na VPC.

Limpeza​

  1. No terminal da instância, pare o servidor com Ctrl + C.
  2. Associe a sub-publica-1a de volta à NACL padrão: em ACLs de rede, selecione a NACL padrão da lab-vpc → Editar associações de sub-redes → marque sub-publica-1a.
  3. Exclua a nacl-lab-bloqueio (Ações → Excluir ACL de rede).
  4. No lab-publica-sg, remova a regra HTTP que você criou.
