VPC Endpoint do S3

Objetivo​

Fazer uma instância em sub-rede privada, sem NAT Gateway, acessar o Amazon S3 usando um Gateway Endpoint. O S3 passa a ser acessado pela rede da AWS, sem internet.

Veja a teoria em VPC Endpoints.

Pré-requisitos​

  • Instância ec2-privada-1a em execução, com acesso SSH pela ec2-publica
  • Os NAT Gateways devem estar apagados (laboratório 4), e as rotas 0.0.0.0/0 das route tables privadas, removidas. Se o NAT existir, a instância alcança o S3 pela internet e o teste perde o sentido
  • Uma role do IAM com a política AmazonS3ReadOnlyAccess (a mesma do hands-on de IAM, ou crie uma nova, por exemplo role-ec2-s3-leitura, com o caso de uso EC2)

Etapas​

1. Criar um bucket de teste​

  1. Abra o console do S3 → Criar bucket.
  2. Nome: único no mundo, por exemplo lab-vpc-endpoint-SEU-NOME-123. Region: a mesma dos laboratórios.
  3. Mantenha Bloquear todo o acesso público ligado e clique em Criar bucket.
  4. Abra o bucket e envie um arquivo pequeno, por exemplo teste.txt.

2. Anexar a role à instância privada​

  1. No EC2, selecione a ec2-privada-1a → Ações → Segurança → Modificar função do IAM.
  2. Escolha a role com leitura do S3 e salve.
observação

As credenciais temporárias da role chegam à instância pelo serviço de metadados (169.254.169.254), que é local e não depende de internet.

3. Testar o S3 sem o endpoint​

Conecte na ec2-privada-1a (pela pública) e rode:

aws s3 ls --region us-east-1 --cli-connect-timeout 5

Use a Region onde você está trabalhando, no lugar de us-east-1.

O comando falha por tempo esgotado. A sub-rede privada não tem rota para a internet, e o S3 é um endpoint público.

4. Criar o Gateway Endpoint​

  1. No console da VPC, clique em Endpoints → Criar endpoint.
  2. Nome: vpce-s3-lab.
  3. Categoria do serviço: Serviços da AWS.
  4. Em Serviços, pesquise s3 e selecione o de Tipo: Gateway, no formato com.amazonaws.REGION.s3.
  5. VPC: lab-vpc.
  6. Tabelas de rotas: marque rt-privada-1a e rt-privada-1b.
  7. Política: Acesso total.
  8. Clique em Criar endpoint.

5. Ver a rota criada pela AWS​

  1. Abra a rt-privada-1a → aba Rotas.
  2. Há uma nova rota automática:
DestinoAlvo
10.0.0.0/16local
pl-xxxxxxxx (prefix list do S3)vpce-xxxxxxxx

A prefix list é a lista de faixas de IP do S3, mantida pela AWS.

6. Testar o S3 com o endpoint​

Na ec2-privada-1a, repita o comando:

aws s3 ls --region us-east-1 --cli-connect-timeout 5

Agora ele lista os seus buckets. Liste o conteúdo do bucket e baixe o arquivo:

aws s3 ls s3://lab-vpc-endpoint-SEU-NOME-123 --region us-east-1
aws s3 cp s3://lab-vpc-endpoint-SEU-NOME-123/teste.txt . --region us-east-1
cat teste.txt

Confirme também que a instância continua sem internet:

curl -m 5 https://checkip.amazonaws.com

Ainda falha. O endpoint só abre o caminho para o S3, e não para a internet.

O que observar​

  • O endpoint funciona por rota: a rota do S3 (pl-...) é mais específica que qualquer 0.0.0.0/0, então o tráfego para o S3 usa o endpoint automaticamente.
  • O comando da AWS CLI não mudou: nenhum parâmetro novo foi necessário.
  • O Gateway Endpoint é gratuito. Com o NAT Gateway, o mesmo tráfego seria cobrado por GB processado.
  • Só vale para as route tables associadas ao endpoint.
  • Funciona apenas dentro da VPC. Para acessar o S3 a partir da rede da empresa, seria preciso um Interface Endpoint.

Limpeza​

  1. Na ec2-privada-1a, apague o arquivo baixado: rm teste.txt.
  2. No S3, esvazie e exclua o bucket de teste.
  3. Se não for mais usar, desanexe a role da instância (Ações → Segurança → Modificar função do IAM → remover).
  4. O endpoint não tem custo e pode ficar. Se quiser apagar, vá em Endpoints → Ações → Excluir endpoints.
