EC2 em sub-rede pública e privada

Objetivo​

Lançar uma instância na sub-rede pública e uma instância privada em cada AZ, e testar na prática:

  • A instância pública é acessível pela internet.
  • As instâncias privadas não são acessíveis de fora, apenas pela pública.
  • As instâncias privadas não conseguem sair para a internet (ainda não há NAT).

Veja a teoria em Internet Gateway e NAT Gateway e Security Groups e NACLs.

Pré-requisitos​

  • VPC lab-vpc com quatro sub-redes, Internet Gateway e route tables (Internet Gateway e rotas)
  • Um key pair (.pem) para acessar as instâncias. Use o mesmo do laboratório de EC2 ou crie um novo
  • Terminal com cliente SSH

Etapas​

1. Criar o Security Group da instância pública​

  1. No EC2 (ou na VPC), vá em Grupos de segurança → Criar grupo de segurança.
  2. Nome: lab-publica-sg. Descrição: Instancia publica. VPC: lab-vpc.
  3. Regra de entrada: tipo SSH, origem Meu IP.
  4. Mantenha a saída padrão e clique em Criar grupo de segurança.

2. Criar o Security Group da instância privada​

  1. Crie outro: Nome: lab-privada-sg. VPC: lab-vpc.
  2. Regras de entrada:
    • SSH, origem o grupo lab-publica-sg
    • Todos os ICMP - IPv4, origem o grupo lab-publica-sg
  3. Mantenha a saída padrão e clique em Criar grupo de segurança.
observação

Em vez de um IP, a origem é outro Security Group: só instâncias que usam lab-publica-sg alcançam a privada. É o padrão das arquiteturas em camadas.

3. Lançar a instância pública​

  1. No EC2, clique em Executar instância.
  2. Nome: ec2-publica. AMI: Amazon Linux 2023. Tipo: t3.micro (ou o tipo elegível ao Free Tier da sua conta).
  3. Par de chaves: o seu.
  4. Em Configurações de rede, clique em Editar:
    • VPC: lab-vpc
    • Sub-rede: sub-publica-1a
    • Atribuir IP público automaticamente: Habilitar
    • Security group: selecione lab-publica-sg
  5. Clique em Executar instância.

4. Lançar as instâncias privadas​

Lance duas instâncias, uma em cada AZ:

NomeSub-rede
ec2-privada-1asub-privada-1a
ec2-privada-1bsub-privada-1b

Em ambas, selecione o mesmo par de chaves da ec2-publica. Sem ele, não será possível acessar as instâncias privadas por SSH.

Em ambas, em Configurações de rede:

  • VPC: lab-vpc
  • Atribuir IP público automaticamente: Desabilitar
  • Security group: lab-privada-sg

Clique em Executar instância.

Anote o IP público da ec2-publica e o IP privado de cada instância privada (coluna IPv4 privado, nos detalhes da instância):

  • ec2-privada-1a: começa com 10.0.11.
  • ec2-privada-1b: começa com 10.0.12.

5. Acessar a instância pública​

No seu computador, carregue a chave no agente SSH e conecte com o encaminhamento de agente (-A):

chmod 400 minha-chave.pem
ssh-add minha-chave.pem
ssh -A ec2-user@IP_PUBLICO
aviso

Use o encaminhamento de agente (-A) em vez de copiar o arquivo .pem para dentro da instância. Uma chave privada guardada em um servidor é um risco de segurança.

6. Acessar as instâncias privadas pela pública​

Dentro da ec2-publica, teste as duas:

ping -c 3 IP_PRIVADO_1A
ping -c 3 IP_PRIVADO_1B
ssh ec2-user@IP_PRIVADO_1A

Os pings respondem (a regra ICMP permite a origem lab-publica-sg) e o SSH funciona. Mesmo em AZs diferentes, a comunicação é direta, pela rota local da VPC. Você está dentro da ec2-privada-1a, que não tem IP público.

Saia (exit) e repita o SSH para o IP da ec2-privada-1b.

7. Testar a saída para a internet​

Dentro de uma das instâncias privadas:

curl -m 5 https://checkip.amazonaws.com

O comando falha por tempo esgotado. As route tables privadas não têm rota para a internet, e a instância não tem IP público. Repita nas duas instâncias privadas.

Agora saia da privada (exit) e, na ec2-publica, rode o mesmo comando:

curl -m 5 https://checkip.amazonaws.com

Ele responde com o IP público da instância. Essa sub-rede tem rota para o Internet Gateway.

O que observar​

  • As instâncias privadas só são acessíveis de dentro da VPC, e a regra do Security Group restringe a origem à instância pública.
  • A instância pública funciona como bastion host. Em produção, prefira o Session Manager, que dispensa porta de entrada.
  • Sem NAT Gateway, as instâncias privadas não instalam pacotes nem baixam atualizações. Resolvemos isso no próximo laboratório.
  • Uma instância com IP público cobra por hora pelo endereço IPv4 público, mesmo dentro do Free Tier.

Limpeza​

Mantenha as três instâncias para o próximo laboratório. Se for pausar os estudos, pare as instâncias (o IP público da ec2-publica muda ao reiniciar) ou encerre todas e recrie depois.
