Flow Logs e Reachability Analyzer

Objetivo​

Registrar o tráfego da VPC com VPC Flow Logs, consultar conexões aceitas e rejeitadas, e usar o Reachability Analyzer para descobrir qual regra bloqueia um caminho.

Veja a teoria em VPC Flow Logs e Reachability Analyzer.

Pré-requisitos​

  • lab-vpc com a ec2-publica e a ec2-privada-1b em execução (EC2 pública e privada)
  • Acesso SSH às instâncias com ssh -A

Parte 1: VPC Flow Logs​

1. Criar o grupo de logs​

  1. Abra o console do CloudWatch → Logs → Gerenciamento de logs → Criar grupo de logs.
  2. Nome: lab-vpc-flow-logs.
  3. Retenção: 1 dia, para não acumular custo.
  4. Classe de logs: Padrão
  5. Clique em Criar.

2. Criar o Flow Log da VPC​

  1. No console da VPC, selecione lab-vpc → aba Logs de fluxo → Criar log de fluxo.
  2. Nome: lab-flowlog.
  3. Filtro: Tudo (aceitos e rejeitados).
  4. Intervalo máximo de agregação: 1 minuto.
  5. Destino: Enviar para o CloudWatch Logs.
  6. Grupo de logs de destino: lab-vpc-flow-logs.
  7. Perfil do IAM: crie ou selecione um perfil de serviço para Flow Logs (o console oferece a criação).
  8. Formato do registro de log: Formato padrão da AWS.
  9. Clique em Criar log de fluxo.

3. Gerar tráfego aceito e rejeitado​

Conecte na ec2-publica (ssh -A) e rode:

ping -c 3 IP_PRIVADO_1B
curl -m 3 http://IP_PRIVADO_1B:9999
  • O ping é aceito (há regra de ICMP).
  • O curl na porta 9999 é rejeitado: nenhum Security Group libera essa porta.

Aguarde de 5 a 10 minutos para os registros aparecerem.

4. Consultar os logs​

  1. No CloudWatch, selecione o grupo de logs e clique em Visualizar no Logs Insights.
  2. Selecione o grupo lab-vpc-flow-logs.
  3. Rode a consulta:
fields @timestamp, interfaceId, srcAddr, dstAddr, dstPort, protocol, action
| filter action = "REJECT"
| sort @timestamp desc
| limit 20

Você deve ver a tentativa na porta 9999, com action igual a REJECT. Troque o filtro para ACCEPT e veja o ping.

observação

É normal aparecerem também registros REJECT de IPs desconhecidos da internet tentando portas da ec2-publica. São varreduras automáticas, comuns em qualquer IP público.

Parte 2: Reachability Analyzer​

5. Analisar um caminho bloqueado​

  1. No console da AWS, pesquise por Reachability Analyzer (ele fica no Network Manager, e não dentro do menu da VPC) e clique em Criar e analisar caminho.
  2. Nome: publica-para-privada-1b-9999.
  3. Tipo de origem: Instâncias → ec2-publica.
  4. Tipo de destino: Instâncias → ec2-privada-1b.
  5. Protocolo: TCP. Porta de destino: 9999.
  6. Clique em Criar e analisar caminho.

O resultado é Não alcançável, e o console aponta o componente que bloqueia: o Security Group da ec2-privada-1b, que não tem regra para a porta 9999.

6. Corrigir e analisar de novo​

  1. No Security Group da ec2-privada-1b, adicione uma regra de entrada: TCP personalizado, porta 9999, origem o Security Group da ec2-publica.
  2. No Reachability Analyzer, selecione o caminho e clique em Executar análise novamente.
  3. O resultado passa a Acessível, com o caminho listado salto a salto.

O que observar​

  • Flow Logs mostram o que aconteceu, e o Reachability Analyzer mostra o que a configuração permite. Eles se complementam.
  • Os Flow Logs registram metadados (IPs, portas, protocolo, ação), sem o conteúdo dos pacotes.
  • Os registros demoram alguns minutos: não são em tempo real.
  • O Reachability Analyzer não envia pacotes. Ele analisa a configuração e custa centavos por análise.
  • O Analyzer não enxerga problemas dentro da instância (serviço parado, firewall do sistema operacional).

Limpeza​

  1. Na lab-vpc, aba Logs de fluxo, exclua o lab-flowlog.
  2. No CloudWatch, exclua o grupo de logs lab-vpc-flow-logs.
  3. No Security Group da ec2-privada-1b, remova a regra da porta 9999.
  4. No Reachability Analyzer, exclua o caminho (criar o caminho não tem custo, e apagar mantém tudo organizado).
