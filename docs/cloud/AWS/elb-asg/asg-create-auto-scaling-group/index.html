Criação Auto Scaling Group

Agora que você já tem o Launch Template configurado, vamos criar o Auto Scaling Group que utilizará esse template para gerenciar automaticamente suas instâncias EC2. O ASG será responsável por manter o número desejado de instâncias, distribuí-las entre AZs e integrá-las com o ALB.

Pré-requisitos​

Certifique-se de ter:

  • Launch Template criado (capítulo 3.2)
  • ALB configurado com Target Group
  • VPC com subnets em múltiplas AZs
  • Security Groups das instâncias configurados

1. Criar Auto Scaling Group​

Acessar Auto Scaling Groups​

  1. AWS Console → EC2 → Auto Scaling → Auto Scaling Groups
  2. Clique em "Create Auto Scaling group"

Step 1: Choose launch template​

  1. Auto Scaling group name: Digite um nome para seu ASG
  2. Launch template: Selecione o Launch Template criado anteriormente (escolha uma versão específica)

Step 2: Choose Instance Launch Options​

  1. VPC: Selecione sua VPC (mesma do ALB)

  2. Availability Zones and subnets:

    • Selecione pelo menos 2 AZs diferentes
    • Escolha subnets privadas
    • Exemplo:
      • us-east-1a: subnet-private-1a
      • us-east-1b: subnet-private-1b

  3. Availability Zone distribution:

    • Selecione: "Balanced best effort" (recomendado)
      • Tenta distribuir igualmente entre todas as AZs selecionadas
      • Se uma AZ falhar: Continua lançando em outras AZs disponíveis
      • Flexibilidade: Prioriza manter o número desejado de instâncias
      • Comportamento: "Melhor esforço" para balanceamento

Step 3: Integrate with other services​

Esta configuração é onde selecionamos o Load Balancing que irá integrar com o ASG.

  1. Em Load balancing selecione "Attach to an existing load balancer"

  2. Em Attach to an existing load balancer selecione Choose from your load balancer target groups

    • Selecione seu Target Group (ex: tg-webserver)

  3. Em Health checks selecione "Turn on Elastic Load Balancing health checks"

    • Health check grace period: 300 seconds

Health Check Grace Period:

  • Tempo que o ASG aguarda antes de considerar uma nova instância "unhealthy"
  • 300 segundos permite que o User Data Script complete a configuração

Step 4: Configure group size and scaling​

Configure as capacidades do seu ASG:

1. Group size:

  • Desired capacity: 2
    • O que é: Número de instâncias que você quer manter em operação normal
    • Comportamento: ASG sempre tenta manter exatamente este número

2. Scaling:

  • Min desired capacity: Número mínimo de instâncias que sempre devem estar rodando.
  • Max desired capacity: Número máximo de instâncias que podem ser criadas.

3. Automatic scaling - Opcional

Esta seção controla como o ASG decide quando escalar automaticamente. No nosso exemplo iremos configurar como "No scaling policies"

  • Comportamento: Não escala automaticamente baseado em métricas

4. Instance maintenance policy

Esta configuração controla como o ASG substitui instâncias durante atualizações:

  • No policy (padrão): Novas instâncias são criadas antes de terminar outras.
  • Launch before terminating: Cria novas instâncias e aguarda ficarem prontas antes de terminar antigas.
  • Terminate and launch: Termina e cria instâncias ao mesmo tempo.
  • Custom behavior: Define valores personalizados para capacidade mínima e máxima disponível.

Para este tutorial usaremos "No policy"

As demais configurações "Additional capacity settings" e "Additional settings" iremos deixar como padrão.

Step 5: Add notifications and tags​

  1. Notifications (Opcional): Configure SNS se quiser alertas
  2. Tags: Adicione tags para organização:
Key: Name              | Value: ASG-WebServer
Key: Environment       | Value: Production
Key: ManagedBy         | Value: AutoScaling

Step 6: Review and create​

  1. Review todas as configurações
  2. Create Auto Scaling group
