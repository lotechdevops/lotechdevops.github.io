Configuração de SSL/TLS no Application Load Balancer

Neste capítulo, vamos evoluir o ALB básico criado no capítulo anterior adicionando certificados SSL/TLS para garantir comunicação segura.

Pré-requisito: ALB básico já configurado e funcionando conforme capítulo 2.3.

1. Visão Geral do SSL/TLS no ALB​

Por que usar HTTPS?

HTTPS (HTTP Secure) é essencial para aplicações modernas porque:

  • Criptografia: Protege os dados em trânsito entre cliente e servidor.
  • Autenticação: Garante que os usuários estão conectando ao site correto.
  • Performance: HTTP/2 (apenas com HTTPS) oferece melhor performance.
  • Compliance: Muitas regulamentações exigem HTTPS.

Como o ALB processa SSL/TLS​

Cliente HTTPS → ALB (Terminação SSL) → Target HTTP/HTTPS

O ALB pode fazer terminação SSL onde:

  1. Cliente se conecta via HTTPS ao ALB.
  2. ALB descriptografa o tráfego usando o certificado.
  3. ALB pode reenviar como HTTP ou HTTPS para o targets.
  4. Reduz carga de processamento SSL dos servidores backend.

Componentes necessários:​

  • ✅ Certificado SSL: via AWS Certificate Manager (ACM)
  • ✅ Listener HTTPS: Porta 443 no ABL
  • ✅ Política de Segurança: Define versões TLS surportadas.
  • ✅ Redirecionamento: HTTP -> HTTPS automático.

2. Solicitando Certificado via AWS Certificate Manager​

O AWS Certificate Manager (ACM) fornece certificados SSL/TLS gratuitos e gerenciados automaticamente.

Passo 1: Acessar o ACM​

  1. No console AWS, procure por Certificate Manager (ACM)
  2. Certifique-se de estar na mesma região do seu ALB.
  3. Clique em "Request".
  4. Selecione "Request a public certificate"
  5. Clique em "Next"
  6. Configure o "domain names"

💡Dica: Use wildcard (*.exemplo.com) para cobrir subdomínios como api.exemplo.com, admin.exemplo.com

  1. Escolha o método de validação DNS validation (recomendado)

Após solicitar o certificado:

  1. Abre o certificado na lista.
  2. Clique em "Create record in Route 53 (se usando Route 53)
  3. Ou copie os registros CNAME para seu provedor DNS.

⏱️ Tempo de validação: 5-30 minutos após configurar DNS

O Certificado passará pelos status:

  • Pending validation -> Aguardando validação DNS
  • Issued -> ✅ Pronto para uso!

3. Configurando Listener HTTPS​

Com o certificado pronto, vamos configurar o listener HTTPS no ALB.

Passo 1: Acessar o ALB​

  1. EC2 Console -> Load Balancers
  2. Selecione seu ALB criado no capítulo anterior
  3. Vá para a aba Listeners

Passo 2: Adicionar Listener HTTPS​

  1. Clique em "Add listener"
  2. Configure o listener
Protocol: HTTPS
Port: 443
Default actions: Forward to → [seu-target-group]

Passo 3: Configurar Certificado SSL​

  1. Seleciona "From ACM"
  2. Escolha o certificado que você criou
  3. Certificate: *.devopsr66.com (arn:aws:acm:....)

Security Policy:​

  • Recomendado: ELBSecurityPolicy-TLS13-1-2-Res-2021-06
  • Para compatibilidade máxima: ELBSecurityPolicy-2016-08
  • Para segurança máxima: ELBSecurityPolicy-FS-1-2-Res-2020-10

💡 Escolha da política:​

  • TLS 1.2: Boa compatibilidade e segurança
  • TLS 1.3: Máxima segurança, menos compatibilidade
  • Perfect Forward Secrecy: Segurança adicional

Passo 4: Confirmar Criação​

  1. Review todas as configurações.
  2. Clique em "Add"
  3. ✅ Listener HTTPS criado!

4. Configuração Endereço ALB no DNS Route 53​

  1. Copie a URL do ALB
  2. Entra no Route 53
  3. Clique no Hosted zones e abre o seu domínio.
  4. Clique em "Create record"
  5. Em Record name, escolha um subdomínio para o seu ALB.
  6. Em Record type, escolha CNAME
  7. Cole o endereço do ALB em Value
  8. Em TTL, escolha 1m.
  9. Clique em "Create records"

5. Implementando Redirecionamento HTTP → HTTPS​

Agora que você já tem o listener HTTPS funcionando, vamos configurar o redirecionamento automático para garantir que todo tráfego use HTTPS. Isso é uma melhor prática essencial para segurança web moderna.
