Bucket policy e acesso público

Objetivo​

Usar bucket policies para liberar a leitura pública de apenas um prefixo, manter o resto privado e negar acessos sem HTTPS.

Veja a teoria em Políticas no Amazon S3 e Block Public Access e Object Ownership.

Pré-requisitos​

  • Bucket lab-s3-SUFIXO dos laboratórios anteriores
  • Um terminal com curl (seu computador ou o CloudShell)
Ambiente de estudo

Este laboratório torna parte do bucket público. Use somente arquivos de teste sem informação sensível e refaça o bloqueio público na limpeza.

Etapas​

1. Preparar os objetos​

No bucket, crie as pastas publico e privado e envie:

ArquivoPastaConteúdo
index.txtpublico/Conteudo publico
segredo.txtprivado/Conteudo privado

Abra a URL do objeto de cada um no navegador. Os dois retornam AccessDenied, porque o bucket está com o bloqueio de acesso público ativo.

2. Desativar o bloqueio de acesso público​

  1. Aba Permissões → Bloquear acesso público (configurações do bucket) → Editar.
  2. Desmarque Bloquear todo o acesso público e salve.
  3. Confirme digitando confirmar.

Sem isso, a AWS rejeita qualquer policy que conceda acesso público.

3. Liberar leitura pública só do prefixo publico/​

  1. Permissões → Política do bucket → Editar.
  2. Cole a policy abaixo, trocando SEU_BUCKET pelo nome do bucket:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "LeituraPublicaPrefixoPublico",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::SEU_BUCKET/publico/*"
    }
  ]
}
  1. Salve e teste no navegador (troque a Region se for diferente):
https://SEU_BUCKET.s3.us-east-1.amazonaws.com/publico/index.txt
https://SEU_BUCKET.s3.us-east-1.amazonaws.com/privado/segredo.txt

O primeiro mostra Conteudo publico. O segundo continua com AccessDenied.

4. Exigir HTTPS​

Edite a policy e adicione um segundo statement dentro de Statement:

{
  "Sid": "NegarSemHTTPS",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": [
    "arn:aws:s3:::SEU_BUCKET",
    "arn:aws:s3:::SEU_BUCKET/*"
  ],
  "Condition": {
    "Bool": { "aws:SecureTransport": "false" }
  }
}

Teste com curl, mostrando só o código HTTP:

curl -s -o /dev/null -w "%{http_code}\n" http://SEU_BUCKET.s3.us-east-1.amazonaws.com/publico/index.txt
curl -s -o /dev/null -w "%{http_code}\n" https://SEU_BUCKET.s3.us-east-1.amazonaws.com/publico/index.txt

O primeiro retorna 403 (HTTP bloqueado). O segundo retorna 200.

O que observar​

  • Uma policy tem Effect, Principal, Action, Resource e, opcionalmente, Condition.
  • O Block Public Access é uma trava extra: mesmo com uma policy pública, ele bloqueia enquanto estiver ativo.
  • Um Deny explícito vale mais que qualquer Allow.
  • Dar acesso por prefixo evita expor o bucket inteiro.

Limpeza​

  1. Permissões → Política do bucket → Excluir.
  2. Bloquear acesso público → Editar → marque Bloquear todo o acesso público → salve.
