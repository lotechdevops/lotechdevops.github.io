Route 53 Resolver - DNS Recursivo para VPCs

O Amazon Route 53 Resolver é o componente responsável por fornecer resolução DNS recursiva dentro das VPCs da AWS.

Enquanto o Route 53 tradicional é usado como servidor autoritativo (responde por domínios que você gerencia), o Resolver atua como um cliente que busca resposta em outros servidores, internos ou externos.

Ele funciona como o servidor DNS padrão para instâncias EC2 em VPCs, mas pode ser customizado para rotear consultas DNS internas, externas ou híbridas, com controle total.

Por que o Route 53 Resolve existe?​

Por padrão, tods as instâncias em uma VPC usam o Route 53 Resolver automaticamente para resolver nomes de domínio.

Mas em ambientes complexos, como redes híbridas, multicontas ou conectividade com on-premises, você precisa de algo mais poderoso.

O Resolver permite:

  • Reencaminhar nomes de domínio específicos para servidores internos.
  • Resolver domínios privados da AWS entre contas.
  • Permitir que redes on-premises resolvam nomes de recursos em VPCs.
  • Fazer resolução bidirecional entre VPC - On-premises

Componentes Principais​

1. Endpoints do Resolver​

São interfaces de rede criadas dentro de uma VPC para habilitar consultas DNS direcionadas.

Existem dois tipos:

Outbound Endpoint​

  • Permite que a VPC envia requisições DNS para servidores fora da AWS (ex: um servidor BIND local, Active Directory, DNS da GCP, etc)
  • Você cria esse endpoint e define regras que redirecionam certos domínios (como .corp.local) para o destino desejado.

Inbound Endpoint​

  • Permite que redes externas enviem consultas DNS para sua VPC.
  • Muito útil para ambientes híbridos com VPN ou Direct Connect.
  • Exemplo: seu servidor DNS on-prem envia consultas para internal.app.aws hospedado em uma Hosted Zone privada.

2. Regras de Encaminhamento (Forwarding Rules)​

Regras que definem para onde o resolver deve encaminhar as consultas baseadas no domínio.

Você define:​

  • Um sufixo de domínio (ex: .corp.local)
  • Um ou mais servidores DNS para os quais as consultas devem ser encaminhadas

Essas regras podem ser:

  • Associadas a uma ou mais VPCs
  • Compartilhadas entre contas com AWS Resource Access Manager (RAM)

Segurança e Controle​

  • Os endpoints do resolver são integrados com Security Groups, permitindo controlar quem pode consultar.
  • Todo o tráfego DNS pode ser monitorado com VPC Flow Logs e CloudWatch.
  • É possível ativar DNS Firewall (Route 53 Resolver DNS Firewall) para filtrar e bloquear domínios maliciosos ou não permitidos.

Diferença entre Resolver e Route 53 "autoritativo"​

| Função                      | Route 53 Autoritativo     | Route 53 Resolver       |
| --------------------------- | ------------------------- | ----------------------- |
| Responde por domínios?      | ✅ Sim (ex: `meusite.com`) | ❌ Não, apenas encaminha |
| Consulta outros servidores? | ❌ Não                     | ✅ Sim (é recursivo)     |
| Suporta forwarding rules?   | ❌                         | ✅                       |
| Suporta redes híbridas?     | ❌                         | ✅ (com endpoints)       |
| DNS padrão da VPC?          | ❌                         | ✅ Sim                   |

Preço​

  • Cobrados por hora por endpoint (inbound ou outbound).
  • Também há cobrança por número de consultas DNS resolvidas via endpoints.

Conclusão​

O Route 53 Resolver é essencial em projetos de rede híbridas e arquitetura multi-conta. Ele oferece resolução DNS recursiva e controlada dentro das VPCs da AWS, com flexibilidade para conectar ambientes externos e aplicar lógica avançada.

Ao combiná-lo com Hosted Zones Privadas, AWS RAM e segurança por SGs, você obtém uma solução DNS corporativas e robusta, 100% gerenciada pela AWS.
