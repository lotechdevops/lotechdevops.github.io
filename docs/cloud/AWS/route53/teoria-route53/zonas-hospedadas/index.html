Zonas Hospedadas no Amazon Route 53

O que são Zonas Hospedadas (Hosted Zones)​

No Amazon Route 53, uma Hosted Zone é uma representação lógica da zona DNS de um domínio.

Ela contém todos os registros DNS necessários para direcionar o tráfego da internet (ou da rede interna) para os recursos do domínio.

Tipos de Zonas Hospedadas​

O Route 53 oferece dois tipos principais:

1. Zona Hospedada Pública​

  • Usada para domínios acessíveis pela internet.
  • Exemplo: meusite.com acessível publicamente.
  • Permite criar registros como A, AAAA, CNAME, MX, TXT, NS, SOA, etc.

2. Zona Hospedada Privada​

  • Usada para domínios visíveis apenas dentro da VPC da AWS.
  • Ideal para ambientes internos, microserviços privados ou redes híbridas.
  • Exemplo: app.local.corp, resolvido apenas dentro de uma VPC conectada ao Route 53.

Uma zona hospedada privada pode ser associada a uma ou mais VPCs.

Arquivos padrões criados automaticamente​

Ao criar uma zona, o Route 53 gera dois registros por padrão:

| Tipo    | Função                                                    |
| ------- | --------------------------------------------------------- |
| **NS**  | Define os name servers responsáveis pela zona             |
| **SOA** | Contém informações sobre o domínio e a autoridade da zona |

Explicação:

  • Registro NS (Name Server)

    • Mesmo em uma zona privada, o Route 53 gera um registro NS com os name servers da AWS, mas esse registro não é usado externamente, pois a zona não é pública.
    • Ele continua sendo necessário internamente para que o Route 53 saiba como tratar a autoridade da zona dentro da VPC.

  • Registro SOA (Start of Authority)

    • Define informações como:
      • O servidor DNS autorizado primário.
      • Contato administrativo
      • Intervalos de atualização e expiração de cache
    • É obrigatório por padrão em qualquer zona, pública ou privada

Resumo

| Tipo de Zona | Cria NS? | Cria SOA? | NS precisa ser configurado no registrador? |
| ------------ | -------- | --------- | ------------------------------------------ |
| Pública      | ✅        | ✅         | ✅                                          |
| Privada      | ✅        | ✅         | ❌ (uso interno na VPC)                     |

Exemplo - Zona Hospedada Pública​

A imagem abaixo mostra como funciona o uso de uma zona hospedada pública no Amazon Route 53 para resolver nomes de domínio da internet pública para serviços da AWS

Explicação:

  1. Cliente (Client):

    • O usuário digita example.com no navegador.
    • A requisição DNS é enviada para os name servers definidos na zona hospedada pública no Route 53.

  2. Zona Hospedada Pública:

    • Essa zona contém os registros DNS públicos do domínio, como:
      • A (para IPs públicos de EC2)
      • Alias (para S3, CloudFront, ALB, etc)

  3. Recursos que podem ser apontados pela zona hospedada pública:

    • Amazon S3 (Bucket com site estático)
      • Ex: www.example.com apontando para um bucket público.
    • Amazon CloudFront (CDN)
      • Ex: cdn.example.com apontando para distribuição CloudFront.
    • EC2 Instance (com IP público)
      • Ex: api.example.com apontando para uma instância EC2.
    • Application Load Balancer (ALB)
      • Ex: app.example.com usando um registro Alias para o ALB.

Observação:

  • Todos os alvos da zone de hospedagem pública devem ser recursos públicos acessíveis pela internet.
  • O Route 53 atua como o servidor DNS autoritativo para esse domínio.
  • O cliente final nunca vê o que está por trás, ele apenas acessa example.com e recebe a resposta correta via DNS.

Exemplo - Zona Hospedada Privada​

A imagem abaixo demonstra o funcionamento de uma zona hospedada privada no Amazon Route 53, usada para resolver nomes de domínios privados dentro de uma VPC.

Explicação:

  1. Zona Hospedada Privada:

    • Criada no Route 53 e associada a uma VPC específica.
    • Contém registros DNS para domínios internos, como api.example.internal ou db.example.internal

  2. Resolução interna via DNS:

    • As instâncias EC2 e os serviços da VPC consultam a zona hospedada privada ao tentar resolver nomes como:
      • api.example.internal -> 10.0.0.10
      • db.example.internal -> 10.0.0.35

  3. Recursos privados da AWS

    • Todas as resoluções apontam para endereços IP privados (sem acesso externo):
      • Instâncias EC2 com IP privado
      • Instâncias RDS privadas

Situações comuns de uso​

  • Comunicação entre microserviços que rodam em EC2 ou ECS.
  • Acesso interno a bancos de dados, como RDS, Aurora, Redis, etc.
  • Criação de nomes legíveis para aplicações internas, como:
    • webapp.example.internal
    • auth.exemple.internal
    • db.example.internal

Observação:

  • O nome de domínio privado (Ex: exemple.internal) não é visível na internet.
  • A resolução só funciona dentro da(s) VPC(s) associada(s) à zona.
  • Você pode associar uma zona hospedada privada a várias VPCs, mesmo em contas diferentes (com peering ou AWS RAM)
