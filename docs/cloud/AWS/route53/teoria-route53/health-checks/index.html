Health Checks no Route 53

O Amazon Route 53 Health Check é um recurso que permite monitorar a integridade de endpoints públicos, como servidores, aplicações web e serviços hospedados dentro ou fora da AWS.

Com ele, o Route 53 pode detectar falhas automaticamente e tomar decisões dinâmicas no DNS, como:

  • Redirecionar tráfego para um recurso de backup (failover).
  • Retornar somente os IPs saudáveis em respostas multivalor (multivalue answer).
  • Acionar alertas via CloudWatch.

O que é um Health Check?​

É um monitoramento automatizado, realizado periodicamente, onde o Route 53 verifica se um recurso está ativo, acessível e funcional. Ele envia requisições de teste para o destino configurado e espera por uma resposta esperada.

Se o recurso estiver indisponível (ex: servidor fora do ar, tempo de resposta muito alto ou status HTTP inesperado), o health check é marcado como Unhealthy (não íntegro), e o Route 53 pode agir com base nessa informação.

Como funciona internamente?​

  • O Route 53 distribui a checagem entre vários verificadores espalhados globalmente (de 3 a 8 dependendo da configuração).
  • Cada verificador realiza a mesma requisição e reporta o status.
  • O recurso só é considerado Unhealthy se o número mínimo de falhas (threshold) for atingido.
  • O Route 53 não para o roteamento, ele apenas deixa de retornar registros apontados para destinos com status Unhealthy, dependendo da política configurada.

Tipos de Health Checks​

1. Endpoint Health Check​

Esse é o tipo mais comum. O Route 53 realiza uma requisição diretamente para um:

  • IP público (ex: instância EC2, ALB, recurso externo).
  • Nome DNS público (com resolução obrigatória).
  • Endereço com caminho HTTP ou HTTPS (ex: /health, /status).
  • Porta TCP (ex: 22, 3306)

O que pode ser configurado:​

  • Protocolo: HTTP, HTTPS e TCP
  • IP/DNS do recurso
  • Porta
  • Caminho (para protocolos HTTP/HTTPS)
  • Intervalo de verificação (10s ou 30s)
  • Threshold (quantas falhas para considerar "unhealthy")
  • Timeout da resposta
  • Host header e string esperada (opcional para validações de conteúdo)

Exemplo:

http://app.exemplo.com/health
Porta: 80
Esperado: HTTP 200 OK

Se o endpoint responder com outro status ou demorar muito, ele será marcado como indisponível.s

2. Calculated Health Check​

Esse tipo não monitora um endpoint diretamente. Em vez disso, ele combina o resultado de outros health checks e determina sua integridade com base em uma regra de votação.

Use quando:​

  • Você quer criar uma checagem agregada de vários serviços.
  • Deseja que o tráfego seja considerado saudável apenas se 2 de 3 recursos estiverem no ar, por exemplo.

Exemplo:

Você tem 3 servidores:

  • hc-web
  • hc-db
  • hc-api

Você cria um Calculated Health Check chamado hc-app que só será saudável se pelo menos 2 desses 3 estiverem saudáveis.

3. Health Check baseado em CloudWatch Alarm​

Com esse tipo, você não precisa realizar testes diretos com o Route 53. Em vez disso, você vincula um alarme do CloudWatch que está monitorando métricas customizadas, como:

  • Uso de CPU
  • Erros de aplicação
  • Conexões em banco
  • Tempo de resposta de Lambda

Todos os health checks criados no Route 53 geram métricas automáticas no CloudWatch, como:

  • HealthCheckStatus
  • HealthCheckPercentageHealthy
  • TimeToFirstByte

Você pode criar alarmes, acionar notificações por SNS ou conectar com Lambda para ações automatizadas.

Use quando:​

  • Você quer usar métricas avançadas para definir disponibilidade.
  • O recurso não expõe um endpoint HTTP para health check tradicional.

Limitações​

  • Não funciona com IPs privados. Para ambientes internos, você deve usar:
    • CloudWatch Agent
    • AWS Route 53 Resolver + Endpoints
  • Health Check só verifica recursos com acesso público via internet.
  • Não é possível usar path HTTPS com certificados inválidos ou autoassinados (o Route 53 exige handshake completo).

Conclusão​

Health Checks no Route 53 são um componente essencial para criar soluções DNS resilientes, com failover automatizado, monitoramento e controle inteligente do tráfego. Eles ajudam a garantir que somente recursos disponíveis e saudáveis sejam usados, reduzindo indisponibilidades percebidas pelo usuário final.
