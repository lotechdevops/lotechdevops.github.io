Route 53 – Registros

No Amazon Route 53, os records (registros DNS) são os responsáveis por dizer como o tráfego será roteado para um domínio ou subdomínio.

O que cada record contém​

Cada registro criado no Route 53 é composto por:

  • Nome do domínio ou subdomínio

    • Ex: example.com ou www.example.com

  • Tipo de registro (Record Type)

    • Ex: A, AAAA, CNAME, MX, NS, TXT

  • Valor (Value)

    • Ex: Um endereço IP (12.34.56.78), outro domínio, ou um nome de recurso.

  • Política de Roteamento (Routing Policy)

    • Define como o Route 53 responderá às consultas.
    • Ex: simples, baseado em latência, failover, etc.

  • TTL (Time To Live)

    • Tempo em segundos que o registro pode ser armazenado em cache nos resolvers DNS.

Tipos de registros básicos​

  • A: Aponta um nome de domínio para um endereço IPv4.
  • AAAA: Aponta um nome de domínio para um endereço IPv6.
  • CNAME: Aponta um nome de domínio para outro nome de domínio (Não para IP).
  • NS: Define os Name Servers para a zona hospedada.

Observação: Não é possível criar um registro CNAME no topo da zona (Zona Apex).

Por exemplo: você não pode usar CNAME em example.com, mas pode em www.example.com.

Tipos de registros avançados​

  • TXT: Armazena informações de texto (SPF, validações de domínio, etc.)
  • MX: Define os servidores de e-mail do domínio.
  • SRV: Especifica serviços disponíveis em domínios.
  • CAA: Controle quais autoridades de certificação podem emitir certificados.
  • PTR: Usado em DNS reverso (IP -> domínio).
  • SOA: Contém informações sobre a zona DNS (usado em replicação DNS).
  • SPF: Verificação de remetentes de e-mails (hoje feito via TXT).
  • NAPTR, DS: Casos específicos, como DNSSEC e VoIP.

TTL (Time to Live)​

O TTL (Time to Live) é o tempo que um registro DNS pode ser armazenado em cache pelos resolvers (como o servidor DNS do seu provedor ou sistema operacional) antes de uma nova consulta ser feita ao Route 53.

Como funciona​

  1. O cliente (navegador ou app) faz uma requisição DNS para myapp.example.com.
  2. O Route 53 responde com o endereço IP (ex: 12.34.56.78) e o valor de TTL definido para aquele registro.
  3. Esse valor será armazenado em cache pelo tempo definido no TTL, evitando novas consultas durante esse período.

Comparando TTL alto vs baixo​

| Tipo de TTL             | Vantagens                               | Desvantagens                                        |
| ----------------------- | --------------------------------------- | --------------------------------------------------- |
| **Alto TTL** (ex: 24h)  | Menos tráfego no Route 53 (reduz custo) | Pode manter registros desatualizados por mais tempo |
| **Baixo TTL** (ex: 60s) | Mudanças propagam mais rápido           | Mais consultas = mais custo (\$)                    |

Boas práticas​

  • Use TTL alto para recursos estáticos e que não mudam com frequência.
  • Use TTL baixo para recursos que podem mudar (como IPs de servidores, failovers ou migrações).
  • Durante manutenções ou migrações de DNS, TTL baixo é essencial para facilitar a transição.

Observação:

Todos os registros DNS no Route 53 exigem TTL - exceto os registros Alias.

  • Registros Alias não exigem TTL manualmente, pois o Route 53 gerencia isso automaticamente com base no recurso AWS vinculado (como S3, ALB, CloudFront...).
