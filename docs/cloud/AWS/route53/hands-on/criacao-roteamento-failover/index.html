Criação do Roteamento por Failover

Objetivo​

Demonstrar como configurar o roteamento por failover, onde um registro primário (ativo) será utilizado por padrão e um secundário (de failover) assumirá o tráfego automaticamente se o primário falhar.

Pré-requisitos​

  1. Zona hospedada pública já criada no Route 53.
  2. Duas instâncias EC2 com IP públic:
    • Uma para ser o destino primário
    • Outra como instância de backup (failover)
  3. Health Checks já criados para cada instância.

Etapas de Configuração​

  1. Acesse o console do Amazon Route 53 em https://console.aws.amazon.com/route53/
  2. Vá até sua zona hospedada pública e clique em Criar registro
  3. Configure os campos:

Registro Principal​

  • Nome do registro: failover

    Isso criará o domínio: failover.devopsr66.com

  • Tipo de Registro: A
  • Valor IPv4: IP da instância primária
  • TTL: 15 segundos
  • Política de roteamento: Failover
  • Tipo de Failover: Principal
  • ID de verificação de integridade: Selecione a verificação de integridade criada para a instância primária
  • ID do registro: Digite um ID para identificação do registro
  • Clique em Adicionar outro registro

Registro Secundário (failover)​

  • Nome do registro: failover

    Isso criará o domínio: failover.devopsr66.com

  • Tipo de Registro: A
  • Valor IPv4: IP da instância secundária (failover)
  • TTL: 15 segundos
  • Política de roteamento: Failover
  • Tipo de Failover: Secundário
  • ID de verificação de integridade: Selecione a verificação de integridade criada para a instância secundária
  • ID do registro: Digite um ID para identificação do registro
  1. Clique em Criar registro

Testes​

Teste do funcionamento normal​

  1. Acesse a url http://failover.devopsr66.com/
  2. A página da instância primária deve ser exibida.

    Ex: "Função: Primária"

    Instância: " "

    Zona de Disponibilidade: us-east-1a

Teste de Failover​

  1. Deslique a instância primária no EC2.
  2. Aguarde cerca de 1 a 2 minutos (dependendo do TTL e intervalo do health check).
  3. Acesse novamente a url http://failover.devopsr66.com/
  4. A página da instância secundária (failover) deve ser exibida.

    Ex: "Função: Secundária"

    Instância: " "

    Zona de Disponibilidade: us-west-1b

Observações:

  • O health check é obrigatório apenas para o registro primário
  • O Route 53 considera o recurso inativo após 3 falhas consecutivas (padrão configurável).
  • Assim que o recurso volta ao estado íntegro, o tráfego volta a ser roteado pra ele automaticamente.
