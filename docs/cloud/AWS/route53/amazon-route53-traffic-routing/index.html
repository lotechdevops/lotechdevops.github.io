Como o tráfego é roteado

Entender como o DNS funciona é fundamental para aproveitar ao máximo o Route53. Todos os computadores conectados à Internet, desde o seu smartphone ou notebook até os servidores que oferecem conteúdo para grandes sites, se comunicam entre si usando números. Esses números, conhecidos como endereços IP, estão em um dos seguintes formatos:

  • Formato IPv4: Como 192.0.2.44
  • Formato IPv6: Como 2001:0db8:85a3:0000:0000:8a2e:0370:7334

Ao abrir o navegador e acessar um site, você não precisa lembrar e digitar uma string de caracteres longa como essa. Em vez disso, você pode digitar um nome de domínio como example.com e ainda chegar ao lugar certo. Um servilo de DNS, como o Amazon Route53, ajuda a fazer essa conexão entre nomes de domínio e endereços IP.

Configurando o Route53 para Rotear Tráfego​

Para configurar o Amazon Route53 para encaminhar o tráfego da Internet para seu domínio, siga estes passos:

1. Registro do Domínio: Registro o nome de domínio que você deseja que os usuários usem para acessar seu conteúdo.

2. Zona Hospedada Automática: Depois de registrar o seu nome de domínio, o Route53 cria automaticamente uma zona hospedada pública que tem o mesmo nome do domínio.

3. Criação de Registros DNS: Para rotear o tráfego para seus recursos, você cria registros (também conhecidos como conjutos de registros de recursos) em sua zona hospedada. Cada registro inclui:

  • Name (Nome): O nome do registro corresponde ao nome de domínio (example.com) ou subdomínio (www.example.com, retail.example.com) para o qual você deseja que o Route53 encaminhe o tráfego.

  • Type (Tipo): O tipo de registro geralmente determina o tipo de recurso para o qual você deseja que o tráfego seja roteado. Por exemplo, para rotear tráfego para um servidor de e-mail, especifique MX como o tipo. Para rotear o tráfego para um servidor web que tenha um endereço IPv4, você especifica A para tipo.

  • Value (Valor): O Valor é intimamente ligado ao tipo. Se você especifica o tipo como MX, especifica os nomes de um ou mais servidores de e-mail como Valor. Se você especificar A para tipo, você especifica um endereço IP no formato IPv4, como 192.0.2.44.

Processo completo de resolução DNS​

Depois de configurar o Amazon Route 53 para encaminhar o tráfego da Internet para seus recursos, como servidores Web ou buckets do Amazon S3, veja o que acontece em apenas alguns milissegundos quando alguém solicita conteúdo de www.example.com:

1. Consulta Inicial: O usuário abre o navegador da Web, digita www.example.com na barra de endereços e pressiona Enter.

2. Resolvedor de DNS: A solicitação de www.example.com é roteada para um resolvedor de DNS, que costuma ser gerenciado pelo provedor de serviço de Internet (ISP), como um provedor de Internet a cabo, um provedor de banda larga DSL ou uma rede corporativa.

3. Servidor Raiz DNS: O resolvedor de DNS do IPS encaminha a solicitação de example.com para um servidor de nome raiz DNS.

4. Servidor TLD: O resolvedor de DNS encaminha a solicitação de www.example.com novamente, desta vez para um dos servidores de nome TLD dos domínios .com. O servidor de nome dos domínios .com responde à solicitação com os nomes dos quatro servidores de nome do Route 53 associados ao domínio example.com

Cache de Servidores de Nome: O resolvedor DNS armazena em cache os quatro servidores de nome do Route 53. Na próxima vez que alguém acessar example.com, o resolvedor ignorará as etapas 3 e 4, pois ele já tem os servidores de nomes para example.com. Os servidores de nome são normalmente armazenados em cache por dois dias.

5. Consulta ao Route53: O resolvedor de DNS escolhe um servidor de nome do Route 53 e encaminha a solicitação de www.example.com para esse servidor de nome.

6. Resolução do Registro: O servidor de nome do Route 53 procura o registro wwww.example.com na zona hospedada example.com, obtém o valor associado, como o endereço IP de um servidor Web, 192.0.2.44, e retorna o endereço IP para o resolvedor do DNS.

7. Retorno do IP: O resolvedor de DNS finalmente tem o endereço IP de que o usuário precisa. O resolvedor retorna o valor para o navegador da web.

Nota sobre TTL (Time to Live): O resolvedor de DNS também armazena em cache o endereço IP de example.com por um período que você especificar. Assim, ele pode responder mais rapidamente na próxima vez que alguém acessar example.com.

8. Conexão final: O navegador da web envia uma solicitação de example.com para um endereço IP que ele obteve do resolvedor de DNS. É aqui que seu conteúdo está, por exemplo, em um servidor web em execução em uma instância EC2 da Amazon ou em um bucket do Amazon S3 configurado como um endpoint de site.

9. Entrega de conteúdo: O servidor web ou outro recurso em 192.0.2.44 retorna a página da web de www.example.com para o navegador da web e o navegador exibe a página.
