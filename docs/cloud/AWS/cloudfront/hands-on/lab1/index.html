Lab 01: Site Estático com S3 e CloudFront

Objetivo do Lab​

Neste laboratório você vai criar um site estático simples, hospedá-lo em um bucket S3 e distribuí-lo globalmente usando CloudFront. Ao final, você terá um site acessível via CloudFront com acesso direto ao S3 bloqueado.

O que você vai aprender:

  • Criar e configurar bucket S3
  • Upload de arquivos para S3
  • Criar distribuição CloudFront
  • Configurar Origin Access Control (OAC)
  • Bloquear acesso direto ao S3
  • Testar performance do CloudFront

Pré-requisitos​

  • Conta AWS ativa
  • Conhecimento básico de HTML/CSS (vamos criar arquivos simples)
  • Navegador web

Arquitetura Final​

Usuário → CloudFront (CDN Global) → Bucket S3 (Origem Privada)
          ✓ Cache global            ✓ Apenas CloudFront acessa
          ✓ Baixa latência          ✗ Acesso direto bloqueado

Passo 1: Criar o Bucket S3​

1.1 Acessar o Console S3​

Faça login no console AWS e procure o serviço S3.

1.2 Criar Novo Bucket​

Clique em Create bucket e configure:

General configuration:

  • Bucket type: General purpose
  • Bucket name: meu-site-cloudfront-lab

Object Ownership:

  • ACLs disabeled

Block Public Access settings:

  • Mantenha TODAS as 4 opções marcadas

Bucket Versioning:

  • Disable

Default encryption:

  • Server-side encryption with Amazon S3 managed keys (SSE-S3)
  • Bucket Key: Enable

Advanced settings:

  • Object Lock: Disable

Passo 2: Preparar Arquivos do Site​

2.1 Criar Arquivos Localmente​

Para este lab, vamos usar um site estático simples já preparado. Os arquivos estão disponíveis no GitHub.

Faça o download dos arquivos:

Acesse o repositório: GitHub e baixe os arquivos index.html e style.css.

Estrutura do projeto:

lab1/
├── index.html    # Página principal do site
└── style.css     # Estilos e animações

Passo 3: Upload dos Arquivos para o S3​

3.1 Fazer Upload​

No console S3, clique no bucket meu-site-cloudfront-lab-v1 que você criou.

  • Clique em Upload
  • Arraste os 2 arquivos (index.html e style.css) ou clique em Add files

Passo 4: Criar Distribuição CloudFront​

4.1 Acessar CloudFront​

No console AWS, navegue até o serviço CloudFront.

4.2 Escolher o Plano​

  • Clique em Create distribution.

  • Na tela "Choose a plan", selecione Free (plano gratuito)

  • Role a página para baixo e clique em Next

4.3 Configurar Distribution Options​

Distribution name:

  • Digite um nome para sua distribuição, por exemplo: meu-site-cloudfront-lab

Description (opcional):

  • Pode deixar vazio ou adicionar Lab prático de CloudFront com S3

Distribution type:

  • Selecione Single website or app (já vem selecionado por padrão)

Domain - Route 53 managed domain (opcional):

  • Deixe vazio por enquanto (vamos usar apenas o domínio padrão do CloudFront)

Role a página para baixo e clique em Next

4.4 Configurar Origin​

Origin type:

  • Selecione Amazon S3.

  • Após selecionar Amazon S3, a seção S3 Origin aparecerá logo abaixo.

S3 Origin:

  • Clique no campo de texto ou no botão Browse S3. Uma lista com seus buckets S3 aparecerá.

  • Selecione o bucket meu-site-cloudfront-lab-v1 que você criou anteriormente.

O campo será preenchido automaticamente com algo como: meu-site-cloudfront-lab-v1.s3.us-east-1.amazonaws.com

Origin path (opcional):

  • Deixe vazio (não precisamos de subdiretórios específico)

Settings

  • Role a página para baixo até a seção Settings

Allow private S3 bucket access to CloudFront:

  • Mantenha marcado "Allow private S3 bucket access to CloudFront - Recommended" (já vem selecionado por padrão)

Esta opção é fundamental - permite que o CloudFront atualize automaticamente a política do bucket S3 para permitir acesso apenas da distribuição CloudFront

Origin settings:

  • Mantenha Use recommended origin settings (já vem selecionado por padrão)

Cache settings:

  • Mantenha Use recommended cache settings tailored to serving S3 content (já vem selecionado por padrão)

  • Clique em Next no canto inferior direito da página, você será direcionado para a tela Enable security

4.5 Configurar Segurança (Enable Security)​

Web Application Firewall (WAF):

O WAF oferece proteções de segurança incluídas no plano gratuito sem custo adicional.

Proteções incluídas:

  • Proteção contra vulnerabilidades comuns em aplicações web.
  • Proteção contra atores maliciosos descobrindo vulnerabilidades da aplicação.
  • Bloqueio de endereços IP de ameaças potenciais baseado em inteligência de ameaças da Amazon.

Use monitor mode:

  • Deixe desmarcado (para este lab não precisamos do modo monitor)

O modo monitor apenas conta quantas requisições seriam bloqueadas, mas não bloqueia de fato. É útil para testar regras antes de ativar.

Protection against Layer 7 DDoS attacks:

Esta opção está desabilitada (disponível apenas no plano Business)

No plano free, você já tem proteção básica contra DDoS através do AWS Shield Standard, que é incluído automaticamente.

Mantenha as configurações padrão e clique em Next no canto inferior direito, você será direcionado para a tela Review and Create

4.6 Revisar e Criar (Review and Create)​

Esta tela mostra um resumo de todas as configurações que você fez nos passos anteriores.

General configuration:

  • Distribution name: meu-site-cloudfront-lab
  • Description: Lab prático de CloudFront com S3
  • Billing: Free ($0/month)
  • Today's pro-rated charge (estimate): $0

Origin: Observe o banner azul informativo:

"Because you granted CloudFront access to your origin, CloudFront can write and update S3 bucket policies that restrict access to your S3 origin to CloudFront".

Isso informa que o CloudFront irá atualizar automaticamente a política do bucket S3 para permitir acesso apenas da distribuição.

Configurações da origem:

  • S3 origin: meu-site-cloudfront-lab-v1.s3.us-east-1.amazonaws.com
  • Origin path: Vazio
  • Grant CloudFront access to origin: Yes
  • Enable Origin Shield: No
  • Connection attempts: 3
  • Connection timeout: 10

Cache settings:

"CloudFront will apply default cache settings tailored to serving content from a S3 origin. You can customize settings after you create your distribution."

O CloudFront aplicará automaticamente configurações de cache otimizadas para conteúdo S3.

Security:

  • Security protections: Enabled (WAF básico incluído)
  • Use monitor mode: No

Informação importante:

Na parte inferior da tela você verá a mensagem:

"Usage and transfer limits will be prorated for your first month."

Isso significa que os limites de uso serão proporcionais ao tempo restante do mês.

Se tudo estiver correto, clique no botão laranja "Create distribution" no canto inferior direito.

Após criar a distribuição, você será redirecionado para a página de detalhes.

Verifique as informações principais:

5.3 Copiar Distribution Domain Name​

Na seção Details, copie o Distribution domain name.

Esse será o domínio que você usará para acessar seu site:

https://d1tmnmb8swn594.cloudfront.net

(O seu domínio será diferente - cada distribuição tem um ID único)

Passo 6: Configurar Default Root Object​

6.1 Identificar o Problema​

Ao tentar acessar o site via CloudFront:

https://d1tmnmb8swn594.cloudfront.net

Você recebe erro Access Denied

Mesmo com a política do S3 já configurada automaticamente, o CloudFront não sabe qual arquivo servir quando você acessa apenas o domínio raiz (sem especificar /index.html).

6.2 Testar com Caminho Completo​

Antes de configurar o Default Root Object, teste acessando o arquivo diretamente:

https://d1tmnmb8swn594.cloudfront.net/index.html

Se funcionar com /index.html mas não sem, o problema é apenas a falta do Default Root Object.

Se continuar dando erro mesmo /index.html, aguarde 5-10 minutos, a distribuição pode ainda estar propagando globalmente.

6.3 Configurar Default Root Object​

No console do CloudFront, na página de detalhes da sua distribuição:

  • Vá na aba General.
  • Na seção Settings, verifique o campo Default root object
  • Se estiver vazio (mostrar -), você precisa configurá-lo.
  • Clique no botão Edit no campo superior direito.
  • Role até encontrar o campo Default root object.
  • Digite: index.html
  • Role até o final e clique em Save changes

6.4 Aguardar Atualização​

O status da distribuição mudará para Deploying

Essa atualização geralmente leva 2-5 minutos.

Aguarde até o status voltar para Enabled com data de modificação atualizada.

6.5 Testar Novamente​

Após o deploy concluir, acesse novamente:

https://d1tmnmb8swn594.cloudfront.net

Agora o site deve carregar completamente!

Passo 7: Verificar Performance e Cache​

7.1 Testar HTTPS​

Com o site carregado, clique no cadeado ao lado da URL no navegador.

Você verá que a conexão é segura com certificado SSL/TLS válido fornecido automaticamente pelo CloudFront.

  • Clique em A Conexão é Segura -> O Certificado é válido para ver mais detalhes.

7.2 Abrir DevTools​

  • Pressione F12 para abrir as ferramentas de desenvolvedor do navegador.
  • Vá na aba Network (Rede)

7.3 Analisar Headers do CloudFront​

  • Recarregue a página
  • Você verá todas as requisições sendo feitas
  • Clique no arquivo d1tmnmb8swn594.cloudfront.net na lista de requisições.
  • Vá na seção Headers e role até Response Headers
  • Procure pelos headers do CloudFront:
X-Cache: Hit from cloudfront
X-Amz-Cf-Pop: GRU3-P1
X-Amz-Cf-Id: [ID único da requisição]

Explicação dos headers:

  • X-Cache: Hit from cloudfront -> Arquivo foi servido do cache (rápido)
  • X-Amz-Cf-Pop: GRU3-P1 -> Mostra qual POP atendeu a requisição (ex: GRU3-P1 = Garulhos/São Paulo, GIG=Rio de Janeiro)
  • X-Amz-Cf-Id: ID único da requisição para troubleshooting com suporte AWS

Entendendo Cache Hit vs Cache Miss
  • x-cache: Miss from cloudfront → Primeira vez que este POP recebe requisição para este arquivo. CloudFront busca do S3 e armazena em cache.
  • x-cache: Hit from cloudfront → Arquivo já está em cache no POP. Entrega instantânea sem acessar o S3.

Como você já acessou o site anteriormente, verá "Hit from cloudfront". Isso é o comportamento ideal - mostra que o cache está funcionando!

7.4 Verificar Tempos de Carregamento​

Ainda na aba Network, observe a coluna Time

Com cache hit ativo, os tempos devem estar muito baixos:

  • index.html: ~10-40ms
  • style.css: ~10-40ms

Isso demonstra a excelente performance do CloudFront servindo conteúdo em cache próximo ao usuário.

Passo 8: Testar Bloqueio de Acesso Direto ao S3​

8.1 Tentar Acessar S3 Diretamente​

  • Abra uma nova aba no navegador e tente acessar o arquivo diretamente no S3:
https://meu-site-cloudfront-lab-v1.s3.us-east-1.amazonaws.com/index.html

(Substitua meu-site-cloudfront-lab-v1 pelo nome do seu bucket e us-east-1 pela sua região)

  • Você deve receber erro com mensagem XML:
<Error>
<Code>AccessDenied</Code>
<Message>Access Denied</Message>
<RequestId>7A5Z8WRWX997PFJ9</RequestId>
<HostId>zmVYRSPKi5UhDliagRGII7glkOpVy8GlNw3k+4cl/OA/OiSgkJ0rW3dN7l23j80lZDILVZcy1VGWotbXu012buWOo38rdwpHDyMO2v1rTBo=</HostId>
</Error>

Esse erro confirma que a configuração de segurança está funcionando perfeitamente.

Passo 9: Limpeza de Recursos​

Importante

Execute estes passos para evitar cobranças indesejadas na sua conta AWS. Mesmo no free tier, é importante limpar recursos não utilizados.

9.1 Desabilitar e Deletar Distribuição CloudFront​

No console do CloudFront, acesse a lista de distribuições.

  • Selecione a distribuição.
  • Clique em Disable.
  • Confirme clicando em Disable novamente.
  • Aguarde 5-15 minutos até o status mudar de "Enabled" para Disabled.

9.2 Cancelar Plano​

Se você criou a distribuição com o plano gratuito, precisa cancelar o plano antes de deletar

  • Na página de detalhes da distribuição, procure pela seção de Billing e clique em Manage plan.
  • Clique em Cancel plan.
  • Confirme o cancelamento.
Importante sobre Planos
  • Plano Free: Precisa cancelar e aguardar até o final do ciclo de cobrança mensal para deletar
  • Standard pricing: Pode deletar imediatamente após desabilitar

Após cancelar o plano Free, você precisará aguardar até o final do ciclo de cobrança mensal.

9.3 Deletar Distribuição (Após Fim do Ciclo)​

Após o fim do ciclo de cobrança ou se estava em standard pricing:

  • Selecione a distribuição (certifique-se que está "Disabled").
  • Clique em "Delete".
  • Confirme a exclusão.
Custos Durante Espera

Enquanto a distribuição estiver desabilitada (Disabled), ela NÃO gera custos. Você pode aguardar tranquilamente o fim do ciclo para deletar.

9.4 Deletar Bucket S3​

Pode Deletar Imediatamente

O bucket S3 pode ser deletado a qualquer momento, não precisa aguardar o CloudFront.

  • No console do S3, acesse a lista de buckets.
  • Selecione o bucket meu-site-cloudfront-lab-v1.
  • Clique em Empty.
  • Digite permanently delete para confirmar.
  • Clique em Empty
  • Aguarde até todos os objetos serem removidos.
  • Após esvaziar, selecione o bucket novamente.
  • Clique em Delete
  • Digite o nome do bucket para confirmar.
  • Clique em Delete bucket
