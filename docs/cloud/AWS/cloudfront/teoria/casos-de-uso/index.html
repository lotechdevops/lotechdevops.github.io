Casos de Uso do CloudFront

Acelerar Sites Estáticos​

O caso de uso mais comum e direto do CloudFront é distribuir sites estáticos globalmente. Sites estáticos são aqueles compostos principalmente de arquivos que não mudam frequentemente: HTML, CSS, JavaScript, Imagens, Fontes.

Arquitetura Típica​

Origem: Bucket Amazon S3 contendo todos os arquivos do site.

CloudFront: Distribuição apontando para o bucket S3 com Origin Access Control (OAC) configurado.

Resultado: Usuários acessam via CloudFront, que entrega conteúdo do POP mais próximo. Acesso direto ao S3 é bloqueado.

Benefícios​

Performance: Sites carregam em 10-50ms em vez de 200-500ms para usuários globais.

Custo: Transferência S3 → CloudFront é gratuita. Você paga apenas CloudFront → Usuários.

Segurança: S3 privado, acessível apenas via CloudFront. Adicione WAF para proteção extra.

Escalabilidade: CloudFront lida automaticamente com picos de tráfego sem você provisionar recursos.

Configuração Recomendada​

  • TTL longo para assets versionados (CSS, JS com hash no nome): 1 ano
  • TTL médio para imagens: 7-30 dias
  • TTL curto para HTML: 5-60 minutos
  • Comprimir arquivos texto (CSS, JS, HTML) automaticamente
  • Usar HTTPS com certificado do ACM

Exemplo Prático​

Um blog técnico hospedado em S3:

https://meu-blog.s3.amazonaws.com → Privado (acesso bloqueado)
https://d123abc.cloudfront.net → Público (domínio CloudFront)
https://blog.exemplo.com.br → Público (domínio personalizado)

Visitante do Brasil: POP São Paulo entrega em 15ms Visitante da Europa: POP Londres entrega em 18ms Visitante da Ásia: POP Tóquio entrega em 20ms

Streaming de Vídeo​

O CloudFront oferece recursos específicos para distribuição de vídeo, tanto sob demanda (VOD) quanto ao vivo.

Vídeo Sob Demanda (VOD)​

Arquitetura:

  • Vídeos armazenados no S3 (geralmente em múltiplas resoluções)
  • CloudFront distribui usando protocolos como HLS ou DASH
  • Player no navegador/app escolhe automaticamente a qualidade baseado na conexão

Configuração:

  • Armazene vídeos no S3 em formato de streaming (segmentos pequenos)
  • Configure CloudFront para cachear segmentos de vídeo
  • TTL longo (vídeos raramente mudam): 7-30 dias
  • Use Signed URLs/Cookies para conteúdo premium/privado

Benefício dos Caches Regionais:

  • Vídeos populares ficam nos POPs (acesso instantâneo).
  • Vídeos menos populares ficam nos caches regionais (ainda rápido, sem sobrecarregar origem)

Streaming ao Vivo​

Arquitetura:

  • AWS MediaLive codifica o stream ao vivo
  • AWS MediaPackage empacota em formatos HLS/DASH
  • CloudFront distribui globalmente
  • Usuários assistem com mínimo delay

Vantagens:

  • Cache de fragmentos de mídia reduz carga no MediaPackage
  • Distribuição global permite milhares de espectadores simultâneos
  • Latência baixa mesmo para eventos ao vivo

Formatos Suportados​

  • HLS (HTTP Live Streaming): Apple, funciona em iOS, Safari e maioria dos players
  • DASH (Dynamic Adaptive Streaming over HTTP): Padrão aberto, suporte amplo
  • CMAF (Common Media Application Format): Formato moderno, compatível com HLS e DASH
  • Microsoft Smooth Streaming: Para ambientes Microsoft

Distribuição de APIs​

Mesmo que APIs retornem conteúdo dinâmico, o CloudFront traz benefícios significativos

APIs com Cache​

Para endpoints que retornam dados relativamente estáveis:

Exemplo: API de listagem de produtos, categorias, informações públicas

Configuração:

  • TTL curto: 1-5 minutos
  • Cache baseado em query strings relevantes
  • Invalidar cache quando dados mudam

Benefício:

Durante o período de TTL, requisições são atendidas do cache (rápido, sem carga na origem). Ideal para dados que são lidos muito mais do que escritos.

APIs sem Cache (Otimização de Rede)​

Para endpoints que retornam dados únicos por usuário:

Exemplo: Dados de conta do usuário, carrinho de compras, informações personalizadas.

Configuração:

  • TTL = 0 (não cacheia)
  • CloudFront funciona como proxy otimizado

Benefícios mesmo sem cache:

  • Conexões persistentes com origem (reduz latência de TCP/TLS handshake)
  • Roteamento via rede backbone AWS (mais rápido e confiável que internet pública)
  • Compressão automática de respostas
  • Proteção DDoS incluída

Lambda@Edge para APIs​

Execute código nas edge locations para:

  • Validar tokens JWT sem chamar origem
  • Adicionar/remover headers
  • Redirecionar baseado em lógica customizada
  • Transformar requisições/respostas
  • A/B testing

Criptografia no Nível do Campo​

Para dados extremamente sensíveis que precisam de proteção adicional além de HTTPS.

Como Funciona​

Você especifica campos específicos (ex: número de cartão de crédito, CPF) que devem ser criptografados. O CloudFront criptografa esses campos usando sua chave pública antes de enviar para a origem. Apenas aplicações com a chave privada correspondente conseguem descriptografar.

Exemplo de Uso​

Formulário de pagamento:

  • Campos normais (nome, endereço) → HTTPS padrão
  • Número do cartão → Criptografia no nível do campo
  • CVV → Criptografia no nível do campo

Benefício:

Mesmo que alguém com acesso à origem ou logs consiga ver os dados, os campos sensíveis estão criptografados. Apenas o processador de pagamento (com chave privada) pode descriptografar.

Configuração​

  1. Gere par de chaves (pública/privada)
  2. Adicione chave pública ao CloudFront
  3. Especifique quais campos criptografar
  4. Configure origem para descriptografar com chave privada

Personalização na Borda​

CloudFront Functions e Lambda@Edge prermitem executar código próximo aos usuários finais.

CloudFront Functions​

Características:

  • JavaScript leve, execução em menos de 1ms
  • Muito barato (gratuito até 2 milhões de invocações/mês)
  • Casos de uso simples

Exemplos:

  • Manipular headers (adicionar security headers)
  • Redirecionar requisições (www -> não-www)
  • Reescrever URLs
  • Validações simples

Lambda@Edge​

Características:

  • Node.js ou Python
  • Execução mais longa (até 30 segundos)
  • Acesso a recursos externos (APIs, databases)
  • Mais caro que CloudFront Functions

Exemplos:

  • Autenticação/autorização customizada
  • Gerar respostas dinâmicas sem chamar origem
  • Transformações complexas de conteúdo
  • Personalização baseada em geolocalização
  • A/B testing avançado

Quando usar cada um​

CloudFront Functions: Operações simples e rápidas, alto volume, custo mínimo.

Lambda@Edge: Lógica complexa, acesso a recursos externos, transformações pesadas.

Conteúdo Privado​

Restringir acesso ao seu conteúdo usando URLs ou cookies assinados.

URLs Assinadas​

Você gera URLs temporárias com assinatura digital. Apenas quem tem a URL válida consegue acessar.

Exemplo:

https://d123.cloudfront.net/video.mp4?Expires=1234567890&Signature=abc123...

Configuração:

  • Crie par de chaves (CloudFront key pair)
  • Configure CloudFront para exigir URLs assinadas
  • Sua aplicação gera URLs assinadas quando usuário autorizado solicita

Casos de uso:

  • Conteúdo premium (cusros pagos, vídeos exclusivos)
  • Downloads restritos
  • Compartilhamento temporário

Cookies Assinados​

Similar a URLs assinadas, mas usa cookies em vez de parâmetros na URL.

Vantagem: Melhor para múltiplos arquivos. Um cookie dá acesso a vários recursos.

Exemplo de uso: Plataforma de cursos onde aluno autenticado recebe cookie que permite acessar todos os vídeos do curso.

Origin Access Control (OAC)​

Para origens S3, configure OAC para garantir que apenas CloudFront possar acessar o bucket.

Configuração:

  1. Crie OAC na distribuição CloudFront
  2. Atualize bucket policy do S3 para permitir apenas o OAC
  3. Remova permissões públicas do bucket

Resultado: Impossível acessar https://bucket.s3.amazonaws.com/arquivo.jpg diretamente. Apenas https://cloudfront.net/arquivo.jpg funciona.

Combinando Proteções​

Para máxima segurança:

  • OAC no S3 (bloqueia acesso direto)
  • Signed URLs/Cookies (controle quem acessa via CloudFront)
  • WAF (protege contra ataques web)
  • Geo-restriction (bloqueia países específicos se necessário)
Escolhendo o Caso de Uso

Sites estáticos e vídeo VOD são os casos mais simples para começar. APIs e personalização na borda são mais avançados mas trazem benefícios significativos quando bem implementados.
