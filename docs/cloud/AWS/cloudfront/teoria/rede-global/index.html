Rede Global do CloudFront

Infraestrutura Global​

O CloudFront opera uma das maiores redes de distribuição de conteúdo do mundo, com mais de 600 pontos de presença (POPs) distribuídos em dezenas de países e todos os continentes habitados. Essa presença global massiva é o que permite ao CloudFront entregar conteúdo com baixa latência para usuários em qualquer lugar do mundo.

A rede inclui dois tipos de infraestrutura: edge locations (POPs) e Regional Edge Caches. Ambos trabalham juntos para criar uma hierarquia de cache que otimiza performance e reduz custos.

Distribuição Geográfica​

Os pontos de presença do CloudFront estão estrategicamente posicionados nas principais áreas metropolitanas do mundo:

Américas: São Paulo, Rio de Janeiro, Bogotá, Buenos Aires, Santiago, Miami, Nova York, Los Angeles, Dallas, Toronto, entre outras.

Europa: Londres, Paris, Frankfurt, Amsterdam, Madrid, Estocolmo, Varsóvia, Milão, entre outras.

Ásia-Pacífico: Tóquio, Seul, Singapura, Hong Kong, Mumbai, Sydney, Melbourne, entre outras.

Oriente Médio e África: Dubai, Tal Aviv, Johannesburgo, Cidado do Cabo, entre outras.

Para ver a lista completa e sempre atualizada dos locais, consulte a página oficial da rede de borda global da AWS.

Classes de Preços e Seleção de Locais​

O CloudFront oferece diferentes classes de preço que controlam quais edge locations são usadas:

Price Class All: Usa todos os 400+ POPs globalmente. Melhor performance global, mas custa mais alto em regiões caras como Oceania.

Price Class 200: Exclui as regiões mais caras (algumas partes da América do Sul, Oceania e partes da Ásia). Bom equilíbrio entre performance e custo para a maioria dos casos.

Price Class 100: Usa apenas América do Norte e Europa. Menor custo, mas performance reduzida para usuários em outras regiões.

A escolha depende do seu público-alvo e orçamento. Se seus usuários estão principalmente na América do Norte e Europa, Price Class 100 pode ser suficiente. Para audiência global, use Price Class All.

Intervalos de Endereços IP​

O CloudFront usa intervalos específicos de endereços IP para seus servidores. Conhecer esses intervalos é importante para configurar firewalls, security groups e outras regras de rede.

A AWS publica todos os intervalos de IP em formato JSON que é atualizado automaticamente. Você pode baixar o arquivo em https://ip-ranges.amazonaws.com/ip-ranges.json

Para filtrar apenas IPs do CloudFront, procure por:

"service": "CLOUDFRONT",
"region": "GLOBAL"

Alternativamente, existe uma ferramenta que mostra apenas IPs do CloudFront: https://d7uri8nf7uskq.cloudfront.net/tools/list-cloudfront-ips

Listas de Prefixos Gerenciados​

A AWS oferece listas de prefixos gerenciados especificamente para o CloudFront. Essas listas contêm os intervalos de IP de todos os servidores voltados para a origem do CloudFront e são atualizados automaticamente pela AWS.

Existem duas listas:

  • com.amazonaws.global.cloudfront.origin-facing (IPv4)
  • com.amazonaws.global.ipv6.cloudfront.origin-facing (IPv6)

Por que usar?​

As listas de prefixos gerenciados são extremamente úteis para proteger suas origens. Se sua origem está na AWS (EC2, ALB, etc) e protegida por security groups, você pode configurar o security group para aceitar tráfego apenas dos IPs do CloudFront.

Exemplo de configuração:

Security Group da Origem:
- Permitir HTTPS (443) de: com.amazonaws.global.cloudfront.origin-facing
- Bloquear todo o resto

Isso garante que usuários não possam acessar sua origem diretamente, todo tráfego é forçado a passar pelo CloudFront, onde você tem controle sobre cache, WAF, e outras proteções.

Benefícios​

Segurança: Origem só aceita tráfego do CloudFront, impossível acessar diretamente.

Manutenção Zero: A AWS atualiza automaticamente a lista quando adiciona novos IPs. Você não precisa fazer nada.

Simplicidade: Uma única referência em vez de gerenciar centenas de ranges de IP manualmente.

Proteção DDoS: Ataques diretos à origem são bloqueados no security group.

Limitação Importante​

A lista de prefixos gerenciados do CloudFront tem um "peso" especial nas cotas da VPC. Consulte a documentação sobre pesos de listas gerenciadas para entender o impacto nas suas cotas.

Protegendo Origens fora da AWS​

Se sua origem não está na AWS (servidor on-premises ou em outro cloud), você não pode usar listas de prefixos gerenciados. Nesse caso, use outras estratégias:

Cabeçalhos Personalizados: Configure o CloudFront para adicionar um cabeçalho secreto em todas as requisições à origem. Configure a origem para aceitar apenas requisições com esse cabeçalho. Exemplo:

CloudFront adiciona: X-Custom-Secret: valor-secreto-aqui
Origem verifica se esse header existe e é válido

Firewall IP: Configure o firewall da origem para aceitar apenas IPs do CloudFront (usando o arquivo ip-ranges.json). Desvantagem: precisa atualizar manualmente quando AWS adiciona novos IPs.

VPN ou Direct Connect: Se sua origem on-premises precisa de conectar à AWS, use VPN ou Direct Connect para criar um túnel seguro.

Roteamento Inteligente​

O CloudFront não apenas roteia para o POP geograficamente mais próximo. O sistema de roteamento considera múltiplos fatores:

Latência de Rede: Medida em tempo real entre usuário e cada POP potencial.

Carga do Servidor: POPs sobrecarregados podem redirecionar tráfego para POPs próximos com mais capacidade.

Saúde do POP: Se um POP está com problemas, tráfego é automaticamente redirecionado.

Padrões de Tráfego: O sistema aprende e otimiza baseado em padrões históricos.

Isso significa que ocasionalmente um usuário pode ser direcionado para um POP que não é o geograficamente mais próximo, mas que oferece melhor performance no momento.

Failover e Alta Disponibilidade​

A arquitetura distribuída do CloudFront oferece alta disponibilidade natural:

Redundância Geográfica: Conteúdo replicado em centenas de locais. Se um POP falha, outros assumem automaticamente.

Failover Automático: Se o CloudFront detecta problemas em um POP, redireciona tráfego sem intervenção manual.

Origin Failover: Você pode configurar uma origem secundária. Se a primária falhar, CloudFront automaticamente tenta a secundária.

Multi-Region Origins: Combine múltiplas origens em diferentes regiões AWS para máxima resiliência.

Monitorando a Rede Global​

O CloudWatch oferece métricas específicas sobre distribuição geográfica do tráfego:

Requests by Location: Veja de quais países/regiões vêm suas requisições.

Data Transfer by Location: Entenda onde está consumindo mais banda.

Cache Hit Rate by POP: Identifique POPs com baixa taxa de cache hit.

Essas métricas ajudam a otimizar configurações e entender seu público global.

Proteção de Origem

Sempre configure sua origem para aceitar apenas tráfego do CloudFront. Para origens AWS, use listas de prefixos gerenciados. Para origens externas, use cabeçalhos personalizados secretos. Isso previne bypass do CloudFront e ataques diretos.
