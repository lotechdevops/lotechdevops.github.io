Configuração de Cache

Taxa de Acertos de Cache (Cache Hit Ratio)​

A taxa de acertos de cache é a métrica mais importante para avaliar performance e custos do CloudFront. Representa a porcentagem de requisições atendidas diretamente do cache sem ir à origem.

Exemplo:

  • 1000 requisições recebidas
  • 850 atendidas do cache
  • 150 foram à origem
  • Taxa de acertos = 85%

Metas recomendadas:

  • Acima de 85%: Excelente
  • 70-80%: Bom
  • 50-70%: Precisa otimização
  • Abaixo de 50%: Configuração problemática

Impacto:

Uma taxa de 90% significa que apenas 10% das requisições chegam à origem. Com 100.000 requisições/dia, sua origem recebe apenas 10.000 - você pode usar servidores 90% menores.

Cache Behaviors (Comportamentos de Cache)​

Cache behaviors permitem aplicar configurações diferentes para paths diferentes da sua distribuição. É como ter múltiplas "regras" de cache em uma única distribuição.

Estrutura de Behaviors​

Cada behavior define:

  • Path Pattern: Qual caminho ele afeta (ex: /imagens/*, /api/*, *.jpg)
  • Origem: De onde buscar conteúdo (pode ter múltiplas origens)
  • TTLs: Mínimo, padrão e máximo
  • Query Strings: Quais incluir no cache
  • Headers: Quais encaminhar à origem
  • Cookies: Como lidar com cookies

Ordem de Avaliação​

CloudFront avalia beahviors de cima para baixo, usando o primeiro que corresponde.

Exemplo:

1. Path: /api/*          → TTL: 0 segundos
2. Path: /imagens/*.jpg  → TTL: 30 dias
3. Path: /imagens/*      → TTL: 7 dias
4. Default (*)           → TTL: 24 horas

Requisição para /api/produtos → Usa behavior #1 Requisição para /imagens/logo.jpg → Usa behavior #2 Requisição para /imagens/icon.png → Usa behavior #3 Requisição para /sobre.html → Usa default

Casos de Uso Práticos​

Site com API e conteúdo estático:

/api/*          → TTL: 0s (sempre dinâmico)
/static/*       → TTL: 1 ano (versionado, nunca muda)
/*.css          → TTL: 1 dia
/*.js           → TTL: 1 dia
/*.jpg,*.png    → TTL: 7 dias
Default         → TTL: 1 hora

E-commerce:

/produtos/imagens/*  → TTL: 30 dias, origin: S3 de imagens
/api/carrinho/*      → TTL: 0s, origin: Application Load Balancer
/api/catalogo/*      → TTL: 5 minutos, origin: ALB
Default              → TTL: 1 hora, origin: S3 principal

Parâmetros de Query String​

Query Strings são os parâmetros após ? na URL: /produto?id=123&cor=azul

Estratégias de Cache​

Ignorar todos (None):

/produto?id=123&cor=azul
/produto?id=123&cor=vermelho

Ambos retornam o MESMO objeto do cache. Use quando query strings não afetam o conteúdo.

Incluir todos (ALL):

/produto?id=123&cor=azul    → Cache separado
/produto?id=123&cor=vermelho → Cache separado
/produto?cor=azul&id=123     → Cache separado (ordem diferente!)

Cada combinação única gera entrada de cache diferente. Use quando todos os parâmetros afetam o conteúdo.

Lista específica (Whitelist):

Whitelist: id, categoria

/produto?id=123&categoria=eletronicos&utm_source=google
/produto?id=123&categoria=eletronicos&utm_campaign=promo

Ambos usam MESMO cache (utm_* ignorados). Apenas ide categoria contam para cache.

Boas Práticas​

Para conteúdo estático (imagens, CSS, JS): Ignore todos os parâmetros. Query strings são geralmente para analytics/tracking.

Para APIs de listagem: Use whitelist incluindo apenas parâmetros que afetam a resposta (page, limit, filter), ignorando tracking (utm_*, ref).

Para conteúdo personalizado: Configure TTL=0 ou inclua todos se cada combinação realmente retorna conteúdo diferente.

Cache Baseado em Cookies​

Cookies podem afetar drasticamente a taxa de cache hit se mal configurados.

Estratégias​

Ignorar todos (None): CloudFront não considera cookies para cache. Todos usuários recebem o mesmo conteúdo em cache.

Incluir todos (All): Cada combinação única de cookies gera cache separado. Use apenas se conteúdo é realmente único por usuário.

Lista específica (Whitelist): Apenas cookies especificados afetam o cache.

Exemplo Problemático​

Configuração: Incluir todos os cookies
Cookies comuns: session_id, user_id, analytics_id, _ga, _gid, etc.

Resultado: Cada usuário tem cookies únicos
         → Cada usuário gera cache separado
         → Taxa de cache hit próxima de 0%
         → Todas requisições vão à origem!

Solução​

Whitelist apenas cookies que realmente afetam conteúdo:
- user_type (para mostrar preços diferentes B2B/B2C)
- region (para conteúdo regionalizado)

Ignorar cookies de tracking/analytics:
- _ga, _gid, session_id, etc.

Conteúdo Público vs Privado​

Conteúdo público (homepage, catálogo): Ignore todos os cookies. Todo mundo vê a mesma coisa.

Conteúdo semi-privado (preços por região): Whitelist apenas cookies relevantes (region, user_tier).

Conteúdo privado (dashboard do usuário): TTL=0 ou incluir cookie de sessão (cada usuário vê seus dados).

Cache Baseado em Headers​

Headers HTTP podem afetar tanto o cache quanto o comportamento da requisição.

Headers Comuns​

Accept-Encoding: Sempre encaminhe para origem. Permite origem decidir se comprime resposta (gzip, brotli).

Autorization: Se presente, considere configurar TTL=0. Requisições autenticadas geralmente retornam dados únicos.

CloudFront-Viewer-Country: Header especial que o CloudFront adiciona com o país do visitante. Use para cache baseado em geolocalização.

User-Agent: Cuidado! Existem milhares de user-agents diferentes. Incluir no cache pode pulverizar completamente sua taxa de cache hit.

Cache por Devide Type​

Em vez de cachear por User-Agent completo (ruim), use a funcionalidade de CloudFront de detectar device:

CloudFront-Is-Desktop-Viewer: true/false
CloudFront-Is-Mobile-Viewer: true/false
CloudFront-Is-Tablet-Viewer: true/false

Configure behavior para encaminhar esses headers. Resultado: máximo 3 versões em cache (desktop, mobile, tablet) em vez de milhares.

Estratégias de Versionamento​

Em vez de invalidar cache frequentemente (custa dinheiro e tempo), use versionamento.

Versionamento por Nome de Arquivo​

Antes:
/static/estilo.css → Muda conteúdo, precisa invalidar

Depois:
/static/estilo-v1.css
/static/estilo-v2.css
/static/estilo-v3.css

Cada versão é um arquivo diferente. Atualizou? Muda a versão no HTML. Nunca precisa invalidar.

Versionamenot por Hash​

Build gera hash do conteúdo:
/static/estilo.a3f2b1c.css
/static/app.8d4e9f2.js

Ferramentas como Webpack fazem isso automaticamente. Conteúdo diferente = hash diferente = URL diferente = sem problemas de cache.

Versionamento por Query String​

/static/estilo.css?v=1
/static/estilo.css?v=2

Funciona, mas menos elegante. Configure behavior para incluir query string v no cache.

Origin Shield​

Origin Shield é uma camada adicional de cache centralizado que fica entre caches regionais e sua origem.

Como Funciona​

Sem Origin Shield:
Cache Regional 1 → Origem
Cache Regional 2 → Origem
Cache Regional 3 → Origem
(3 requisições à origem)

Com Origin Shield:
Cache Regional 1 → Origin Shield → Origem (só 1 requisição)
Cache Regional 2 → Origin Shield ↗
Cache Regional 3 → Origin Shield ↗

Quando Usar​

Use se:

  • Origem tem capacidade limitada ou é cara para escalar
  • Conteúdo muda frequentemente (muitas requisições à origem)
  • Você quer consolidar requisições de múltiplas regiões

Não use se:

  • Origem já é super escalável (ex: S3)
  • Taxa de cache hit já está acima de 90%
  • Quer economizar (Origin Shield tem custo adicional)

Configuração​

Ative Origin Shield e escolha uma região AWS próxima da sua origem: Exemplo:

  • Origem em us-east-1 → Origem Shield em us-east-1
  • Origem em sa-east-1 → Origem Shield em sa-east-1

Políticas de Cache Gerenciadas​

A AWS oferece políticas de cache pré-configuradas para casos comuns:

CachingOptimized: TTL longo, ignora query strings e headers desnecessários. Para conteúdo estático.

CachingDisabled: TTL=0, encaminha tudo à origem. Para conteúdo completamente dinâmico.

Elemental-MediaPackage: Otimizada para streaming de vídeo via MediaPackage.

Amplify: Otimizada para aplicações Amplify (framework da AWS).

Você pode usar essas prontas ou criar políticas customizadas baseadas nelas.

Otimização Contínua

Monitore a taxa de cache hit semanalmente. Se cair abaixo de 80%, investigue: pode ser mudança no tráfego, novo tipo de conteúdo, ou configuração que precisa ajuste.
