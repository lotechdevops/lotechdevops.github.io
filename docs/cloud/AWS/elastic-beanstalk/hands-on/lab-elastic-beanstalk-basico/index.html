Deploy Básico no Elastic Beanstalk

Objetivo​

O objetivo deste laboratório é realizar o deploy de uma aplicação simples no Amazon Elastic Beanstalk utilizando as opções padrão do console AWS.
Esse passo a passo mostra como iniciar rapidamente um ambiente sem a necessidade de ajustes avançados, ideal para entender o fluxo básico do serviço.

Etapas de Configuração​

Etapa 1 - Configurações do Ambiente​

  1. Abra o console do Amazon Elastic Beanstalk em https://console.aws.amazon.com/elasticbeanstalk/

  2. Clique em Criar aplicação

  3. Na etapa Configurar ambiente, selecione:

    • Ambiente de servidor Web -> Usado para sites, APIs ou aplicações web acessíveis via HTTP.

  4. Em Informações da aplicação, informe o nome da aplicação

  5. Em Informações do ambiente, preencha:

    • Nome do Ambiente -> Esse nome será utilizado para identificar e acessar a aplicação.

  6. Em Código da aplicação:

    • Aplicação de amostra -> cria um ambiente básico com o código de exemplo da AWS.
    • Fazer upload do seu código -> permite enviar seu próprio pacote .zip. Nesse caso será necessário informar:
    • Rótulo da versão -> identificador da versão do código.
    • Arquivo local ou Amazon S3 -> origem do código a ser implantado.

  7. Em Predefinições, escolha como o ambiente será privisionado.

    • Instância única (qualificada para o nível gratuito) -> Cria apenas uma instância EC2.
    • Instância única (spot) -> Semelhante à anterior, mas utilizando instâncias Spot, o que pode reduzir custos, porém sem garantia de disponibilidade constante.
    • Alta disponibilidade -> Cria múltiplas instâncias EC2 atrás de um balanceador de carga, garantindo tolerância a falhas.
    • Alta disponibilidade (uso de instâncias Spot e sob demanda) -> Mistura instâncias Spot e On-Demand para equilibrar custo e disponibilidade.
    • Configuração personalizada -> Permite ajustar manualmente parâmetros como rede, segurança, escalabilidade e banco de dados.

    Para este laboratório básico, selecione Instância única (qualificada para o nível gratuito). Essa é a forma mais simples e econômica para subir uma aplicação inicial.

  8. Clique em Próximo para seguir para a etapa 2.

Etapa 2 - Configuração de acesso ao serviço​

Nesta etapa, é necessário configurar os perfis do IAM que o Elastic Beanstalk utilizará para gerenciar os recursos do ambiente.

2.1 - Perfil de serviço (Obrigatório): Ao clicar em Criar perfil, a tela de criação da Role do IAM é exibida. Nela você deve selecionar o serviço que usuará essa Role e o caso de uso específico.

  • Elastic Beanstalk - Compute -> Esse caso de uso é voltado para o perfil de instância EC2. Ele concede permissões para que as instâncias criadas no ambiente possam executar ações necessárias para a aplicação, como acessar o Amazon S3 ou enviar métricas para o CloudWatch.

  • Elastic Beanstalk - Environment -> Esse caso de uso é o correto para o Perfil de serviço, pois permite que o Elastic Beanstalk tenha acesso a outros recursos da AWS necessários para criar e gerenciar ambientes.

  • Para o Perfil de serviço, selecione Elastic Beanstalk - Environment e continue a criação da Role.

  • Geralmente, ao final da criação, o console gere automaticamente uma Role chamada aws-elasticbeanstalk-service-role, que será utilizada para esse propósito.

2.2 - Perfil da Instância EC2 (Obrigatório): Ao clicar em Criar perfil, a tela de criação da Role do IAM é exibida com as mesmas opções de caso de uso vistas no Perfil de serviço.

A diferença está na escolha correta do caso de uso: Elastic Beanstalk - Compute

  • Ela concede permissões para que as instâncias do ambiente consigam executar ações necessárias, como:
    • Enviar logs e métricas para o Amazon CloudWatch.
    • Acessar arquivos armazenados no Amazon S3.
    • Interagir com outros serviços de suporte dentro da AWS.

  • Para o Perfil da instância EC2, selecione Elastic Beanstalk - Compute e continue a criação da Role.

  • Normalmente, o console cria uma Role com o nome aws-elasticbeanstalk-ec2-role, que será associada automaticamente às instâncias EC2 do ambiente.

2.3 - Par de chaves EC2 (opcional):

  • Selecione um par de chaves existente ou crie um novo caso queira acessar as instâncias via SSH.
  • Essa configuração é opcional: se não precisar de acesso remoto às instâncias, pode deixar em branco.

Etapa 3 - Definir redes, banco de dados e etiquetas​

Nesta etapa, você pode configurar como o ambiente do Elastic Beanstalk será provisionado em termos de rede, banco de dados e organização com etiquetas.

3.1 - Configurações de instâncias:

  • VPC -> Você pode escolher entre a VPC padrão ou uma VPC personalizada criada por você.

  • Endereço IP público -> Marque essa opção apenas se quiser que as instâncias EC2 recebam IP público diretamente.

  • Sub-redes -> Selecione ao menos uma sub-rede.

3.2 - Banco de dados:

  • Essa opção permite integrar um RDS ao ambiente, criando um banco de dados gerenciado junto à aplicação.

Atenção: Se você habilitar o banco de dados, lembre-se que o RDS não é excluído automaticamente quando o ambiente do Beanstalk for encerrado. É necessário removê-lo manualmente para evitar custos extras.

3.3 - Etiquetas (tags):

  • As tags permitem identificar, organizar e gerenciar seus recursos dentro da AWS.
  • Cada tag é formada por um par chave/valor (exemplo: **`Projeto = EB-lab1)
  • O uso de tags é opcional

Etapa 4 - Configurar o tráfego e a escalabilidade da instância (Opcional)​

Nesta etapa, o Elastic Beanstalk permite ajustar configurações avançadas como relacionadas às instâncias EC2 e ao Auto Scaling do ambiente. Embora seja opcional, é importante entender o que cada seção representa:

4.1 - Instâncias:

  • Volume raiz (dispositivo de inicialização) -> define o tipo, tamanho e performance do volume EBS associado às instâncias.

  • Monitoramento do Amazon CloudWatch -> define o intervalo de coleta de métricas. Pode ser de 5 minutos (padrão) ou 1 minuto (para maior granularidade).

  • Serviço de metadados da instância (IMDS) -> por padrão, o Beanstalk habilita apenas o IMDSv2 por questões de segurança.

  • Grupos de segurança do EC2 -> escolhe os Security Groups que irão controlar o tráfego de rede das instâncias.

4.2 - Capacidade (Auto Scaling):

  • Tipo de ambiente -> pode ser instância única (para labs e testes) ou Balanceamento de carga (para produção, garantindo alta disponibilidade).

  • Composição da frota -> escolhe entre instâncias sob demanda ou instâncias Spot

  • Arquitetura -> selecione entre x86_64 (mais compatível) ou arm64 (mais barato, mas exige compatibilidade de software)

  • Tipos de instâncias -> escolha os tipos de instâncias que poderão ser usados no ambiente. É possível listar mais de um tipo (ex: t3.micro, t3.small), o que dá flexibilidade no provisionamento.

  • ID da AMI -> por padrão, o Elastic Beanstalk seleciona automaticamente a AMI mais adequada com base na plataforma, arquitetura e região.

Para o laboratório básico, não é necessário alterar essas opções. Mantenha os valores padrão e avance para a próxima etapa.

Etapa 5 - Configurar atualizações, monitoramento e registros em log (opcional)​

Nesta etapa, você pode ajustar opções mais avançadas do ambiente, relecionadas a monitoramento, atualizações, notificações, estratégias de deploy e logs.

5.1 - Monitoramento:

  • Relatórios de integridade -> escolha entre:

    • Básico: fornece informações limitadas sobre o estado do ambiente.

    • Aprimorado: fornece relatórios mais detalhados, incluindo métricas de instâncias e ambiente, como:

      • Métricas personalizadas do CloudWatch -> permite escolher métricas específicas para monitoramento.

  • Streaming de logs para o CloudWatch Logs -> envia eventos de integridade e registros para o CloudWatch Logs.

5.2 - Atualizações gerenciadas da plataforma:

  • Ativar atualizações automáticas -> permite que o Elastic Beanstalk aplique atualizações de plataforma automaticamente durante uma janela de manutenção semanal.

  • Janela de atualização -> dia e horário em que as atualizações serão aplicadas.

  • Nível da atualização -> escolha se serão aplicadas apenas correções e patchs ou também atualizações secundárias.

  • Substituição de instâncias -> opção para recriar instâncias se não houver atualização disponível.

5.3 - Notificações por e-mail

  • Permite inserir um endereço de e-mail para receber notificações sobre eventos importantes do ambiente (ex: falhas, atualizações, alterações de estado).

5.4 - Atualizações e implantações contínuas

  • Políticas de implantação -> define como a aplicação será atualizada:

    • Todas de uma vez -> mais rápido, mas pode causar indisponibilidade.

    • Rolling / Rolling with Additional Batch / Immutable -> estratégias mais seguras.

  • Atualizações de configuração -> define se alterações na configuração serão aplicadas continuamente sem downtime.

  • Preferências de implantação -> ajustar verificações de integridade, limites e tempo de execução de comandos durante deploys.

5.5 - Software de plataforma

  • Servidor de proxy -> escolhe entre Nginx ou Apache (dependendo da plataforma usada).

  • Amazon X-Ray -> habilite se quiser rastrear requisições e identificar gargalos de desempenho.

  • Armazenamento de logs no S3 -> permite armazenar logs do ambiente em um bucket do Amazon S3.

  • Streaming de logs para CloudWatch -> envia logs das instâncias diretamente para o CloudWatch Logs.

  • Propriedade do ambiente -> configure variáveis de ambiente (ex: PYTJONPATH, DATABASE_URL) que serão utilizadas pela aplicação.

Para este laboratório básico, você pode manter todas essas configurações no padrão e prosseguir para a revisão e criação do ambiente.

Etapa 6 - Revisão e Criação​

Depois de configurar as etapas anteriores, o Elastic Beanstalk exibirá um resumo com todas as opções selecionadas para a aplicação e o ambiente.

6.1 - Revise as informações exibidas:

  • Nome da aplicação e nome do ambiente
  • Plataforma escolhida
  • Código da aplicação (aplicação de amostra ou código enviado)
  • Configuração de rede (VPC e sub-rede selecionada)
  • Perfis do IAM criados (perfil de serviço e perfil da instância EC2)
  • Predefinição escolhida (ex: Instância única)
  • Outras informações opcionais mantidas como padrão.

6.2 - Se tudo estiver correto, clique em Criar

Esse processo pode levar alguns minutos, pois o Beanstalk irá:

  • Provisionar automaticamente os recursos de infraestrutura.
  • Configurar monitoramento com CloudWatch
  • Subir a aplicação no ambiente criado.

6.3 - Ao final, será exibida uma URL pública no formato

http://<nome-do-ambiente>.<regiao>.elasticbeanstalk.com

6.4 - Clique na URL para validar que a aplicação está funcionando

  • Caso tenha usado a opção Aplicação de amostra, a página exibirá o exemplo padrão do Elastic Beanstalk.
  • Caso tenha feito upload do seu código, a aplicação definida será carregada.
