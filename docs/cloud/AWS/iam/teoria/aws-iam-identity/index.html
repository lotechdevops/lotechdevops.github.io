Identidades no IAM

Conceito Geral de Identidades​

No contexto do IAM, uma identidade é qualquer elemento que possa receber permissões para acessar recursos da AWS. As identidades podem ser associadas a uma ou mais políticas que definem:

  • Quais ações podem ser realizadas
  • Em quais recursos
  • Sob quais condições

As identidades incluem:

  • Usuários do IAM
  • Grupos do IAM
  • Perfis do IAM (IAM Roles)

Diferença entre Identidade e Entidade​

Embora os termos pareçam semelhantes, é importante entender suas diferenças:

  • Identidade IAM: É um objeto que pode representar uma pessoa ou aplicação e pode conter permissões. Inclui usuários, grupos e perfis.
  • Entidade IAM: É uma identidade autenticável, ou seja, que pode fazer login ou executar chamadas de API diretamente. Inclui apenas usuários e perfis.

Resumo:​

TipoPode ser autenticado?Exemplo
Usuário IAM✅ SimPessoa com login próprio
Grupo IAM❌ NãoColeção de usuários IAM
Perfil IAM (Role)✅ Sim (assumível)EC2 com Role, identidade federada

Tipos de Identidades IAM​

1. Identidades Nativas​

Usuário-Raiz da Conta​

  • Criado automaticamente ao criar a conta AWS.
  • Possui acesso total a todos os recursos.
  • Deve ser usado apenas para tarefas críticas como configuração de billing.
  • É recomendado proteger com MFA e evitar o uso diário.

Usuários do IAM​

  • Representam pessoas ou aplicações específicas.
  • Possuem credenciais (senha, chave de acesso).
  • Podem receber políticas de permissão diretamente.

Grupos do IAM​

  • Agrupam usuários com permissões comuns.
  • Facilita a administração (Ex: grupo DevOps, grupo Financeiro).
  • Políticas são atribuídas ao grupo, refletindo nos membros.

Perfis do IAM (IAM Roles)​

  • São identidades assumíveis temporariamente por usuários, aplicações ou serviços da AWS.
  • Não estão associadas a uma pessoa específica.
  • São usados com EC2, Lambda, S3, STS e federação de identidades.

2. Identidades Federadas​

Você pode federar identidades externas (como AD, Google ou Okta) com a AWS. O processo envolve mapear o usuário externo para um perfil do IAM (role) e conceder permissões temporárias.

Como Funciona:​

  1. O usuário se autentica em um provedor de identidade externo.
  2. O provedor emite credenciais temporárias.
  3. A AWS mapeia essas credenciais para uma Role do IAM.
  4. A Role assume as permissões necessárias para acesso aos recursos.

Exemplos de Provedores de Identidade:​

  • Active Directory via SAML
  • Google Workspace via OIDC
  • Auth0, Okta, Azure AD

3. IAM Identity Center (SSO)​

O AWS IAM Identity Center (antigo AWS SSO) é uma solução centralizada para gerenciar identidades e acessos em múltiplas contas e aplicações AWS.

Benefícios:​

  • Interface única para login de usuários
  • Criação automatizada de Roles para acesso às contas
  • Suporte nativo a federação com AD, Okta, Google, etc.
  • Ideal para ambientes com múltiplas contas (AWS Organizations)

Estrutura Hierárquica de Identidades​

Identidades do IAM
├── Usuário-Raiz
│ └── Acesso completo (criado automaticamente)
├── Usuários do IAM
│ ├── Para pessoas físicas
│ └── Para aplicações específicas
├── Grupos do IAM
│ └── Conjunto lógico de usuários
└── Perfis do IAM (Roles)
├── Assumíveis por serviços (EC2, Lambda, etc.)
├── Assumíveis por usuários (cross-account, temporário)
└── Assumíveis via federação de identidade

Conclusão​

Entender os diferentes tipos de identidades no IAM é essencial para implementar controle de acesso eficaz e seguro. Saber quando usar um usuário, grupo, role ou federação faz toda a diferença para um ambiente bem gerenciado e escalável na AWS.
