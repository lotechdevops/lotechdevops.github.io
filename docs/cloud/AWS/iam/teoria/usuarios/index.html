Usuários IAM

O que é um Usuário IAM?​

Um usuário IAM é uma identidade criada na sua conta AWS que representa uma pessoa específica ou uma aplicação. Cada usuário pode ter permissões próprias e credenciais únicas para acessar recursos da AWS.

❗ Importante: Um usuário IAM com permissões de administrador não é equivalente ao usuário-raiz da conta AWS.

Recomendação da AWS​

A melhor prática de segurança recomenda usar federação de identidades com credenciais temporárias (via IAM Identity Center ou SSO corporativo). Usuários IAM com credenciais permanentes devem ser usados somente quando a federação não for viável.

Como a AWS identifica um Usuário IAM​

Ao criar um usuário, o IAM gera três identificadores:

TipoDescrição
Nome AmigávelNome legível atribuído na criação (ex: joao, maria)
ARNIdentificador global: arn:aws:iam::123456789012:user/joao
ID ExclusivoRetornado via API/CLI, não aparece no Console. Identificador técnico único

Tipos de Credenciais​

Usuários IAM podem usar três formas de autenticação, dependendo da finalidade:

1. Senha do Console​

Permite login via interface web (AWS Management Console).

Características:

  • Acesso humano via navegador
  • Permanente até ser alterada
  • Suporta MFA e políticas de complexidade

URL de login personalizada:

https://[account-id].signin.aws.amazon.com/console

Configurações disponíveis:

  • Expiração periódica
  • Complexidade mínima
  • Bloqueio de senhas reutilizadas
  • Reset obrigatório no primeiro login

2. Chaves de Acesso (Access Keys)​

Permitem acesso programático à AWS via CLI, SDKs e APIs.

Estrutura:

  • Access Key ID: identificador público (ex: AKIA...)
  • Secret Access Key: segredo compartilhado (mostrado uma única vez)

Observações:

  • No máximo 2 chaves ativas por usuário
  • Devem ser rotacionadas periodicamente
  • Jamais devem ser expostas em código-fonte

Estados possíveis:

  • Active — chave funcional
  • Inactive — chave desabilitada
  • Deleted — chave removida

3. Credenciais Temporárias (STS)​

Geradas ao assumir uma Role usando o AWS STS (Security Token Service). Recomendadas para tarefas específicas ou acesso temporário.

Componentes:

  • Access Key ID (inicia com ASIA)
  • Secret Access Key
  • Session Token
  • Expiration (de 15 min a 12 horas)

Vantagens:

  • Expiram automaticamente (menor risco)
  • Cada sessão tem ID único (auditoria)
  • Ideal para cross-account, CI/CD e assunção de roles com menor privilégio

Comparativo dos Tipos de Credenciais​

CaracterísticaSenha ConsoleChave de AcessoSTS (Temporária)
InterfaceWebCLI / API / SDKCLI / API / SDK
DuraçãoPermanentePermanenteTemporária (15min–12h)
MFA SuportadoSimNãoSim (ao assumir role)
Uso idealAcesso humanoScripts e apps legadosAcesso temporário
SegurançaMédiaAlta c/ rotaçãoMuito Alta
Limite1 por usuário2 por usuárioIlimitado

Boas Práticas com Usuários IAM​

Para Humanos:​

  • Use federação + IAM Identity Center
  • Aplique MFA obrigatória
  • Nunca utilize o mesmo usuário para múltiplas pessoas

Para Aplicações:​

  • Prefira roles associadas a serviços (ex: EC2 instance profile)
  • Evite credenciais permanentes hardcoded
  • Use OIDC com GitHub Actions, GitLab CI, etc.

Para Automação / CI/CD:​

  • Use assunção de roles via STS
  • Configure provedores confiáveis e política de trust adequada
  • Revogue tokens temporários em casos de exposição

Anti-padrões a evitar​

  • Chaves de acesso no código-fonte
  • Compartilhamento de usuário IAM entre pessoas
  • Falta de rotação periódica de chaves
  • Uso do mesmo usuário para produção e testes

Comandos CLI Essenciais​

Criar usuário:​

aws iam create-user --user-name joao --path "/DevOps/"

Adicionar tags:​

aws iam tag-user --user-name joao \
  --tags Key=Departamento,Value=Engenharia Key=Tipo,Value=DevOps

Criar senha de console:​

aws iam create-login-profile --user-name joao \
  --password "TempPass123!" --password-reset-required

Criar chave de acesso:​

aws iam create-access-key --user-name joao

Habilitar MFA:​

aws iam enable-mfa-device \
  --user-name joao \
  --serial-number arn:aws:iam::123456789012:mfa/joao \
  --authentication-code1 123456 --authentication-code2 654321

Verificar último login:​

aws iam get-user --user-name joao

Gerar relatório de credenciais:​

aws iam generate-credential-report
aws iam get-credential-report

Verificar permissões:​

aws iam list-attached-user-policies --user-name joao
aws iam list-user-policies --user-name joao

Conclusão​

Usuários IAM ainda são necessários em casos específicos, mas a recomendação moderna da AWS é usar identidades federadas com credenciais temporárias sempre que possível. Manter o controle rigoroso das credenciais é essencial para a segurança, governança e conformidade na nuvem.
