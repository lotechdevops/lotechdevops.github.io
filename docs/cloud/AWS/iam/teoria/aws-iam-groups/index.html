Grupos IAM

O que são Grupos de Usuários IAM?​

Um grupo de usuários IAM é uma forma de agrupar múltiplos usuários para facilitar o gerenciamento de permissões. Ao associar políticas a um grupo, todos os usuários membros herdam essas permissões.

Como Funcionam os Grupos​

Exemplo Prático​

Você pode criar um grupo chamado Admins e anexar a ele a política AdministratorAccess. Todos os usuários membros do grupo herdarão automaticamente essas permissões.

Benefícios Operacionais​

  • Novo colaborador? Basta adicioná-lo ao grupo correto.
  • Mudança de função? Remova dos grupos antigos e insira nos novos.
  • Centralização: Uma única política por grupo vale para todos os membros.

Anexação de Políticas​

Você pode anexar políticas baseadas em identidade a um grupo. Essas permissões serão automaticamente herdadas pelos usuários membros.

Atenção: Grupos não podem ser definidos como Principal em políticas baseadas em recurso. Apenas usuários e roles são entidades autenticáveis.

Características dos Grupos IAM​

1. Muitos-para-Muitos​

  • Um grupo pode conter vários usuários
  • Um usuário pode participar de vários grupos

2. Sem Aninhamento​

  • Grupos não podem conter outros grupos
  • Apenas usuários IAM são membros válidos

3. Sem Grupo Padrão​

  • Nenhum grupo inclui todos os usuários automaticamente
  • Um grupo universal deve ser criado manualmente

4. Cotas e Limitações​

  • Limite de grupos por conta
  • Limite de grupos por usuário

Consulte limites do IAM para mais detalhes.

Exemplo de Estrutura Organizacional​

Conta AWS
├── Grupo: Admins
│   └── Políticas: AdministratorAccess
├── Grupo: Developers  
│   └── Políticas: PowerUserAccess
└── Grupo: Test
    └── Políticas: ReadOnlyAccess

Fluxo:

  1. Proprietário cria grupo Admins
  2. Admins criam grupos Developers e Test
  3. Cada usuário recebe credenciais individuais
  4. Permissões são gerenciadas via grupos

Estratégias de Agrupamento​

🔹 Por Função​

  • Administrators
  • Developers
  • QAEngineers
  • Auditors

🔹 Por Projeto​

  • ProjectAlpha-Team
  • PlatformTeam

🔹 Por Nível de Acesso​

  • PowerUsers
  • ReadOnlyUsers
  • BillingUsers

🔹 Por Departamento​

  • Engineering
  • Marketing
  • Finance
  • HR

Boas Práticas​

Recomendado​

  • Use grupos para evitar políticas diretamente em usuários
  • Nomeie grupos com clareza
  • Documente o objetivo de cada grupo

Evitar​

  • Grupos com propósito genérico demais
  • Uso excessivo de políticas individuais
  • Nomes pouco descritivos

Limitações Importantes​

  • Grupos não são entidades autenticáveis
  • Não fazem login, não são assumidos e não aparecem como originadores de ações no CloudTrail
  • Sua função é organizacional, não operacional

Comandos CLI Essenciais​

Criar grupo:​

aws iam create-group --group-name DevOpsEngineers --path "/Engineering/DevOps/"

Adicionar descrição via tags:​

aws iam tag-role --role-name DevOpsEngineers \
  --tags Key=Description,Value="DevOps Engineers with infrastructure management access"

Anexar políticas gerenciadas da AWS:​

aws iam attach-group-policy --group-name DevOpsEngineers \
  --policy-arn arn:aws:iam::aws:policy/PowerUserAccess

Anexar política customizada:​

aws iam attach-group-policy --group-name DevOpsEngineers \
  --policy-arn arn:aws:iam::123456789012:policy/CustomDevOpsPolicy

Adicionar usuários ao grupo:​

aws iam add-user-to-group --user-name joao.silva --group-name DevOpsEngineers

Conclusão​

Os grupos IAM ajudam a manter o ambiente organizado, seguro e escalável. Usar grupos para controlar permissões torna o gerenciamento de acessos muito mais eficiente, especialmente em ambientes com muitos usuários.
