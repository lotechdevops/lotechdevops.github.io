Criar IAM Role para Serviços da AWS

Objetivo​

Aprender a criar uma IAM Role genérica para qualquer serviço da AWS (EC2, Lambda, ECS, etc.), permitindo que o serviço assuma a função e acesse recursos da conta com base em permissões definidas.

Neste lab, você verá um exemplo prático de uma Role para EC2 acessar o Amazon S3 de forma segura e sem uso de chaves de acesso.

Pré-requisitos​

  • Conta AWS com permissões administrativas
  • Pelo menos um serviço da AWS ativo (neste exemplo: EC2 e S3)

O que é uma IAM Role para serviço?​

Uma IAM Role é uma identidade que um serviço da AWS pode assumir automaticamente para obter credenciais temporárias e realizar ações com base em uma política associada.

Exemplos comuns:

  • EC2 acessando S3
  • Lambda gravando logs no CloudWatch
  • ECS acessando Secrets Manager

A Role precisa confiar no serviço que irá assumi-la (definido na trust policy).

Etapas para Criar a Role (Exemplo: EC2 → S3)​

1. Criar a IAM Role​

  1. Vá até IAM > Funções
  2. Clique em Criar perfil
  3. No campo Tipo de entidade confiável, selecione Serviço da AWS
  4. No Campo Caso de uso, selecione EC2
  5. Clique em Próximo
  6. Selecione a política que define o que o serviço poderá fazer:
    • Exemplo: AmazonS3ReadOnlyAccess
  7. Clique em Próximo
  8. Escolha um nome para a Role
    • Exemplo: EC2S3ReadOnlyRole
  9. Clique em Criar perfil

2. Associar a Role ao Serviço (EC2 neste exemplo)​

  1. Vá para o Console EC2
  2. Selecione a instância EC2 desejada
  3. Clique em:
    • Ações
    • Segurança
    • Modificar função do IAM
  4. Selecione a função criada anteriormente.
  5. Clique em Atualizar função do IAM

3. Validar Acesso ao S3 pela EC2​

  1. Conecte na instância EC2
  2. Execute o seguinte comando:
aws s3 ls s3://imagens-miniaturas --region us-east-1

Se os objetos do bucket forem listados, a role está funcionando corretamente.

Boas Práticas​

  • Nomeie suas roles por serviço e propósito (LambdaCloudWatchLogsRole)
  • Sempre utilize o menor conjunto de permissões necessário
  • Use tags para facilitar auditoria e rastreamento
  • Valide as permissões com o IAM Access Analyzer

Conclusão​

IAM Roles para serviços da AWS são essenciais para garantir segurança, automação e governança. Ao permitir que EC2, Lambda ou ECS assumam funções com permissões temporárias, você elimina o uso de chaves de acesso e adota boas práticas nativas da AWS.

Neste exemplo, você aprendeu a criar uma Role para EC2 acessar o S3 — mas esse mesmo conceito se aplica a qualquer serviço compatível com IAM.
