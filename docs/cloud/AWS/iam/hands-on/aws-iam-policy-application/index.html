Aplicação de Políticas IAM

Objetivo​

Aprender a aplicar diferentes tipos de políticas IAM (gerenciadas, personalizadas e inline) a usuários e grupos para controlar permissões de forma eficaz.

Pré-requisitos​

  • Conta AWS com acesso administrativo.
  • Usuário e grupo previamente criados.

Etapas​

1. Acessar o Console do IAM​

  1. Acesse o Console da AWS

2. Aplicar Política Gerenciada da AWS​

  1. Vá até IAM > Grupos de usuário
  2. Clique no grupo que receberá a política.
    • No nosso exemplo iremos aplicar a política no grupo DevOps-EC2FullAccess criado anteriormente.
  3. Vá até a aba Permissões e
  4. Clique na opção Adicionar permissões e depois clique em Anexar políticas
  5. Use o campo de busca e selecione, por exemplo:
    • AmazonS3ReadOnlyAccess
  6. Clique em Anexar políticas

3. Criar Política Gerenciada Personalizada​

  1. Vá até IAM > Políticas
  2. Clique em Criar política
  3. Na aba Visual, defina:
    • Serviço: RDS
    • Ações permitidas: DescribeDBInstances, CreateDBInstance
    • Recursos: Clique em Tudo para selecionar qualquer RDS criado na conta.
  4. Clique em Próximo
  5. Digite um nome da política e uma descrição.
    • No nosso exemplo iremos criar a política:
      • Nome: PoliticaPersonalizada-RDS-DevOps
      • Descrição: Politica personalizada para o time de devops listar as database do rds.
  6. Clique em Criar política

4. Criar Política Inline (1:1)​

  1. Vá em IAM > Usuários clique no usuário que receberá a política.
  2. Na aba Permissões, clique em Adicionar permissões e Criar política em linha
  3. Na aba Visual, defina:
    • Serviço: DynamoDB
    • Ações permitidas: Todas de Leitura
    • Recursos: Clique em Tudo para selecionar qualquer DynamoDB criado na conta.
  4. Clique em Próximo
  5. Digite um nome da política e uma descrição.
    • No nosso exemplo iremos criar a política:
      • Nome: PoliticaPersonalizada-DynamoDB-DevOps
      • Descrição: Politica personalizada para o time de devops listar as database do DynamoDB.
  6. Clique em Criar política

Boas Práticas​

  • Use políticas gerenciadas para reuso e consistência
  • Evite usar políticas inline, exceto em casos pontuais
  • Nomeie as políticas de forma descritiva (CustomEC2Ops, S3FullDev)
  • Sempre siga o princípio do menor privilégio
  • Revise permissões com o Access Advisor
