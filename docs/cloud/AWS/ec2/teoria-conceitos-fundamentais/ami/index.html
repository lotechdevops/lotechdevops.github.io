Amazon Machine Images (AMIs)

Uma Amazon Machine Image (AMIs) é o ponto de partida de qualquer instância EC2 - um modelo que contém tudo necessário para inicializar uma máquina virtual: sistema operacional, discos, drivers e software pré-instalado. Ao iniciar uma instância, você define qual AMI usar, sendo essencial que ela seja compatível com a região, arquitetura, virtualização e tipo de instância desejada.

Componentes essenciais de uma AMI​

Uma AMI inclui:

  • O sistema de arquivos raiz com sistema operacional e softwares.
  • Configurações de mapeamento de dispositivos de bloco (root e volumes adicionais).
  • Metadados, como arquitetura (x86_64, ARM64), tipo de virtualização (HVM ou PV), e permissões de execução.

Tipos de dispositivo raiz​

  • AMI baseada em EBS: Utiliza volumes do Elastic Block Store (EBS) como root. Permite parar/continuar instâncias, dados permanecem após o encerramento, e está alinhada com padrões atuais de uso.
  • AMI baseada em armazenamento de instância: Usa o armazenamento local para dados temporários. Menos recomendado nos dias atuais - limita-se a instâncias antigas e não oferece persistência após desligamento.

Virtualização: HVM vs PV​

  • HVM (Hardware Virtual Machine): Padrão moderno que permite desempenho superior, acesso a extensões de hardware (GPU, rede aprimorada) e é compatível com quase todos os tipos de instância atuais.
  • PV (Paravirtual): Modelo legado, compatível apenas com instâncias antigas. Atualmente em desuso.

Ciclo de vida de uma AMI​

O ciclo completo inclui criação (a partir de instâncias configuradas), cópia entre regiões, descontinuação, desativação e exclusão. Ferramentas como Amazon Data Lifecycle Manager e EC2 Image Builder permitem automatizar esses processos para maior eficiência e padronização.

Compartilhamento e permissões de execução​

Você controla quem pode usar sua AMI:

  • Pública: Todos os usuários da AWS podem iniciar instâncias.
  • Explícita: Permite acesso para contas, organizações ou unidades organizacionais.
  • Implícita: Apenas o proprietário possui acesso por padrão.

É possível compartilhar AMIs com outras contas ou torná-las públicas; mas atenção: algumas não podem ser públicas caso contenham componentes criptografados ou vinculados a produtos licensing-based. AMIs públicas também têm regras específicas de descontinuação automática após determinado tempo.

AMIs pagas no AWS Marketplace​

O AWS Marketplace oferece AMIs pré-configuradas (e muitas vezes pagas), criadas por terceiros, com softwares e licenciamento incluídos - como soluções de segurança, bancos de dados e ferramentas de desenvolvimento. A cobrança inclui o custo da instância EC2 mais a taxa da AMI.

Cotas e Limites​

Algumas cotas padrão por região:

  • Total de AMIs (públicas + privadas): 50.000.
  • AMIs públicas: 5.
  • Compartilhamento por AMI (contas/organizações): 1.000.

Se necessário, é possível solicitar aumento dessas cotas via Service Quotas no console da AWS.

A AMI é o coração de suas instâncias EC2, escolher e gerenciar bem suas imagens garante consistência, segurança e eficiência. Saber as diferenças entre tipos de dispositivo, virtualização, ciclo de vida e permissões é fundamental para arquitetar ambientes mais robustos e automatizados.
