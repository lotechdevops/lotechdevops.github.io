Volumes EBS

Objetivo​

Neste laboratório você vai:

  • Criar um volume EBS
  • Anexar o volume a uma instância EC2
  • Formatar e montar o volume no Linux, inclusive de forma permanente
  • Aumentar o tamanho do volume
  • Criar um snapshot e copiá-lo para outra região

Veja a teoria em Amazon EBS.

Requisitos​

  • Conta AWS ativa
  • Uma instância EC2 em execução, para receber o volume
  • Permissões no IAM para criar e gerenciar volumes EBS

1. Criar um volume EBS​

  1. Abra o console do Amazon EC2: https://console.aws.amazon.com/ec2/
  2. No painel de navegação, em Elastic Block Store, clique em Volumes.
  3. Clique em Criar volume.
  4. Em Tipo de volume, selecione o tipo desejado:
    • gp3, gp2: uso geral
    • io1, io2: alta performance (IOPS provisionado)
    • st1, sc1: HDD otimizado para throughput e para dados frios
    • Magnético (standard): opção antiga, pouco usada
  5. Em Tamanho, informe a capacidade do volume em GiB.
  6. (Apenas gp3, io1 e io2) defina o valor de IOPS.
  7. (Apenas gp3) defina a Taxa de transferência em MiB/s.
  8. Em Zona de disponibilidade, selecione a AZ do volume.

    Para anexar o volume a uma instância, ela precisa estar na mesma AZ.

  9. Em ID do snapshot, escolha:
    • Valor padrão, para criar um volume vazio
    • Um snapshot existente, para criar o volume a partir dele
  10. (Apenas com snapshot, opcional) Taxa de inicialização de volume: velocidade, em MiB/s, para carregar os blocos do snapshot.
  11. (Apenas io1 e io2) Para o Multi-Attach, marque Habilitar Multi-Attach.
  12. Em Criptografia, defina se o volume será criptografado e a chave.
  13. (Opcional) Adicione tags.
  14. Clique em Criar volume.

2. Anexar o volume a uma instância​

  1. Em Elastic Block Store → Volumes, selecione o volume.
  2. Clique em Ações → Associar volume.
  3. Em Instância, selecione a instância que vai receber o volume.
  4. Em Nome do dispositivo, use o valor sugerido (por exemplo, /dev/sdf).
  5. Clique em Associar volume.

3. Preparar e montar o volume (Linux)​

  1. Conecte na instância (SSH ou Session Manager).
  2. Identifique o volume:
lsblk

Exemplo de saída:

NAME          MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
nvme0n1       259:0    0   8G  0 disk
├─nvme0n1p1   259:1    0   8G  0 part /
├─nvme0n1p127 259:2    0   1M  0 part 
└─nvme0n1p128 259:3    0  10M  0 part /boot/efi
nvme1n1       259:4    0   5G  0 disk

O disco nvme1n1 é o volume recém-anexado, ainda sem sistema de arquivos.

  1. Crie o sistema de arquivos:
sudo mkfs -t ext4 /dev/nvme1n1
  1. Crie o ponto de montagem e monte o volume:
sudo mkdir /mnt/ebs
sudo mount /dev/nvme1n1 /mnt/ebs
  1. Verifique:
df -hT

Exemplo de saída:

Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/nvme1n1   ext4  4.9G   24K  4.6G   1% /mnt/ebs

Opcional: montar automaticamente no boot​

  1. Obtenha o UUID do volume:
sudo blkid -s UUID /dev/nvme1n1
  1. Edite o arquivo /etc/fstab:
sudo nano /etc/fstab
  1. Adicione a linha, trocando pelo UUID obtido:
UUID=SEU-UUID-AQUI /mnt/ebs ext4 defaults,nofail 0 2
  1. Teste a configuração:
sudo umount /mnt/ebs
sudo mount -a
df -hT
aviso

Um erro no /etc/fstab pode impedir o boot da instância. A opção nofail evita isso quando o volume não está presente. Sempre teste com sudo mount -a antes de reiniciar.

4. Aumentar o tamanho do volume​

  1. Em Elastic Block Store → Volumes, selecione o volume.
  2. Clique em Ações → Modificar volume.
  3. No campo Tamanho, insira o novo valor (maior que o atual).
  4. Clique em Modificar e confirme.
  5. Aguarde o estado da modificação chegar a Otimizando ou Concluído.

É possível aumentar o volume com a instância em execução, sem reiniciar. Depois de uma modificação, é preciso esperar um tempo (cerca de 6 horas) para modificar o mesmo volume de novo.

4.1. Ajustar o sistema de arquivos no Linux​

Depois de aumentar o volume, o sistema de arquivos ainda usa o tamanho antigo.

  1. Confira o tamanho atual:
df -hT
lsblk
  1. Redimensione o sistema de arquivos:
sudo resize2fs /dev/nvme1n1
  1. Confirme o novo tamanho:
df -hT

Saída esperada:

Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/nvme1n1   ext4  9.8G   24K  9.3G   1% /mnt/ebs

5. Criar um snapshot do volume​

  1. Em Elastic Block Store → Volumes, selecione o volume.

    Confirme que é o volume correto, principalmente se a instância tiver mais de um.

  2. Clique em Ações → Criar snapshot.
  3. Adicione uma descrição e, se quiser, tags.
  4. Clique em Criar snapshot.
  5. Acompanhe em Elastic Block Store → Snapshots. O estado muda de Pendente para Concluído.

6. Copiar um snapshot para outra região​

A cópia é útil para:

  • Recuperação de desastres (DR)
  • Criar volumes em outras regiões
  • Manter backups distribuídos geograficamente
  1. Em Elastic Block Store → Snapshots, selecione o snapshot.
  2. Clique em Ações → Copiar snapshot.
  3. Na tela de cópia:
    • Região de destino: a região para onde o snapshot será copiado
    • Descrição: uma descrição para a nova cópia
    • Criptografia: se o snapshot original é criptografado, a cópia também será. Você pode manter a mesma chave KMS ou escolher outra
    • Tags: opcional
  4. Clique em Copiar snapshot.
  5. Na região de destino, acompanhe em Snapshots. A cópia pode levar vários minutos.

Se escolher outra chave KMS, ela precisa existir na região de destino.

Limpeza​

Snapshots e volumes soltos continuam sendo cobrados.

  1. Desmonte o volume (sudo umount /mnt/ebs) e remova a linha do /etc/fstab.
  2. Volumes → Ações → Desassociar volume, e depois Excluir volume.
  3. Snapshots → exclua o snapshot, e a cópia na região de destino.
