Security Groups

Objetivo​

Criar um Security Group, associá-lo à instância e comprovar na prática como as regras de entrada liberam ou bloqueiam o tráfego.

Pré-requisitos​

  • Instância lab-ec2-01 em execução
  • Acesso à instância por SSH ou Session Manager (Conectar na instância)

Etapas​

1. Criar o Security Group​

  1. No EC2, menu lateral Rede e segurança → Security Groups → Criar grupo de segurança.
  2. Nome: web-lab. Descrição: Lab web. VPC: a VPC padrão.
  3. Em Regras de entrada, adicione apenas:
    • Tipo SSH, origem Meu IP
  4. Mantenha a regra de saída padrão (todo o tráfego).
  5. Clique em Criar grupo de segurança.

2. Associar à instância​

  1. Selecione a instância → Ações → Segurança → Alterar grupos de segurança.
  2. Adicione sg-web-lab e remova o grupo launch-wizard-1.
  3. Clique em Salvar.
observação

Uma instância pode ter vários Security Groups, e as regras de todos eles são somadas. Mudanças nas regras valem imediatamente, sem reiniciar a instância.

3. Subir um servidor de teste​

Conecte na instância e inicie um servidor web simples na porta 80:

cd /tmp
sudo python3 -m http.server 80

4. Testar com a porta fechada​

  1. No seu computador, abra http://IP_PUBLICO no navegador.
  2. A página não carrega (timeout). O Security Group está bloqueando a porta 80.

5. Abrir a porta 80​

  1. Abra sg-web-lab → Regras de entrada → Editar regras de entrada.
  2. Adicionar regra: tipo HTTP, origem Qualquer local-IPv4 (0.0.0.0/0).
  3. Salve e atualize a página no navegador. Agora a listagem de arquivos aparece.
aviso

Origem 0.0.0.0/0 libera para a internet inteira. Para HTTP em um site público é normal, mas nunca faça isso para SSH, banco de dados ou outras portas administrativas.

6. Fechar novamente​

  1. Edite as regras e exclua a regra HTTP.
  2. Atualize o navegador: novas conexões voltam a falhar.
  3. No terminal da instância, pare o servidor com Ctrl + C.

O que observar​

  • Security Groups só têm regras de permissão (allow); não existe regra de bloqueio explícito.
  • São stateful: a resposta de uma conexão permitida volta sem precisar de regra de saída.
  • A origem de uma regra pode ser um IP, uma faixa (CIDR) ou outro Security Group.

Limpeza​

Nada a apagar. O sg-web-lab é reutilizado no próximo laboratório.
