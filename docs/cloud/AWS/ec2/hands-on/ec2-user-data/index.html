User data: subindo um servidor web no boot

Objetivo​

Automatizar a configuração de uma instância com um script de user data, que roda uma única vez no primeiro boot.

Pré-requisitos​

  • Security Group web-lab (Security Groups na prática)
  • Key pair lab-ec2-key

Etapas​

1. Liberar a porta 80​

  1. Abra web-lab → Editar regras de entrada.
  2. Mantenha SSH (Meu IP) e adicione HTTP com origem 0.0.0.0/0.

2. Lançar a instância com user data​

  1. EC2 → Executar instâncias.
  2. Nome: lab-ec2-web. AMI: Amazon Linux 2023. Tipo: t3.micro. Key pair: lab-ec2-key.
  3. Grupo de segurança: selecione Selecionar grupo de segurança existente e escolha web-lab.
  4. Expanda Detalhes avançados e role até Dados do usuário (User data). Cole o script:
#!/bin/bash
dnf update -y
dnf install -y nginx
systemctl enable --now nginx

TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" \
  -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
ID=$(curl -s -H "X-aws-ec2-metadata-token: $TOKEN" \
  http://169.254.169.254/latest/meta-data/instance-id)

echo "<h1>Ola do EC2 $ID</h1>" > /usr/share/nginx/html/index.html
  1. Clique em Executar instância.

3. Testar​

  1. Aguarde 1 a 2 minutos após o estado Em execução (o script ainda está rodando).
  2. Abra http://IP_PUBLICO no navegador. A página mostra o ID da instância.

4. Ver os logs do script​

Conecte na instância e execute:

sudo cat /var/log/cloud-init-output.log | tail -n 30
systemctl status nginx

O que observar​

  • O user data roda como root e somente no primeiro boot (por padrão).
  • O limite de tamanho é de 16 KB.
  • Não coloque senhas ou chaves no user data: qualquer pessoa com acesso à instância consegue lê-lo.
  • Se o site não abrir, quase sempre é o Security Group (porta 80) ou o script ainda em execução. O log acima mostra o erro.

Limpeza​

Mantenha a instância lab-ec2-web: ela será usada nos próximos laboratórios.
