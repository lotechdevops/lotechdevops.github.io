EFS - Elastic File System

O que é o Amazon Elastic File System (EFS)​

O Amazon Elastic File System (EFS) é um serviço de armazenamento de arquivos totalmente gerenciado e elástico, projetado para oferecer compartilhamento de dados sem a necessidade de provisionar ou gerenciar manualmente capacidade e desempenho.

O EFS foi criado para escalar automaticamente até petabytes sem interromper aplicações, aumentando ou diminuindo a capacidade à medida que arquivos são adicionais ou removidos. Isso elimina a complexidade de implantar, corrigir e manter sistemas de arquivos tradicionais, permitindo que você foque nas aplicações e não na infraestrutura.

Com suporte ao protocolo Network File System (NFS) v4.1 e v4.0, o EFS é compatível com a maioria dos aplicativos e ferramentas existentes, integrando-se facilmente a serviços como Amazon EC2, Amazon ECS, Amazon EKS, AWS Lambda e AWS Fargate.

Tipos de sistema de arquivos no EFS​

O Amazon EFS oferce dois tipos principais de sistemas de arquivos: Regional e One Zone

  • Regional (Recomendado):

    Armazena dados de forma redundante em múltiplas Zonas de Disponibilidade separadas geograficamente dentro da mesma Região AWS.

    Esse modelo garante alta disponibilidade e durabilidade contínua, mesmo que uma ou mais zonas de disponibilidade se tornem indisponíveis.

    É a opção indicada para cargas de trabalho que exigem o mais alto nível de resiliência.

  • One Zone:

    Armazena dados em apenas uma Zona de Disponibilidade, oferecendo custo mais baixo, mas com maior risco em caso de falha dessa zona.

    No improvável evento de perda ou dano total/parcial da zona (por exemplo, incêncio, inundação ou falha grave de infraestrutura), os dados podem ser perdidos.

    Mesmo assim, esste tipo de sistema é projetado para ofercer 99,999999999% de durabilidade, protegendo contra falhas de disco, host e rack.

Para maior proteção, o Amazon EFS realiza backup automático de sistemas One Zone usando o AWS Backup, permitindo restaurar os dados para qualquer zona operacional dentro da mesma região ou até em outra região. Esses backups são replicados em três zonas de disponibilidade e projetados para alta durabilidade.

Comparação entre tipos de sistemas de arquivos EFS​

| Tipo de sistema de arquivos | Projetado para                                              | Durabilidade (projetada) | Disponibilidade | Zonas de disponibilidade | Outras considerações                              |
| --------------------------- | ----------------------------------------------------------- | ------------------------ | --------------- | ------------------------ | ------------------------------------------------- |
| **Regional**                | Dados que exigem a maior durabilidade e disponibilidade     | 99,999999999% (11 9s)    | 99,99%          | >= 3                     | Nenhuma                                           |
| **One Zone**                | Dados que não exigem a maior durabilidade e disponibilidade | 99,999999999% (11 9s)    | 99,99%          | 1                        | Não resistente à perda da zona de disponibilidade |

Os sistemas de arquivos One Zone estão disponíveis apenas em Zonas de disponibilidade específicas.

Como o Amazon EFS funciona​

O Amazon EFS fornece um sistema de arquivos simples, set-and-forget, elástico e sem servidor.

Com o Amazon EFS, você pode criar um sistema de arquivos, montar o sistema de arquivos em uma instância Amazon EC2 e, em seguida, ler e gravar dados de e para o seu sistema de arquivos.

Você pode montar um sistema de arquivos EFS em sua VPC por meio do protocolo Network File System versões 4.0 e 4.1 (NFSv4).

Recomendado usar um cliente Linux NFSv4.1 da geração atual, como os encontrados mais recentes Amazon Linux, Amazon Linux 2, Red Hat, Ubuntu e macOS Big Sur AMIs, em conjunto com o auxiliar de montagem EFS.

Para alguns AMIs, deverá instalar um cliente NFS para montar seu sistema de arquivos na instância Amazon EC2

Você pode acessar seu sistema de arquivos NFS simultaneamente a partir de vários clientes NFS, para que aplicativos que se expandam além de uma única conexão possam acessar um sistema de arquivos. A Amazon EC2 e outras instâncias computacionais AWS executadas em várias zonas de disponibilidade dentro da mesma região da AWS podem acessar o sistema de arquivos, permitindo que muitos usuários acessem e compartilhem uma fonte de dados comum.

Destinos de Montagem (Mount Targets)​

Para acessar seu sistema de arquivos EFS em uma VPC, você cria um ou mais destinos de montagem na VPC.

Um destino de montagem fornece um endereço IP para um endpoint NFSv4 no qual você pode montar um sistema de arquivos EFS.

Você monta seu sistema de arquivos usando o nome DNS do serviço, que é resolvido para o endereço IP do destino de montagem do EFS na mesma zona de disponibilidade da sua instância EC2.

Você pode criar um destino de montagem em cada zona de disponibilidade da região AWS.

Se houver várias sub-redes em uma zona de disponibilidade na sua VPC, você poderá criar um destino de montagem em uma dessas sub-redes.

Todas as instâncias EC2 nessa zona de disponibilidade compartilham esse destino de montagem.

Um sistema de arquivos NFS só pode ter destinos de montagem em uma VPC por vez.

Os destinos de montagem são projetados para serem altamente disponíveis.

Ao projetar para alta disponibilidade e failover para outras zonas de disponibilidade (AZs), lembre-se de que, embora os endereços IP e DNS para os destinos de montagem em cada AZ sejam estáticos, eles são componentes redundantes que recebem suporte de vários recursos.

Como o Amazon EFS funciona com a Amazon EC2​

Sistema de arquivos regional do EFS​

O Amazon EFS pode ser montado em instâncias EC2 dentro de uma VPC, permitindo que múltiplas instâncias compartilhem os mesmos dados simultaneamente.

No caso de um sistema de arquivos EFS Regional, um destino de montagem (mount target) é criado em cada zona de disponibilidade (AZ) da região. Cada mount target recebe um endereço IP próprio e atua como ponto de conexão para as instâncias EC2.

Para otimizar custos e desempenho, recomenda-se que cada instância EC2 acesse o EFS por meio do mount target da mesma AZ onde está localizada.

Mesmo distribuído em várias AZs, o sistema de arquivos é único e consistente, garantindo alta disponibilidade e redundância dos dados. Isso permite que diferentes instâncias, em diferentes zonas, acessem e compartilhem a mesma base de dados de forma simultânea e segura.

Sistema de arquivos One Zone do EFS​

A imagem a seguir mostra várias instâncias Amazon EC2 acessando um sistema de arquivos Amazon EFS do tipo One Zone, a partir de diferentes zonas de disponibilidade em uma única região da AWS.

Nesta imagem, a VPC possui duas zonas de disponibilidade, cada uma com uma sub-rede. Como o tipo de sistema de arquivos é One Zone, ele só pode ter um único destino de montagem (Mount Target). Para obter melhor desempenho e custo, recomenda-se acessar o sistema de arquivos a partir de um destino de montagem na mesma zona de disponibilidade da instância EC2 onde ele está sendo montado.

No entanto, se a instância EC2 estiver localizada em uma zona de disponibilidade diferente do destino de montagem, o acesso aos dados resultará em custos adicionais de transferência e possivelmente maior latência.

Modos de desempenho e throughput​

O EFS foi projetado para ofercer baixa latência, altas taxas de throughput e IOPS para uma ammpla gama de workloads. Ele conta com dois modos de desempenho principais:

  • Uso Geral (General Purpose): Ideal para workloads sensíveis à latência, como servidores web, diretórios de usuários, sistemas de gerenciamento de conteúdo e serviços de arquivos em geral.
  • Throughput Elástico (Elastic Throughput): Ajusta automaticamente a capacidade de throughput conforme a demanda, sem necessidade de configuração manual, sendo ideal para workloads com picos e variações imprevisíveis.

Classes de Armazenamento​

O Amazon EFS oferece duas classes principais de armazenamento, projetadas para equilibrar desempenho e custo, permitindo que você armazene dados de forma eficiente de acordo com o padrão de acesso.

1. EFS Standard​

Indicada para arquivos acessados com frequência, oferecendo alta disponibilidade, baixa latência e replicação automática entre múltiplas Zonas de Disponibilidade no caso de sistemas de arquivos regionais.

Características​

  • Armazenamento de alta disponibilidade e durabilidade.
  • Acesso com baixa latência.
  • Replicação automática entre múltiplas zonas de disponibilidade (no caso do tipo Regional).

2. EFS Standard-Infrequent Access (Standard-IA)​

É voltada para dados acessos com pouca frequência, mantendo o mesmo nível de durabilidade e disponibilidade do EFS Standard, mas com custo significativamente menor por GB armazenado. Entretanto, nesta classe há cobrança adicional por leitura de dados, o que a torna mais indicada para arquivos de backup, históricos ou arquivados, que precisam permanecer disponíveis, mas raramente são utilizados.

Características​

  • Menor custo por GB armazenado.
  • Mesma durabilidade e disponibilidade do EFS Standard.
  • Cobrança por recuperação de dados (por GB lido).

EBS Lifecycle Management​

O EFS conta com um recurso chamado Gerenciamento de Ciclo de Vida (Lifecycle Management), que move automaticamente arquivos inativos para a classe Infrequent Access (IA), ajudando a reduzir custos sem que você precise mover dados manualmente.

  • Como funciona:
    • Você define um período de inatividade (7, 14, 30, 60 ou 90 dias).
    • Arquivos que não forem acessados nesse período são movidos para a classe IA.
    • Se forem acessados novamente, permanecem na IA, mas você pagará pelo custo de leitura.

Comparação de custos (exemplo aproximado)​

ClasseCusto por GB-mês (us-east-1)Custo por leitura (por GB)

Habilitar o Lifecycle Management pode gerar economias significativas em workloadas que acumulam dados pouco acessados, sem compremeter a disponibilidade.

Segurança no EFS​

O Amazon EFS oferece recursos de segurança para proteger os dados em trânsito e em repouso, além de controles de acesso detalhados para garantir que apenas usuários e aplicações autorizadas possam interagir com o sistema de arquivos. Para proteção dos dados em repouso, o EFS oferece criptografia integrada usando o AWS KMS. Essa criptografia pode ser habilitada no momento da criação do sistema de arquivos, garantindo que todos os dados e metadados armazenados sejam criptografadossss automaticamente. Já para dados em trânsito, o EFS suporte criptografia utilizando o protocolo TLS, que pode ser ativada ao montar o sistema de arquivos, assegurando a proteção das informações durante a comunicação entre clientes e o serviço.

O controle de acesso ao EFS é realizado por meio de uma combinação de permissões no nível do sistema de arquivos e configurações de rede. No nível do sistema de arquivos, o EFS utiliza permissões POSIX (Portable Operating System Interface), que permitem definir, no próprio sistema, quais usuários e grupos têm permissão de leitura, gravação ou execução em arquivos e diretórios.No nível de rede, o acesso é controlado por Security Groups associados aos Mount Targets, restringindo conexões apenas a instâncias e redes autorizadas. Além disso, o EFS integra-se ao AWS IAM, permitindo a criação de políticas granulares para controlar quais identidades podem criar, gerenciar ou excluir sistemas de arquivos e destinos de montagem.

Essa combinação de criptografia, permissões POSIX, controle por Security Groups e políticas IAM proporciona uma camada de segurança robusta, ajudando a atender requisitos de conformidade e protegendo dados contra acessos não autorizados, tanto em cenários de uso interno quanto em aplicações expostas a múltiplos clientes e workloads distribuídas.
