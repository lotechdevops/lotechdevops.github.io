Tipos de Instância EC2

A AWS oferece diversos tipos de instâncias EC2, organizados em famílias otimizadas para diferentes cenários de uso, como processamento, memória, armazenamento ou desempenho gráfico.

Cada tipo de instância possui variações de tamanho (ex: t3.micro, m6i.large, c7g.xlarge), que indicam a quantidade de vCPU, memória e capacidade de rede.

Como escolher o tipo ideal​

A escolha depende das características da sua aplicação, como:

  • Precisa de mais CPU ou mais RAM?
  • Precisa de armazenamento rápido (EBS/SSD/NVMe)?
  • Executa tarefas gráficas ou machine learning?
  • Executa cargas de trabalho burstáveis (picos de uso)?

Como analisar uma instância​

Vamos analisar a instância m6i.large

  • m - Família
  • 6 - Geração mais recente (quanto maior, mais atual)
  • i - Baseada em processador intel
  • large - Tamanho da instância (ex: nano, micro, small, medium, large, xlarge, 2xlarge, etc.)

Outros sufixos comuns:

  • a- Processador AMD
  • g- Graviton (Arm)
  • n- Otimizado para rede
  • d- Com disco local
  • metal- Instância bare-metal (sem hypervisor)

Principais Famílias de Instâncias EC2​

Família T - Burstable (uso geral com picos)​

As instâncias da família T são ideais para workloadas que geralmente usam pouca CPU, mas que precisam de desempenho extra de forma ocasional. Elas funcionam com um sistema de créditos de CPU, acumulando recursos quando o uso está baixo, e consumindo durante os picos.

Essas instâncias são ótimas para servidores de sites de baixo tráfego, ambientes de desenvolvimento, microserviços e bancos de dados leves.

Exemplos​

  • t3.micro
  • t3a.small
  • t4g.medium (baseada em Graviton)

Família M - General Purpose (uso geral)​

As instâncias da família M são balanceadas, com um proporção estável entre vCPU, memória e rede. Servem para uma grande variedade de workloadas: desde aplicações web até servidores de backend e bancos de dados de pequeno porte.

São muito utilizadas em ambientes corporativos e soluções generalistas.

Exemplos​

  • m6i.large (Intel)
  • m7g.medium (Graviton3)
  • m5a.xlarge (AMD)

Família C - Compute Optimized​

As instâncias da família C é voltada para aplicações que exigem alto desempenho de CPU, como servidores web de alta carga, processamento paralelo, análises em tempo real, renderização e carga com muita computação.

Elas oferecem alto throughput por núcleo e baixa latência.

Exemplos​

  • c7g.xlarge (Graviton3)
  • c6a.2xlarge (AMD)
  • c6i.xlarge (Intel)

Família R - Memory Optimized​

As instâncias da família R são projetadas para workloadas que precisam de muita RAM, como banco de dados em memória (Redis, Memcached), bancos relacionais, aplicações análiticas e servidores que mantêm grandes quantidades de dados na memória.

Exemplos​

  • r6i.large
  • r7g.xlarge
  • r5a.4xlarge

Famílias I / D / H - Storage Optimized​

Essas famílias são ideais para workloads com acesso intensivo a disco, seja em termos de throughput ou IOPS. Usadas para bancos NoSQL, mecanismos de busca, data lakes e ETL com grandes volumes de dados.

  • A família I (ex: i4i.large) é otimizada para IOPS com NVMe SSD.
  • A família D (ex: d3.xlarge) é otimizada para throughput com HDD.
  • A família H (ex: h1.2xlarge) oferece discos magnéticos com alta densidade.

Família G / P / Inf - Accelerated Computing​

Essas instâncias possuem aceleradores de hardware como GPUs NVIDIA ou chips customizados da AWS para tarefas de computação intensiva, como:

  • Treinamento e inferência em Machine Learning.
  • Renderização 3D.
  • Simulações científicas.

Exemplos​

  • g5.xlarge (GPU NVIDIA para ML e gráficos).
  • p4d.24xlarge (treinamento profundo de ML).
  • inf2.xlarge (otimizada para inferência com AWS Inferentia).

Família X - High Memory​

A família X é voltada para workloads que exigem centenas de GB ou até vários TB de memória RAM, como sistemas SAP HANA, bancos in-memory, e aplicações financeiras com grandes datasets.

Exemplos​

  • x2idn.16xlarge
  • x2gf.8xlarge

Família Z - High Frequency​

A família Z oferece instâncias com alta frequência de clock por núcleo, ideal para aplicações sensíveis à performance por thread, como EDA (automação de design eletrônico), licenças de software por core e bancos de dados com alta exigência por core.

Exemplo:​

  • z1d.large (até 4.0 GHz por núcleo)
