Client VPN Endpoints

🧭 Como criar um Client VPN Endpoint na AWS (passo a passo)​

Após gerar os certificados e importar o certificado do servidor no AWS ACM, o próximo passo é criar o Client VPN Endpoint, associar uma subnet, configurar rotas e autorizações. Esse será o ponto de entrada para conexões remotas na sua VPC.

Este guia cobre todas as etapas necessárias, utilizando o console da AWS, com recomendações práticas.

🔍 1. Acesse o console da AWS e abra o VPC​

  • No menu de busca, pesquise por client vpn endpoints e clique para abrir.

➕ 2. Clique em Create Client VPN Endpoint​

📝 3. Preencha os dados principais​

  • Name tag: "vpn-bastion-endpoint" (ou nome descritivo)
  • Description: "Acesso remoto para VPC HostBastion"
  • Client IPv4 CIDR:
    • Este campo define a faixa de endereços IP privados que será atribuída aos clientes VPN quando eles se conectarem ao endpoint.
    • Tamanho mínimo permitido: /22
    • Tamanho máximo permitido: /12
    • O intervalo que você definir não pode sobrepor com nenhum outro CIDR das suas VPCs.
    • Exemplo: 172.20.0.0/22
    • Esses IPs não estão na sua VPC, mas são roteáveis através do tunelamento VPN. A AWS cria uma interface virtual para rotear esses IPs até os recursos da VPC com base nas regras de rota e autorização que você configurar.

Autenticação:​

  • Server certificate ARN: selecione o certificado do servidor (importado no ACM)
    • Esse é o certificado que representa o "servidor" VPN. Ele foi gerado com extendedKeyUsage = serverAuth e importado no ACM. Esse certificado será usado pelo endpoint VPN para autenticar sua identidade com os clientes que tentarem se conectar.
  • Authentication options: selecione Mutual authentication
    • Isso significa que além do servidor VPN ser autenticado, os clientes também precisarão apresentar um certificado válido, garantindo segurança mútua entre cliente e servidor.
  • Client certificate ARN: selecione o certificado da CA que assinou o client.crt
    • Aqui você vai informar o certificado da Autoridade Certificadora (CA) que assinou os certificados dos clientes. Isso permite que a AWS valide se o certificado apresentado pelo cliente é confiável, garantindo que apenas dispositivos autorizados se conectem à VPN.

Logging (opcional):​

  • Pode deixar desabilitado ou configurar para enviar logs ao CloudWatch Logs

⚙️ 4. Configurações adicionais:​

  • DNS server 1 \ DNS server 2 (opcional): Permite configurar servidores DNS personalizados que serão utilizados pelos clientes conectados à VPN. Se você usa o Route 53 ou outro DNS interno, pode definir aqui os IPs.

  • Transport Protocol: UDP (padrão) UDP é geralmente mais eficiente e preferido para VPNs. TCP pode ser usado se houver restrições específicas de firewall ou proxy.

  • Split-tunnel: Permite que somente o tráfego destinado à rede da AWS passe pela VPN (mantém internet local funcionando)

  • VPC ID: selecione a VPC à qual a VPN se conectará, isso define em qual VPC o endpoint será integrado.

  • Security Groups: selecione um ou mais grupos de segurança, eles controlam o tráfego entre os clientes conectados via VPN e os recursos dentro da VPC.

  • VPN Port: 443 Porta padrão utilizada para estabelecer a conexão VPN. Pode ser alterada caso tenha regras específicas de rede.

  • Enable self-service portal (opcional): Ativa um portal web onde os usuários podem baixar a configuração da VPN. Útil em ambientes com muitos usuários, mas exige integração com autenticação federada (IAM Identity Center/SAML).

  • Session timeout hours: 24 (padrão) Tempo máximo de duração da sessão VPN antes de expirar automaticamente. Pode ser ajustado para controle de segurança.

  • Client Connect Handler (opcional): Permite acionar um Lambda sempre que um cliente se conectar à VPN. Pode ser usado para auditoria, verificação de identidade, ou aplicação de políticas personalizadas.

✅ 5. Clique em Create Client VPN Endpoint​

Aguarde a criação. O endpoint ficará com status Pending-association até que uma subnet seja associada.

🔗 6. Associar uma subnet​

  1. Clique na aba Target network associations
  2. Clique em Associate target network

  1. Selecione:
    • A VPC desejada
    • A subnet privada onde o tráfego será roteado.

🛡️ 7. Criar regras de autorização​

Para que os dispositivos conectados à VPN possam acessar os recursos dentro da VPC, é necessário criar regras de autorização. Essas regras atuam como uma camada de permissão adicional, além do security group e das rotas.

  1. Clique na aba Authorization Rules
  2. Clique em Create authorization rule

  1. Configure os campos da seguinte forma:
    • Destination network to enable access: Esse é o CIDR da sua VPC — você está autorizando os clientes VPN a acessarem toda a rede interna da VPC.
    • Grant access to: Allow access to all users: Isso permite que qualquer cliente que apresente um certificado válido se conecte. Se você tiver grupos de usuários integrados via SAML, poderá restringir a regra a grupos específicos.
