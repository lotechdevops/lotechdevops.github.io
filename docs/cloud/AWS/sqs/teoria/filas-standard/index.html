Filas Standard do Amazon SQS

O Que São Filas Standard?​

As Filas Standard são o tipo padrão de fila do Amazon SQS. Elas oferecem throughput praticamente ilimitado, permitindo um número quase infinito de transações por segundo para operações como enviar, receber e deletar mensagens.

Filas Standard garantem que cada mensagem seja entregue pelo menos uma vez, mas devido à arquitetura altamente distribuída, ocasionalmente mais de uma cópia da mensagem pode ser entregue e as mensagens podem chegar fora de ordem.

Características Principais​

Throughput Ilimitado​

  • Sem limite de transações por segundo
  • Escalabilidade automática para qualquer volume
  • Sem necessidade de provisionamento

Operações suportadas:

  • SendMessage: Enviar mensagens
  • ReceiveMessage: Receber mensagens
  • DeleteMessage: Deletar mensagens

Entrega pelo menos uma vez (At-Least-Once Delivery)​

Garantia: Cada mensagem é entregue pelo menos uma vez, mas pode ser entregue mais de uma vez.

Por que acontece duplicação?

O Amazon SQS armazena mensagens redundantemente em múltiplos servidores distribuídos em diferentes Availability Zones. Em situações raras, quando uma mensagem é recebida ou deletada, pode haver um pequeno atraso na sincronização entre os servidores, fazendo com que uma cópia da mensagem seja entregue novamente.

Exemplo:

1. Consumidor recebe mensagem A (servidor 1)
2. Consumidor processa mensagem A
3. Consumidor deleta mensagem A
4. Sincronização entre servidores tem delay
5. Consumidor recebe mensagem A novamente (servidor 2 ainda não sincronizou)

Solução: Implemente Idempotência na sua aplicação - processar a mesma mensagem múltiplas vezes deve ter o mesmo resultado.

Melhor esforço de ordenação (Bast-Effort Ordering)​

Garantia: O SQS faz o melhor esforço para manter a ordem, mas não garante que mensagens sejam entregues na mesma ordem que foram enviadas.

Por que acontece desordenação?

Mensagens são distribuídas entre múltiplos servidores para alta disponibilidade. Quando um consumidor solicita mensagens, elas podem vir de diferentes servidores, resultando em ordem diferente.

Exemplo:

Produtor envia: A → B → C
Consumidor pode receber: A → C → B (ou qualquer outra ordem)

Quando a ordem importa: Use fila FIFO em vez de Standard.

Armazenamento Redundante​

Quando você envia uma mensagem usando SendMessage, o Amazon SQS:

  1. Armazena a mensagem redundantemente em múltiplas Availability Zones
  2. Só confirma o envio após armazenamento bem-sucedido
  3. Garante que nenhuma falha em um único servidor, rede ou AZ torne as mensagens inacessíveis

Durabilidade: As mensagens estão seguras mesmo em caso de falhas de hardware ou AZ.

Casos de Uso para Filas Standard​

1. Desacoplar Requisições de Usuários do Trabalho em Background​

Cenário: Upload de mídia com processamento pesado

Usuário faz upload de vídeo
    ↓
API envia mensagem para fila SQS
    ↓
API retorna sucesso imediatamente
    ↓
Workers consomem mensagens e processam vídeos

Vantagens:

  • Usuário não espera processamento completo
  • Workers processam em seu próprio ritmo
  • Sistema escala independentemente

2. Distribuir Tarefas para Múltiplos Workers​

Cenário: Validação de cartões de crédito em alto volume

Sistema de pagamento envia 10.000 transações/segundo
    ↓
Fila SQS armazena todas as requisições
    ↓
50 workers consomem e validam paralelamente

Vantagens:

  • Carga distribuída automaticamente
  • Adicionar/remover workers conforme demanda
  • Nenhuma transação perdida durante picos

3. Buffering para Processamento em Lote​

Cenário: Inserção de dados em banco de dados

Aplicação gera 1 milhão de registros/dia
    ↓
Envia para fila SQS conforme gerados
    ↓
Worker agrega mensagens em lotes de 1000
    ↓
Insere no banco em batch (mais eficiente)

Vantagens:

  • Reduz número de chamadas ao banco
  • Otimiza performance de I/O
  • Processa quando banco estiver menos ocupado

4. Integração Entre Sistemas​

Cenário: Sistema legado se comunicando com novo sistema

Sistema Legado → SQS ← Novo Sistema

Migração gradual sem downtime

Vantagens:

  • Sistemas não precisam estar online simultaneamente
  • Permite migração incremental
  • Fila atua como buffer durante transição

Quando Usar Filas Standard​

Use Filas Standard Se:​

Throughput é prioridade:

  • Precisa processar milhões de mensagens por segundo
  • Volume varia drasticamente (picos imprevisíveis)

Aplicação tolera duplicatas:

  • Pode processar mesma mensagem múltiplas vezes sem problema
  • Operações são idempotentes

Ordem não é crítica:

  • A ordem de processamento não afeta o resultado
  • Exemplo: Enviar emails de notificação (não importa a ordem)

Custo é fator importante:

  • Filas Standard são mais baratas que FIFO
  • $0.40 por milhão de requisições (vs $0.50 FIFO)

Não Use Filas Standard Se:​

Ordem é essencial:

  • Processamento de transações bancárias
  • Sistema de pedidos de e-commerce
  • Comandos que dependem de execução sequencial

Duplicatas não podem ocorrer:

  • Cobrança de cartão de crédito (não pode cobrar 2x)
  • Envio de notificação crítica única
  • Registro de eventos sem deduplicação

Baixo volume com requisitos rígidos:

  • Menos de 3.000 mensagens/segundo
  • Ordem e unicidade são obrigatórias

Configurações Importantes​

Visibility Timeout​

Padrão: 30 segundos

Tempo que uma mensagem fica invisível após ser recebida. Se o consumidor não deletar a mensagem nesse período, ela volta a ficar disponível.

Como escolher:

  • Tempo médio de processamento + margem de segurança
  • Se processamento leva 45s, configure 60s

Message Retention Period​

Padrão: 4 dias Mínimo: 60 segundos Máximo: 14 dias

Tempo que mensagens não processadas permanecem na fila antes de serem automaticamente deletadas.

Maximum Message Size​

Limite: 1024 KiB (1 MB) Para mensagens maiores que 1 MB:

  • Armazena payload no S3
  • Envie apenas referência (S3 URL) na mensagem SQS
  • Use Extended Client Library (Java) que faz isso automaticamente

Receive Message Wait Time​

Padrão: 0 segundos (short polling) Long polling: 1-20 segundos (recomendado)

Long polling (recomendado)

  • Reduz número de chamadas vazias
  • Reduz custos
  • Melhora eficiência

Configuração:

ReceiveMessageWaitTimeSeconds = 20

Exemplo de Fluxo Completo​

Cenário: Sistema de processamento de imagens

1. Usuário faz upload de imagem via API
2. API envia mensagem para fila SQS:
   {
     "imageId": "12345",
     "s3Bucket": "uploads",
     "s3Key": "images/photo.jpg",
     "operations": ["resize", "watermark"]
   }
3. API retorna sucesso ao usuário
4. Worker 1 recebe mensagem (visibility timeout inicia)
5. Worker 1 baixa imagem do S3
6. Worker 1 processa (resize + watermark)
7. Worker 1 faz upload do resultado
8. Worker 1 deleta mensagem da fila

Se worker falhar no passo 6:

  • Visibility timeout expira
  • Mensagem volta para fila
  • Worker 2 pega e processa novamente

Resumo​

Filas Standard do Amazon SQS oferecem throughput ilimitado, entrega pelo menos uma vez e melhor esforço de ordenação. São ideais para alto volume de mensagens onde duplicatas ocasionais são aceitáveis e ordem não é crítica. Para cenários que exigem ordem garantida e processamento exatamente uma vez, use filas FIFO.
