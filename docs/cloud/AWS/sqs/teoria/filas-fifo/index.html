Filas FIFO do Amazon SQS

O Que São Filas FIFO?​

As Filas FIFO (First-In-First-Out) são projetadas para cenários onde a ordem das operações e ausência de duplicatas são críticas. Elas garantem que as mensagens sejam processadas exatamente na ordem em que foram enviadas e que cada mensagem seja entregue uma única vez.

FIFO = First In, First Out (Primeiro a Entrar, Primeiro a Sair)

Características Principais​

Ordenação FIFO Garantida​

Garantia: A ordem em que mensagens são enviadas e recebidas é estritamente preservada.

Produtor envia: A → B → C
Consumidor recebe: A → B → C (sempre nessa ordem)

Como funciona:

  • Mensagens são entregues exatamente na ordem de envio
  • Não há possibilidade de receber C antes do B
  • Ordem é mantida mesmo com múltiplos produtores/consumidores

Processamento Exatamente Uma Vez (Exactly-Once Processing)​

Garantia: Cada mensagem é entregue uma única vez e permanece indisponível até que um consumidor a processe e delete.

Diferença das filas Standard:

  • Standard: At-least-once (pode duplicar)
  • FIFO: Exactly-once (nunca duplica)

Mecanismos de deduplicação:

  1. Content-Based Deduplication: Hash automático do corpo da mensagem
  2. Message Deduplication ID: ID único fornecido pelo produtor

Throughput Limitado​

Limites de throughput:

Modo Standard (padrão):

  • 3.000 mensagens/segundo (com batching)
  • 300 chamadas de API/segundo (sem batching)

Modo Alto Throughput (High Throughput):

  • 70.000 mensagens/segundo (com batching)
  • 9.000 chamadas de API/segundo (sem batching)
Batching

Enviar/receber até 10 mensagens em uma única chamada de API conta como 1 transação, permitindo throughput maior.

Nome da Fila Dever Terminar com .fifo​

Obrigatório: Filas FIFO devem ter .fifo no final do nome.

Exemplos válidos:

  • orders.fifo
  • transactions.fifo
  • my-application-queue.fifo

Inválido:

  • orders (sem .fifo)
  • orders-fifo (precisa ser .fifo no final)

Conceitos Principais de Filas FIFO​

Message Group ID​

Definição: Identificador que agrupa mensagens relacionados. Mensagens do mesmo grupo são processadas em ordem FIFO, mas grupos diferentes podem ser processados em paralelo.

Quando usar:

  • Múltiplos fluxos de trabalho independentes na mesma fila
  • Processar pedidos de diferentes usuários em paralelo

Exemplo - Sistema de pedidos:

Message Group ID: "user-123"
  Mensagens: Criar pedido → Pagar → Enviar (ordem garantida)

Message Group ID: "user-456"
  Mensagens: Criar pedido → Pagar → Enviar (ordem garantida)

Os dois grupos processam em paralelo!

Como funciona:

  • Mensagens com o mesmo Message Group ID são processadas automaticamente
  • Mensagens de groups diferentes podem ser processadas simultaneamente
  • Não há limite para número de grupos em uma fila FIFO

Configuração:

{
  "MessageBody": "Pedido criado",
  "MessageGroupId": "user-123"
}

Message Deduplication ID​

Definição: ID único usado para identificar e eliminar duplicatas dentro de um intervalo de 5 minutos

Janela de deduplicação: 5 minutos

Se você enviar duas mensagens com o mesmo Deduplication ID dentro de 5 minutos, apenas a primeira será aceita

Duas formas de deduplicação:

1. Content-Based Deduplication (Automática):

Ative na configuração da fila. O SQS calcula automaticamente um hash SHA-256 do corpo da mensagem

Habilitar: ContentBasedDeduplication = true

Vantagens:

  • Não precisa gerar IDs manualmente
  • Automático

Desvantagens:

  • Se corpo da mensagem mudar minimamente, é considerada nova mensagem
  • Menos controle

2. Message Deduplication ID (Manual):

Você fornece um ID único ao enviar a mensagem.

{
  "MessageBody": "Processar pagamento",
  "MessageGroupId": "user-123",
  "MessageDeduplicationId": "payment-abc-123"
}

Vantagens:

  • Controle total sobre deduplicação
  • Pode enviar mensagens diferentes com mesmo ID (deduplica)

Desvantagens:

  • Precisa gerar e gerenciar IDs únicos

Exemplo de deduplicação:

10:00:00 - Envia mensagem com DeduplicationId = "msg-001" ✅ Aceita
10:01:00 - Envia mensagem com DeduplicationId = "msg-001" ❌ Rejeitada (duplicata)
10:06:00 - Envia mensagem com DeduplicationId = "msg-001" ✅ Aceita (passou 5 min)

Sequence Number​

Definição: Número único atribuído pelo SQS a cada mensagem em um Message Group, indicando a ordem exata.

Gerado automaticamente: pelo SQS (não é fornecido pelo produtor)

Formato: Número grande e crescente

Uso:

  • Rastrear ordem de processamento
  • Debug e auditoria
  • Confirmar ordem de entrega

Casos de Uso para Filas FIFO​

1. Sistema de Gerenciamento de Pedidos de E-commerce​

Requisito: Pedidos devem ser processados na ordem correta

Message Group ID: "order-12345"

Mensagem 1: Criar pedido
Mensagem 2: Processar pagamento
Mensagem 3: Separar produtos
Mensagem 4: Enviar pedido
Mensagem 5: Notificar cliente

Ordem crítica! Não pode enviar antes de pagar.

2. Integração com Sistemas Legados​

Requisitos: Eventos devem chegar na ordem em que foram gerados

Sistema A → Fila FIFO → Sistema B

Evento 1: Usuário criado
Evento 2: Usuário atualizado
Evento 3: Usuário deletado

Sistema B precisa receber nessa ordem exata.

3. Processamento de Transações Financeiras​

Requisitos: Transações devem ser processadas em ordem e sem duplicatas

Message Group ID: "account-789"

Transação 1: Depósito +1000
Transação 2: Saque -500
Transação 3: Transferência -200

Ordem e unicidade são críticas para integridade financeira.

Modo Alto Throughput (High Throughput)​

Quando usar: Quando precisar de mais de 3.000 mensagens/segundo em uma fila FIFO.

Capacidade:

  • 70.000 mensagens/segundo (com batching de 10 mensagens)
  • 9.000 transações/segundo (sem batching)

Como habilitar:

Na criação ou edição da fila, configure:

DeduplicationScope = messageGroup
FifoThroughputLimit = perMessageGroupId

Como funciona:

  • Deduplicação e ordenação são mantidas dentro de cada Message Group
  • Diferentes Message Groups processam completamente em paralelo
  • Aumento throughput mantendo garantias FIFO por grupo

Requisitos:

  • Usar Message Group IDs (obrigatório)
  • Múltiplos groups para aproveitar paralelismo

Limitações:

  • Sem suporte para Content-Based Deduplication (precisa usar Message Deduplication ID manual)

Configurações Importantes​

Content-Based Deduplication​

Ativar: Se você quer deduplicação automática baseada no conteúdo da mensagem

ContentBasedDeduplication = true

Desativar: Se você vai fornecer Message Deduplication ID manualmente

Visibility Timeout​

Padrão: 30 segundos

Funciona igual às filas Standard - mensagem fica invisível após ser recebida

Message Retention Period​

Padrão: 4 dias Máximo: 14 dias

Igual às filas Standard

Receive Message Wait Time​

Recomendado: 20 segundos (long polling)

Reduz custos e melhora eficiência

Migrar de Standard para FIFO​

Não é Possível Converter

Você não pode converter uma fila Standard existente em FIFO. É necessário criar uma nova fila FIFO e migrar as aplicações.

Passos para migração:

  1. Criar nova fila FIFO
  • Nome deve terminar com .fifo
  • Configurar deduplicação e outros parâmetros
  1. Atualizar produtores
  • Adicionar MessageGroupId em cada mensagem
  • Adicionar MessageDeduplicationId (se não usar content-based)
  1. Atualizar consumidores
  • Apontar para nova fila FIFO
  • Testar processamento
  1. Migração gradual
  • Use feature flags ou blue/green deployment
  • Monitore ambas as filas durante transição
  1. Deletar fila Standar antiga
  • Após validar que tudo funciona
  • Certifique-se que todas as mensagens foram processadas

Quando Usar Filas FIFO​

Use Filas FIFO Se:​

Ordem é crítica:

  • Processamento sequencial de transações
  • Sistema de pedidos (criar -> pagar -> enviar)
  • Execução de comandos que dependem uns dos outros

Duplicatas não podem ocorrer:

  • Cobrança de cartão de crédito
  • Registro de eventos únicos
  • Transações financeiras

Throughput está dentro dos limites:

  • Até 3.000 mensagens/segundo (modo standard)
  • Até 70.000 mensagens/segundo (modo alto throughput)

Integridade de dados é obrigatória:

  • Sistemas regulamentados (financeiro, saúde)
  • Auditoria e compliance

Não Use Filas FIFO Se:​

Throughput precisa ser ilimitado:

  • Mais de 70.000 mensagens/segundo
  • Picos imprevisíveis acima dos limites

Ordem não importa:

  • Envio de emails de notificação
  • Processamento de logs
  • Tarefas independentes

Aplicação já é idempotente:

  • Pode processar duplicatas sem problema
  • Não precisa de ordem

Resumo​

Filas FIFO do Amazon SQS garantem ordem estrita de processamento (FIFO) e entrega exatamente uma vez (exactly-once). São ideais para cenários onde ordem e ausência de duplicatas são críticas, como sistemas de pedidos, transações financeiras e execução de comandos sequenciais. O throughput é limitado (3K-70K msg/s), então avalie se é suficiente para seu caso de uso.
