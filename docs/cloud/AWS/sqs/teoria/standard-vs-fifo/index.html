Standard vs FIFO: Qual Escolher?

Comparação de Garantias​

Standard: At-Least-Once Delivery​

Garantia: Mensagem entregue pelo menos uma vez, mas pode ser entregue múltiplas vezes.

Envio: Mensagem A
Entrega: A, A (duplicata possível)

Consequência:

  • Aplicação deve ser idempotente
  • Processar mensagem 2x deve ter mesmo resultado que processar 1x

Exemplo prático:

❌ Não idempotente:

// Processa cada mensagem
saldo = saldo + valorDepositado; 
// Se processar 2x, saldo ficará errado!

✅ Idempotente:

// Verifica se já processou
if (!transacaoJaProcessada(transacaoId)) {
  saldo = saldo + valorDepositado;
  marcarComoProcessada(transacaoId);
}
// Processar 2x não afeta resultado

FIFO: Exactly-Once Processing​

Garantia: Mensagem entregue exatamente uma vez, nunca duplica

Envio: Mensagem A
Entrega: A (apenas uma vez, garantido)

Consequência:

  • Não precisa implementar deduplicação na aplicação
  • SQS garante que não haverá duplicatas

Comparação de Ordenação​

Standard: Best-Effort Ordering​

Garantia: Faz o melhor esforço para manter ordem, mas não garante.

Envio: A → B → C → D
Entrega possível: A → C → B → D (fora de ordem)

Por que acontece:

  • Mensagens distribuídas em múltiplos servidores
  • Cada servidor retorna mensagens independentemente
  • Não há coordenação de ordem entre servidores

Quando é aceitável:

  • Tarefas independentes (enviar emails)
  • Processamento paralelo sem dependências
  • Ordem final não importa

FIFO: Strict Ordering​

Garantia: Ordem estritamente preservada

Envio: A → B → C → D
Entrega: A → B → C → D (sempre nessa ordem)

Como funciona:

  • Mensagens do mesmo Message Group ID processadas sequencialmente
  • Próxima mensagem só disponível após anterior ser deletada
  • Coordenação entre servidores garante ordem

Quando é necessário:

  • Comandos sequenciais (criar -> configurar -> iniciar)
  • Transações dependentes (pagar -> enviar)
  • Eventos cronológicos (log de auditoria)

Comparação de Throughput​

Standard: Throughput Ilimitado​

Capacidade:

  • Praticamente ilimitado
  • Escala automaticamente
  • Sem limites de transações por segundo

Casos de uso:

  • Picos imprevisíveis de tráfego
  • Volume muito alto (100K+ msg/s)
  • Black Friday, lançamentos, eventos virais

Exemplo:

Sistema de logs: 500.000 mensagens/segundo
→ Standard é a única opção viável

FIFO: Throughput Limitado​

Capacidade:

Modo Standard:

  • 3.000 mensagens/segundo (com batching)
  • 300 transações/segundo (sem batching)

Modo Alto Throughput:

  • 70.000 mensagens/segundo (com batching)
  • 9.000 transações/segundo (sem batching)

Casos de uso:

  • Volume moderado e previsível
  • Máximo de 70K msg/s é suficiente
  • Ordem/unicidade valem o trade-off de throughput

Exemplo:

Sistema de pedidos: 5.000 pedidos/segundo
→ FIFO modo alto throughput suporta

Comparação de Complexidade​

Standard: Simples de Usar​

Facilidade:

  • Não requer Message Group ID
  • Não requer Deduplicidade ID
  • Apenas: enviar, receber, deletar
  • Menos configurações

Código de exemplo:

// Enviar mensagem Standard
await sqs.sendMessage({
  QueueUrl: queueUrl,
  MessageBody: JSON.stringify({
    orderId: "123",
    action: "process"
  })
});

// Simples, sem IDs adicionais

FIFO: Mais Complexo​

Requisitos:

  • Message Group ID obrigatório
  • Deduplication ID ou Content-Based Deduplication
  • Nome da fila deve terminar com .fifo
  • Mais configurações para gerenciar

Código de exemplo:

// Enviar mensagem FIFO
await sqs.sendMessage({
  QueueUrl: queueUrl,
  MessageBody: JSON.stringify({
    orderId: "123",
    action: "process"
  }),
  MessageGroupId: "order-123",           // Obrigatório
  MessageDeduplicationId: "dedup-abc123" // Obrigatório (se não usar content-based)
});

// Mais complexo, precisa gerenciar IDs

Comparação de Custos​

Standard: Mais Barato​

Preço: $0.40 por milhão de requisições

Cálculo exemplo:

10 milhões de mensagens/mês = $4.00/mês
100 milhões de mensagens/mês = $40.00/mês

Vantagens: Economia de 20% comparado a FIFO

FIFO: 25% Mais Caro​

Preço: $0.50 por milhão de requisições

Cálculo exemplo:

10 milhões de mensagens/mês = $5.00/mês
100 milhões de mensagens/mês = $50.00/mês

Diferença: +$0.10 por milhão (+25%)

Vale a pena? Se ordem/unicidade são críticas, sim. Economia de $0.10/mês não compensa bugs causados por duplicatas ou desordem.

Cenários Práticos​

Cenário 1: Sistema de Notificações​

Requisitos:

  • Enviar emails/SMS para milhões de usuários
  • Ordem não importa
  • Se email duplicado for enviado, não é grave

Escolha: Standard

Por quê:

  • Throughput ilimitado (picos de milhões de mensagens)
  • Duplicata ocasional é aceitável (usuário recebe email 2x, não é crítico)
  • Ordem irrelevante (não importa qual usuário recebe primeiro)
  • Mais barato

Cenário 2: Processamento de Pedidos E-commerce​

Requisitos:

  • Criar pedido -> Pagar -> Separar -> Enviar (ordem crítica)
  • Não pode cobrar cartão 2x (sem duplicatas)
  • Volume: 10.000 pedidos/hora

Escolha: FIFO

Por quê:

  • Ordem é obrigatória (não pode enviar antes de pagar)
  • Duplicatas causariam problemas financeiros graves
  • Volume dentro do limite (10K/hora = ~3 msg/s, muito abaixo do limite)

Resumo​

A escolha entre Standard e FIFO depende principalmente de três fatores: ordem, duplicatas e throughput. Use Standard quando precisar de throughput ilimitado e puder tolerar duplicatas ocasionais e desordem. Use FIFO quando ordem e ausência de duplicatas forem críticas e o volume estiver dentro dos limites (até 70K msg/s). Não é possível converter entre tipos - planeje cuidadosamente desde o início.
